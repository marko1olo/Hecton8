# HECTON-8 | Engine Mandate v1.0 | CLASSIFIED: SENIOR IMPL ONLY

## Section0 - FOUNDATIONAL INVARIANTS

[INVARIANT] All runtime asset access routes through `Addressables.LoadAssetAsync<T>`. Zero exceptions.
[INVARIANT] Every handle issued = entry in global registry. No orphaned handles. Ever.
[INVARIANT] Ref-count reaches zero = release scheduled. Deferred max 1 frame via end-of-frame coroutine queue.
[INVARIANT] VRAM budget is hard ceiling. RAM budget is soft ceiling with pressure-graduated response.
[INVARIANT] No synchronous stall on main thread exceeding 0.5ms for any asset operation.

## Section1 - GLOBAL REGISTRY ARCHITECTURE

### 1.1 Primary Store

Registry:      Dictionary<uint, AssetRecord>
AssetRecord:   { Handle: AsyncOperationHandle, RefCount: int, Priority: byte, LastAccessTick: long, SizeBytes: ulong }
PriorityQueue: MinHeap<AssetRecord> keyed on (Priority ASC, LastAccessTick ASC)
PendingRelease: Queue<uint> - populated end-of-frame, drained start-of-next-frame

### 1.2 Key Generation

AssetKey(uint) = FNV-1a-32( guid_string + biome_id_byte + lod_level_nibble )
Collision guard: if Registry.ContainsKey(key) && record.Handle.AssetGUID != incomingGUID -> key ^= 0xDEAD_BEEF, retry once, else throw

### 1.3 Ref-Count Protocol

Acquire(key):
  if Registry[key].exists -> RefCount++ -> return Handle
  else -> LoadAsync -> register -> RefCount = 1 -> return Handle

Release(key):
  RefCount--
  if RefCount <= 0 -> enqueue PendingRelease(key)
  if RefCount < 0 -> Assert.Fail("Double-release: " + key) -> clamp to 0

### 1.4 Tick Integration

Every frame START:
  drain PendingRelease -> execute Section4 RELEASE FLOW per entry

Every frame END:
  update LastAccessTick for all active queries
  run Section6 PRESSURE EVALUATION

## Section2 - PRIORITY QUEUE & LOAD ORDER

### 2.0 Unity Addressables 2.7 Residency / Asset Load Mode

[RULE] Addressables groups must use `AssetLoadMode.RequestedAssetAndDependencies` unless a domain owner proves full packed-asset residency is cheaper for that group.
[RULE] `AllPackedAssetsAndDependencies` is allowed only for tiny always-hot bundles where resident memory is bounded in the group budget and measured in a Memory Profiler capture.
[RULE] Residency reports must distinguish loaded handle count, resident memory, committed memory, and graphics memory. A loaded Addressables handle is not proof that all GPU-side memory is resident.
[RULE] Asset groups must record their load mode in the streaming budget table and in the release ledger.

[FORBID] Enabling `AllPackedAssetsAndDependencies` on biome, texture, audio, terrain, or HLOD groups without a written memory budget.
[FORBID] Calling a bundle "resident-safe" without Memory Profiler resident/committed evidence from Unity 2023.1+ compatible snapshots or platform-native memory counters.
[FORBID] Evicting based only on Addressables ref-count. Residency pressure also considers texture mip residency, render target pressure, native buffers, and driver reserve.

## Engineering Data

| Group Type | Required AssetLoadMode | Residency Evidence | MX350 Rule |
|---|---|---|---|
| Core fallback assets | RequestedAssetAndDependencies | startup Memory Profiler snapshot | May stay loaded |
| Biome textures | RequestedAssetAndDependencies | texture memory + requested mip levels | downgrade mips before broad unload |
| Audio ambient bank | RequestedAssetAndDependencies | resident audio memory | one active bank max under pressure |
| Tiny always-hot LUTs | AllPackedAssetsAndDependencies allowed | size cap and resident capture | total <= 8 MB |
| HLOD/proxy groups | RequestedAssetAndDependencies | handle ledger + VRAM ledger | release LOD0 first |

Project evidence: package lock resolves `com.unity.addressables` to 2.7.6. Local package changelog documents `AssetLoadMode` with `Requested Asset And Dependencies` and `All Packed - Assets And Dependencies`.

### 2.1 Priority Tiers (byte, lower = higher priority)

TIER_0 = 0x00  -> Player Suit, HUD assets, Dive Computer UI
TIER_1 = 0x01  -> Held Tools, Equipped items, Breath-system meshes
TIER_2 = 0x10  -> Proximity Chunks (radius <= StreamInner)
TIER_3 = 0x20  -> Ambient SFX banks, Reverb impulses
TIER_4 = 0x30  -> Mid-range fauna, interactive props
TIER_5 = 0x40  -> Distant HLODs, Biome skybox variants
TIER_6 = 0xFF  -> Preload speculative (background, never blocks frame)

### 2.2 Concurrent Load Slots

MaxConcurrentLoads(tier):
  TIER_0-1 -> 8 slots  (dedicated, never pre-empted)
  TIER_2   -> 6 slots
  TIER_3-4 -> 4 slots
  TIER_5-6 -> 2 slots  (throttled under pressure)

MemoryPressure > 0.75 -> reduce TIER_5-6 slots to 0
MemoryPressure > 0.85 -> reduce TIER_3-4 slots to 1

### 2.3 Load Sequencer

Each frame budget: 2ms load-dispatch window on main thread
Sequence:
  1. Service pending TIER_0 synchronously within 2ms budget
  2. Dispatch async ops in priority order until slot capacity hit
  3. Remaining requests -> stay in queue, re-evaluated next frame
  4. Starvation guard: TIER >= 4 request age > 60 frames -> priority--  (escalate)

## Section3 - STREAMING ZONE MATH

### 3.1 Chunk Radius Definitions

StreamInner  = BaseRadius x (1.0 - PressureFactor x 0.4)
StreamOuter  = StreamInner x 1.6
HLODRadius   = StreamOuter x 2.5

BaseRadius   = 80m  (default, designer-tunable per biome)

### 3.2 Player Velocity Predictive Pre-fetch

LookAheadPoint = PlayerPos + (Velocity.normalized x Speed x 3.0s)
ChunksToPreload = all chunks where dist(chunk.center, LookAheadPoint) <= StreamInner
PreloadPriority = TIER_6 -> escalates to TIER_2 when dist <= StreamInner + 10m

### 3.3 Depth-Layer Biome Gating

BiomeID derived from: depth_meters + biome_tag_byte
Biome groups:
  SHALLOW  [0-200m]  : group_shallow
  TWILIGHT [200-600m]: group_twilight
  ABYSSAL  [600m+]   : group_abyssal
  THERMAL  [special] : group_thermal_vent

[RULE] Never load group_abyssal when CurrentDepth < 500m
[RULE] Never load group_shallow when CurrentDepth > 250m (50m hysteresis prevents thrash)
Hysteresis formula:
  UnloadThreshold(group) = LoadThreshold(group) + 50m

### 3.4 Chunk LOD Selection

DistanceFactor = dist(player, chunk.center) / StreamOuter   [0.0-1.0 clamped]

LOD_level:
  DistanceFactor <= 0.25 -> LOD0
  DistanceFactor <= 0.55 -> LOD1
  DistanceFactor <= 0.85 -> LOD2
  DistanceFactor >  0.85 -> HLOD_impostor

VRAM_pressure > 0.88:
  force LOD_level++ for all non-TIER_0 assets
  cap at LOD2 minimum for player-proximal (dist < 15m)

## Section4 - ASSET RELEASE FLOW

### 4.1 Ordered Teardown Protocol

Step 1: Unregister from all engine tick systems (Update, FixedUpdate subscriptions)
Step 2: Unsubscribe all event delegates (OnDamage, OnInteract, OnVisible callbacks)
Step 3: Disable renderers / audio sources -> prevents 1-frame ghost rendering
Step 4: Return GameObject to pool (if pooled) OR Destroy (if non-pooled, confirmed by PoolRegistry)
Step 5: Addressables.Release(handle) -> decrements internal ref-count
Step 6: Registry.Remove(key)
Step 7: Update PressureFactor (recalc freed bytes in SizeBytes accumulator)

ORDERING IS MANDATORY. Step 5 before Step 4 = memory corruption risk. Never reorder.

### 4.2 Pool Return Validation

Before pool return:
  Assert component state reset (no lingering velocity, no active coroutines, no pending tweens)
  Strip dynamic material property blocks (reset to shared material)
  Clear all cached component refs internal to pooled object

### 4.3 Forced Eviction (Pressure-Triggered)

Eviction candidates = PriorityQueue.GetLowestPriority(n=8) where RefCount == 0
Sort candidates: LastAccessTick ASC (evict oldest-unused first)
Execute Section4.1 for each candidate until PressureFactor < 0.80
Cap evictions per frame: 4 objects max (prevent hitch)

## Section5 - VRAM MANAGEMENT (MX350 GUARD)

### 5.1 VRAM Sampling

Poll interval: every 90 frames (~=1.5s at 60fps)
Source: SystemInfo.graphicsMemorySize (static cap) + custom query via NativePlugin or GL.GetGPUMemory
VRAM_Used   = tracked via custom VRAM_Ledger (sum of all registered texture SizeBytes x mip factor)
VRAM_Budget = 1.80 GB  (hard)
VRAM_Warn   = 1.60 GB  (soft, begin preventive eviction)

### 5.2 Mip Streaming Integration

Texture mip bias on pressure:
  VRAM_Used > WARN  -> GlobalMipBias = +1   (halve resident mips for non-proximal textures)
  VRAM_Used > HARD  -> GlobalMipBias = +2   -> force LOD0 textures to LOD1 resolution
  VRAM_Used < 1.40  -> GlobalMipBias = 0    (restore)

QualitySettings.streamingMipmapsMemoryBudget = (VRAM_Budget - VRAM_Used_NonTex) in MB
Texture2D.requestedMipmapLevel per atlas:
  dist > StreamInner -> requestedMipmapLevel = 2
  dist > StreamOuter -> requestedMipmapLevel = 4  (HLOD, near-black anyway)

### 5.3 LOD0 Texture Forced Release

Trigger: VRAM_Used > 1.80 GB
Targets: all TextureRecords where (Priority >= TIER_4) && (LOD_level == LOD0)
Action:
  Swap to LOD1 texture handle
  Release LOD0 handle via Section4.1 partial (skip Steps 1-4, only Steps 5-7)
  Log: "VRAM_EVICT LOD0->LOD1: {key} freed {bytes}MB"
Recovery: re-queue LOD0 load at TIER_6 if dist returns <= StreamInner x 0.5

## Section6 - RAM PRESSURE SYSTEM

### 6.1 Pressure Calculation

PressureFactor = CurrentReservedMemory_bytes / MaxSystemRAM_bytes

MaxSystemRAM = SystemInfo.systemMemorySize x 1024 x 1024  [bytes]
CurrentReservedMemory = Profiler.GetTotalReservedMemory()  + NativeHeap_estimate

// [FORBID] LINQ .Sum() in hot path.
// Maintain a static running integer _totalRegistrySizeBytes updated on Acquire/Release.  (15% overhead factor)

### 6.2 Graduated Response Thresholds

PressureFactor < 0.60 -> NORMAL:   all tiers active, full preload enabled
PressureFactor >= 0.60 -> CAUTION:  disable TIER_6 speculative loads
PressureFactor >= 0.75 -> WARNING:  evict TIER_5 RefCount==0, disable TIER_5-6 new loads
PressureFactor >= 0.85 -> CRITICAL: evict TIER_4-5, reduce StreamOuter by 30%
PressureFactor >= 0.90 -> EXTREME:  EvictQueue.DrainSynchronously()
                                    StreamInner reduced by 40%, HLOD-only mode for dist > 40m

### 6.3 Deterministic Eviction Gating

Trigger conditions (ANY):
  PressureFactor > 0.90
  Scene transition initiated
  Biome boundary crossed (group swap)
  Player death / respawn sequence

Execution:
  - drain Addressables release queue immediately
  - process at most 4 registered eviction candidates per frame
  - never invoke `Resources.UnloadUnusedAssets()`
  - never rely on GC as pressure relief

Post-execution: recalculate PressureFactor, log delta

### 6.4 Streaming Budget Allocator

Total RAM budget allocated to streaming = MaxSystemRAM x 0.35  (35% ceiling)
  Texture pool:  budget x 0.45
  Mesh pool:     budget x 0.25
  Audio bank:    budget x 0.15
  Misc (VFX,SO): budget x 0.15

If any pool exceeds allocation -> evict from that pool first before touching others

## Section7 - FAILURE MODES & SAFETY SYSTEMS

### 7.1 Load Failure Handler

OnLoadFailed(key, handle, error):
  Log.Error("ASSET_FAIL key={key} error={error}")
  Assign fallback material -> global CHECKERBOARD_MAT (pre-loaded at startup, never released)
  Assign fallback mesh    -> global UNIT_CUBE_MESH (collision proxy)
  Mark record: AssetRecord.IsFallback = true
  Do NOT throw. Do NOT return null. Continue execution.
  Schedule retry at TIER_6 with backoff: 5s, 15s, 60s (exponential, max 3 attempts)

### 7.2 Load Timeout System

TimeoutThreshold = 10.0 seconds

Monitor: per-handle elapsed since LoadAsync dispatch
At T+10s if !handle.IsDone:
  Load LOD1_proxy_key (pre-registered lightweight stand-in, <= 50KB mesh, 128px texture)
  Original load NOT cancelled (Addressables limitation) - monitor separately
  If original eventually completes -> hot-swap LOD1_proxy -> original, Release proxy
  If original fails -> Section7.1 applies

LOD1_proxy registration: mandatory at biome-group init, loaded synchronously at scene start
  (only synchronous load permitted in entire system, bounded at startup, never runtime)

### 7.3 Handle Leak Detection

Every 300 frames: audit Registry
  Flag records where: RefCount > 0 && LastAccessTick < (CurrentTick - 600)
  Log warning: "POTENTIAL_LEAK key={key} refcount={n} age={frames}"
  Do NOT auto-release (unknown if legitimately long-lived)
  Expose via debug overlay: HECTON_DebugOverlay asset leak panel

### 7.4 NullRef Prevention Contracts

All asset accessors return via wrapper:
  T SafeGet<T>(uint key) where T: UnityEngine.Object
    -> returns Registry[key].Handle.Result if valid
    -> returns typed fallback (CHECKERBOARD, UNIT_CUBE, SILENT_CLIP) if IsFallback or null
    -> NEVER returns null to caller

Callers must never cache raw handle.Result directly. Always route through SafeGet.

### 7.5 Async Scene Activation Gate

Scene load progress reported as normalized float [0.0-1.0]
Chunk/content activation uses `Object.InstantiateAsync(chunkPrefab)` or async prefab spawning.
Do not stall on `allowSceneActivation`.
The engine timeslices `Awake`/`OnEnable` across frames during async instantiation.
Overlay fade: 0.5s alpha lerp, driven by unscaled time (immune to timeScale=0 states)
Forbid: any gameplay systems initializing before async instantiation completes

## Section8 - SCALABILITY PROFILES

### 8.1 Quality Tier Definitions

TIER_MINIMAL (MX350 / 6GB RAM):
  StreamInner = 50m, StreamOuter = 80m, HLODRadius = 150m
  MaxTexResolution = 1024px, MipBias = +1 default
  AudioCompression = Vorbis q=0.4, MaxAudioChannels = 24
  ParticleBudget = 512 simultaneous
  ShadowDistance = 30m, ShadowCascades = 2

TIER_MID (RTX 3060 / 12GB RAM):
  StreamInner = 80m, StreamOuter = 130m, HLODRadius = 250m
  MaxTexResolution = 2048px, MipBias = 0
  AudioCompression = Vorbis q=0.6, MaxAudioChannels = 48
  ParticleBudget = 2048
  ShadowDistance = 80m, ShadowCascades = 4

TIER_ULTRA (RTX 4080+ / 32GB RAM):
  StreamInner = 150m, StreamOuter = 240m, HLODRadius = 500m
  MaxTexResolution = 4096px, MipBias = -1 (aniso boost)
  AudioCompression = PCM/ADPCM, MaxAudioChannels = 128
  ParticleBudget = 16384
  ShadowDistance = 200m, ShadowCascades = 4 + RayTraced contact shadows

### 8.2 Runtime Profile Detection

At startup, before any asset load:
  Detect VRAM = SystemInfo.graphicsMemorySize
  Detect RAM  = SystemInfo.systemMemorySize
  Detect CoreCount = SystemInfo.processorCount

ProfileSelect:
  VRAM < 1800MB || RAM < 8GB  -> TIER_MINIMAL
  VRAM < 6000MB || RAM < 16GB -> TIER_MID
  else                       -> TIER_ULTRA

Override: user settings file takes priority over auto-detect if present

### 8.3 Addressable Group Mapping

group_core        -> always loaded, never streamed (Player, HUD, Fallbacks, Proxies)
group_shallow     -> streamed, Biome-gated Section3.3
group_twilight    -> streamed, Biome-gated
group_abyssal     -> streamed, Biome-gated, TIER_MINIMAL: 50% texture res reduction applied
group_thermal     -> streamed, event-triggered only
group_horror_fx   -> streamed, triggered by tension_state >= 0.7 (designer float param)
group_audio_amb   -> streamed, always 1 active bank max (swap on biome cross)
group_audio_music -> streamed, double-buffer: preload next track while current plays

## Section9 - AUDIO STREAMING SPECIFICS

### 9.1 Audio Handle Integration

AudioClip handles follow identical ref-count protocol (Section1.3)
AudioClip key includes sample_rate_tag to prevent cross-rate collisions
Streaming clips (duration > 10s): AudioClip.loadType = AudioClipLoadType.Streaming
Short SFX (duration <= 2s):        AudioClip.loadType = AudioClipLoadType.DecompressOnLoad
Medium (2-10s):                    AudioClip.loadType = AudioClipLoadType.CompressedInMemory

### 9.2 Audio Budget Under Pressure

PressureFactor > 0.80:
  Reduce active AudioSource count to MaxAudioChannels x 0.5
  Prioritize: player breath > proximity horror SFX > ambient loops > music
  Cull lowest-priority sources immediately (no fade, too costly under pressure)

PressureFactor > 0.90:
  Music bank -> pause (not release), resume on pressure drop < 0.80
  Ambient bank -> 1 active loop only, all others released

## Section10 - THREADING & JOB INTEGRATION

### 10.1 Worker Thread Allocation

LoadDispatcher: runs on dedicated thread (not main, not render)
RefCountMutator: Interlocked.Increment / Interlocked.Decrement ONLY (lock-free)
Registry read:   concurrent via ConcurrentDictionary (replace Dictionary if contention detected in profiling)
PressureCalc:    scheduled as Unity Job (IJob), result written to NativeArray<float>[0], read main thread

### 10.2 Addressables Async Continuation

All handle.Completed callbacks scheduled on main thread (Addressables default)
Heavy post-load work (mesh baking, texture compression queries) -> offload via Job System
Max job batch size: 4 assets per frame to prevent job scheduler saturation on 4C/4T targets

### 10.3 4C/4T Optimization Constraints

Never spawn more than (CoreCount - 1) background jobs simultaneously
Reserve 1 core headroom for OS + audio thread
Job dependency chains: chain load -> process -> register to prevent false parallelism overhead
Profile target: load dispatch overhead < 0.3ms/frame on i3-10100

## Section12 - STARTUP SEQUENCE (ORDERED)

Phase 0: Detect hardware profile -> select scalability tier (Section8.2)
Phase 1: Load group_core synchronously (permitted: startup only, bounded < 200ms)
          Includes: CHECKERBOARD_MAT, UNIT_CUBE_MESH, SILENT_CLIP, all LOD_proxies
Phase 2: Initialize Registry, PriorityQueue, VRAM_Ledger, PressureFactor baseline
Phase 3: Preload current biome group at TIER_2 priority (async, show BIOS overlay)
Phase 4: Preload audio_amb bank for starting zone
Phase 5: Await Section7.5 scene activation gate (progress >= 0.90)
Phase 6: Activate scene, remove overlay, enable gameplay systems
Phase 7: Begin speculative preload of adjacent biome at TIER_6

## Section13 - FORBIDDEN PATTERNS (ENFORCEMENT)

[FORBID] Resources.Load           - any runtime path, zero tolerance
[FORBID] Resources.LoadAll        - unconditional
[FORBID] AssetDatabase.LoadAsset  - runtime (editor utility only)
[FORBID] WWW class                - deprecated, replaced by UnityWebRequest if needed
[FORBID] Direct scene.Activate without progress gate
[FORBID] Coroutine-based load without handle registration

[FORBID] GC.Collect() outside Section6.3 authorized trigger (causes 40ms+ hitch on 4C target)
