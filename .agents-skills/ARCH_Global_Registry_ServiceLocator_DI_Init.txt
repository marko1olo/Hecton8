# GLOBAL_REGISTRY_DI - Hecton-8 Technical Mandate

---

## RULE-01 - Static Service Locator Pattern

The `GlobalRegistry` is a static singleton accessor class - not a MonoBehaviour.
It provides the single, authoritative lookup point for all Hecton-8 runtime singletons.

// CANONICAL DECLARATION
public static class GlobalRegistry
{
    // Typed slots for singleton services
    public static IInputService      Input      { get; private set; }
    public static IPhysicsService    Physics    { get; private set; }
    public static IAudioService      Audio      { get; private set; }
    public static ISceneService      Scene      { get; private set; }
    public static IUIService         UI         { get; private set; }

    // Generic multi-instance registries (see RULE-03)
    private static readonly RegistryBucket<IUpdatable>  _updatables  = new(capacity: 128);
    private static readonly RegistryBucket<IRenderable> _renderables = new(capacity: 64);

    public static RegistryBucket<IUpdatable>  Updatables  => _updatables;
    public static RegistryBucket<IRenderable> Renderables => _renderables;
}

[FORBID] Instantiating `GlobalRegistry` via `new`. Class MUST be `static`.
[FORBID] Exposing raw mutable fields. All singleton slots are `private set`.

## RULE-02 - Explicit Registration - OnEnable / OnDisable Contract

Every component that participates in a registry bucket MUST follow this lifecycle contract.
No exceptions. Registration happens in `OnEnable`. Unregistration happens in `OnDisable`.

// CANONICAL COMPONENT PATTERN
public sealed class EnemyAI : MonoBehaviour, IUpdatable
{
    private void OnEnable()
    {
        GlobalRegistry.Updatables.Register(this);
    }

    private void OnDisable()
    {
        GlobalRegistry.Updatables.Unregister(this);
    }

    public void Tick(float dt) { /* game logic */ }
}

[RULE] `OnEnable` / `OnDisable` pair is MANDATORY. Registering without unregistering is a hard defect.
[FORBID] Registering inside `Awake()`. Cross-script order during `Awake` is non-deterministic.
[FORBID] Registering inside constructors or field initializers.

## RULE-03 - RegistryBucket - Dense Array with O(1) Swap-With-Last Removal

All multi-instance registries use `RegistryBucket<T>`, backed by a contiguous `T[]` array.
Removal is O(1) via Swap-With-Last algorithm. No gaps, no null holes, no linked traversal.

public sealed class RegistryBucket<T> where T : class
{
    private readonly T[]  _items;
    private int           _count;
    private readonly int  _capacity;

    public int  Count    => _count;
    public T[]  RawArray => _items;          // expose for O(N) iteration without allocation

    public RegistryBucket(int capacity)
    {
        _capacity = capacity;
        _items    = new T[capacity];
        _count    = 0;
    }

    // O(1) amortized - append to tail
    public void Register(T item)
    {
#if UNITY_EDITOR || DEVELOPMENT_BUILD
        if (_count >= _capacity)
            throw new InvalidOperationException(
                $"[GlobalRegistry] RegistryBucket<{typeof(T).Name}> capacity ({_capacity}) exceeded.");
        if (Contains(item))
            throw new InvalidOperationException(
                $"[GlobalRegistry] Double-registration detected: {item}");
#endif
        _items[_count++] = item;
    }

    // O(N) find + O(1) swap-with-last removal
    public bool Unregister(T item)
    {
        for (int i = 0; i < _count; i++)
        {
            if (!ReferenceEquals(_items[i], item)) continue;

            // SWAP-WITH-LAST
            _count--;
            _items[i]      = _items[_count];
            _items[_count] = null;           // clear tail - prevent loitering reference
            return true;
        }
#if UNITY_EDITOR || DEVELOPMENT_BUILD
        UnityEngine.Debug.LogWarning(
            $"[GlobalRegistry] Unregister called for non-registered item: {item}");
#endif
        return false;
    }

    public bool Contains(T item)
    {
        for (int i = 0; i < _count; i++)
            if (ReferenceEquals(_items[i], item)) return true;
        return false;
    }

    // Called before scene unload (see RULE-07)
    public void Clear()
    {
        System.Array.Clear(_items, 0, _count);
        _count = 0;
    }
}

[DATA] Backing store is `T[]` - contiguous heap block. Cache-line friendly linear scan.
[FORBID] `List<T>`, `LinkedList<T>`, `HashSet<T>` as backing stores for tick-critical buckets.
[SCALE] Capacity is set at construction. Silent resize is forbidden - capacity violations throw in dev builds.

## RULE-04 - Singleton Service Registration - Initialize() Contract

Singleton services (single-instance) use a dedicated typed slot, not a bucket.
They are registered via an explicit `Initialize()` call, never via `Awake` auto-wire.

public static class GlobalRegistry
{
    // --- Singleton Registration API ---

    public static void RegisterService<T>(ref T slot, T instance) where T : class
    {
#if UNITY_EDITOR || DEVELOPMENT_BUILD
        if (slot != null)
            throw new InvalidOperationException(
                $"[GlobalRegistry] Service {typeof(T).Name} already registered. " +
                $"Double-registration is forbidden.");
        if (instance == null)
            throw new ArgumentNullException(nameof(instance),
                $"[GlobalRegistry] Cannot register null as {typeof(T).Name}.");
#endif
        slot = instance;
    }

    public static void UnregisterService<T>(ref T slot, T instance) where T : class
    {
        if (!ReferenceEquals(slot, instance))
        {
#if UNITY_EDITOR || DEVELOPMENT_BUILD
            UnityEngine.Debug.LogWarning(
                $"[GlobalRegistry] Unregister mismatch for {typeof(T).Name}.");
#endif
            return;
        }
        slot = null;
    }
}

// USAGE - inside a service MonoBehaviour:
public sealed class AudioService : MonoBehaviour, IAudioService
{
    // Called explicitly by GameBootstrapper.Initialize() - NOT Awake
    public void Initialize()
    {
        GlobalRegistry.RegisterService(ref GlobalRegistry.Audio, (IAudioService)this);
        // above requires: public static IAudioService Audio; (internal set)
    }

    private void OnDisable()
    {
        GlobalRegistry.UnregisterService(ref GlobalRegistry.Audio, (IAudioService)this);
    }
}

[FORBID] `Awake()`-based cross-script dependency wiring. Use `GameBootstrapper.Initialize()` sequenced calls.
[RULE] Initialization order is the sole responsibility of `GameBootstrapper` (see RULE-05).

## RULE-05 - Initialization Order - GameBootstrapper Sequence

Initialization order is explicit and deterministic. Defined once. Changed only in `GameBootstrapper`.

Priority Byte  Layer         Systems Initialized

  0x00-0x1F    CORE          SceneService, EventBus, ConfigService
  0x20-0x3F    ENVIRONMENT   PhysicsService, AudioService, VFXService
  0x40-0x5F    PLAYER        InputService, PlayerController, CameraRig
  0x60-0x7F    UI            UIService, HUDController, DialogueSystem

public sealed class GameBootstrapper : MonoBehaviour
{
    [SerializeField] private SceneService    _sceneService;
    [SerializeField] private AudioService    _audioService;
    [SerializeField] private InputService    _inputService;
    [SerializeField] private UIService       _uiService;

    private void Start()
    {
        // LAYER 0 - CORE (Priority 0x00)
        _sceneService.Initialize();

        // LAYER 1 - ENVIRONMENT (Priority 0x20)
        _audioService.Initialize();

        // LAYER 2 - PLAYER (Priority 0x40)
        _inputService.Initialize();

        // LAYER 3 - UI (Priority 0x60)
        _uiService.Initialize();
    }
}

[RULE] `GameBootstrapper` is the ONLY class permitted to call `service.Initialize()`.
[FORBID] Services self-registering in `Awake`. This creates non-deterministic init order.
[MATH] Priority byte governs tick dispatch order in `SystemDispatcher` (see RULE-06).

## RULE-06 - Priority-Sorted Tick Dispatch - O(N) Linear Scan

The `SystemDispatcher` iterates registered `IUpdatable` entries in priority order.
Buckets are pre-sorted by layer. No runtime sort. No dictionary lookup per tick.

public sealed class SystemDispatcher : MonoBehaviour
{
    // Four pre-allocated buckets, iterated in fixed order (Core->Environment->Player->UI)
    private static readonly RegistryBucket<IUpdatable>[] _priorityLanes =
    {
        new(capacity: 16),   // CORE        0x00
        new(capacity: 32),   // ENVIRONMENT 0x20
        new(capacity: 32),   // PLAYER      0x40
        new(capacity: 16),   // UI          0x60
    };

    public static RegistryBucket<IUpdatable> GetLane(PriorityLayer layer)
        => _priorityLanes[(int)layer];

    private void Update()
    {
        float dt = Time.deltaTime;

        // O(N) scan across all lanes in deterministic priority order
        for (int lane = 0; lane < _priorityLanes.Length; lane++)
        {
            RegistryBucket<IUpdatable> bucket = _priorityLanes[lane];
            T[]  raw   = bucket.RawArray;
            int  count = bucket.Count;

            // [FORBID] Forward iteration on swap-with-last buffers.
            for (int i = count - 1; i >= 0; i--)
            {
                raw[i].Tick(dt);
            }
        }
    }
}

public enum PriorityLayer : byte
{
    Core        = 0,
    Environment = 1,
    Player      = 2,
    UI          = 3,
}

[SCALE] Total dispatch is O(N) with no allocation. No LINQ. No delegate invocation lists.
[SAFE] Dispatch path assumes `OnDisable` unregisters before destruction. Hot loop contains no Unity null interop.
[FORBID] `LinkedList`, sorted containers, or any per-tick `OrderBy` / `Sort` calls.

## RULE-07 - Safe Cleanup - Registry Clear Before Scene Unload

Stale references after scene unload cause `MissingReferenceException` in `OnDestroy`.
Registry clear MUST precede scene unload. This is enforced via a SceneService hook.

public sealed class SceneService : MonoBehaviour, ISceneService
{
    public void LoadScene(string sceneName)
    {
        // STEP 1 - Flush all multi-instance buckets before unload
        GlobalRegistry.Updatables.Clear();
        GlobalRegistry.Renderables.Clear();
        SystemDispatcher.ClearAllLanes();

        // STEP 2 - Unregister singleton services (they'll re-register in next scene's Initialize)
        // (singleton slots are cleared by each service's OnDisable - triggered by scene unload)

        // STEP 3 - Perform actual scene transition
        UnityEngine.SceneManagement.SceneManager.LoadScene(sceneName);
    }
}

// SystemDispatcher extension
public sealed partial class SystemDispatcher
{
    public static void ClearAllLanes()
    {
        foreach (var lane in _priorityLanes)
            lane.Clear();
    }
}

[FLOW] Order is non-negotiable: Clear -> Unload -> Load -> Initialize.
[SAFE] `Array.Clear` in `RegistryBucket.Clear()` nulls all slots - no loitering Unity object references.
[FORBID] Relying on `OnDestroy` call order across objects for cleanup sequencing.

## RULE-08 - Lifecycle Contract - No Hot-Loop Unity Null Checks

Registered items must unregister in `OnDisable` / `OnDestroy` before destruction.
The dispatcher does not poll `uObj == null` or `!uObj` in the tick path.

Canonical enforcement:
  - registration only while enabled
  - unregistration mandatory in `OnDisable`
  - scene flush clears buckets before unload
  - broken lifecycle = architecture bug, not dispatch responsibility

[SAFE] If a destroyed object survives in a bucket, fix the owner lifecycle. Do not add Unity null checks to the hot loop.
[FORBID] `try/catch` around `Tick()` calls as a substitute for lifecycle correctness.
[FORBID] `FindObjectOfType`, `GameObject.Find`, `GetComponentInChildren` inside `IsAlive` or any tick path.

## RULE-09 - Circular Dependency Defense

If System A requires System B at init time, and System B requires System A - the system deadlocks.
Hecton-8 forbids direct circular references. Decouple via `EventBus`.

FORBIDDEN PATTERN:
  InputService.Initialize() -> calls PlayerController.GetState()
  PlayerController.Initialize() -> calls InputService.RegisterHandler()
  -> Deadlock / NullRef on init

MANDATED PATTERN:
  InputService.Initialize()    -> publishes InputReadyEvent via EventBus
  PlayerController.Initialize() -> subscribes to InputReadyEvent via EventBus
  -> Zero direct coupling. Init order irrelevant.

// EventBus usage - break circular dependency
public sealed class InputService : MonoBehaviour, IInputService
{
    public void Initialize()
    {
        GlobalRegistry.RegisterService(ref GlobalRegistry.Input, (IInputService)this);
        GlobalRegistry.EventBus.Publish(new InputServiceReadyEvent());
    }
}

public sealed class PlayerController : MonoBehaviour, IUpdatable
{
    private void OnEnable()
    {
        GlobalRegistry.EventBus.Subscribe<InputServiceReadyEvent>(OnInputReady);
        GlobalRegistry.Updatables.Register(this);       // lane: Player
    }

    private void OnDisable()
    {
        GlobalRegistry.EventBus.Unsubscribe<InputServiceReadyEvent>(OnInputReady);
        GlobalRegistry.Updatables.Unregister(this);
    }

    private void OnInputReady(InputServiceReadyEvent _)
    {
        // Safe to use GlobalRegistry.Input here - guaranteed non-null
    }
}

[SAFE] Circular dependency between any two systems is a hard architectural defect.
[RULE] Any detected cycle MUST be broken by introducing an `EventBus` message.
[FORBID] Caching service references in field initializers or constructors.

### RULE-09B - EventBus vs GlobalRegistry State Updates

[RULE] `GlobalRegistry` is for stable service discovery and direct query of owned interfaces.
[RULE] `EventBus` is for decoupled broadcasts, dirty-state notifications, lifecycle events, and cross-domain state changes.
[RULE] Simple state updates crossing a domain boundary must use an existing event/signal contract or add a batched NativeQueue-backed signal if the update is broadcast-worthy.
[RULE] Direct `GlobalRegistry.Get<T>()` polling is allowed only for explicit request/response queries where the caller needs immediate data from the owning service and the call is outside hot broadcast cadence.

[FORBID] `GlobalRegistry.Get<T>()` for simple state updates such as "power changed", "temperature changed", "module entered", "entity damaged", "world rebased", "asset pressure changed", or "UI warning changed".
[FORBID] Using service lookup as an event transport.
[FORBID] Per-frame polling of another domain through `GlobalRegistry` when a dirty event can carry the change.
[FORBID] Creating a new EventID for one private caller. Use direct owner query for private request/response; EventBus is for broadcasts.

## Engineering Data

| Communication Shape | Required Path | Rejected Path |
|---|---|---|
| One owner, one immediate query | `GlobalRegistry` typed interface | Event spam |
| One owner, many listeners | NativeQueue EventBus signal | `GlobalRegistry.Get<T>()` polling |
| Dirty state changed | batched event with old/new hash or flags | per-frame service lookup |
| Lifecycle ready/shutdown | EventBus broadcast plus registry slot | hidden Awake dependency |
| Cross-domain command | owner interface or command queue | direct concrete class reference |

### RULE-09C - Hot-Path Service Cache

[RULE] The `GlobalRegistry.*` convenience properties follow the same hot-path law as `GlobalRegistry.Get<T>()`.
[RULE] Any service read used by `Tick()`, `FixedTick()`, `LateFrameTick()`, Burst jobs, or methods called by those paths must be copied into an owner field during `OnEnable`, bootstrap dependency injection, or a dirty lifecycle signal.
[RULE] If the service can change while gameplay is live, the owning service must publish a typed ready/changed/shutdown signal; consumers refresh the cached field from that signal, not by polling registry slots every frame.
[RULE] A hot-path direct registry read is permitted only for an explicitly measured rare event path, such as a footstep, damage impulse, crash dump, or one-shot interaction, and the rationale must name the cadence and fallback.

[FORBID] Calling `GlobalRegistry.Settings`, `GlobalRegistry.Fluid`, `GlobalRegistry.OceanKinematics`, `GlobalRegistry.ResourceDistribution`, or equivalent static service properties from per-frame player, physics, logistics, render, UI, or AI loops just because the property is cheap today.
[FORBID] Hiding registry reads inside helper methods named `Resolve*`, `Refresh*`, `Prepare*`, or `Try*` when those helpers are called by `Tick()` or `FixedTick()`.
[FORBID] Using a registry property as a silent live configuration bus. Use cached snapshot fields and dirty signals.

## Engineering Data

| Hot-Path Need | Required Shape | Rejected Shape |
|---|---|---|
| Stable service dependency | cached owner field | repeated `GlobalRegistry.*` read |
| Live settings/config | dirty signal plus cached snapshot | per-frame settings registry poll |
| Ocean/fluid/player environmental query | cached provider interface with null fallback | registry lookup in movement solver |
| Rare one-shot event | direct lookup with cadence note | unbounded helper-path lookup |

### RULE-09D - Two-Phase Dependency Injection

[RULE] Runtime systems use a strict two-phase dependency protocol: `OnRegister()` then `OnDependencyInject()`.
[RULE] `OnRegister()` exposes the system's owned interfaces, typed signal lanes, and DataVault buffer requests. It does not read other systems.
[RULE] `OnDependencyInject()` receives and caches all external interfaces required by Tick, FixedTick, LateFrameTick, Burst scheduling, renderer upload, save, and telemetry paths.
[RULE] After `OnDependencyInject()` completes, hot paths use cached fields only. A dependency changing at runtime must publish a typed ready/changed/shutdown signal and refresh a cached field on that signal.
[RULE] Bootstrap and SystemDispatcher own the order. Individual systems do not invent Awake dependency order.

Canonical shape:

```
public void OnRegister(DependencyRegistry registry)
{
    registry.Register<IHullStressProvider>(this);
    registry.RequestVaultBuffer(BufferID.HullStress, SystemID.Habitat);
}

public void OnDependencyInject(DependencySnapshot deps)
{
    _signals = deps.Get<ISignalLaneReader>();
    _vault = deps.Get<IDataVault>();
    _stressBuffer = _vault.Resolve<float>(BufferID.HullStress);
}
```

[FORBID] Calling `GlobalRegistry.Get<T>()` inside `Update()`, `Tick()`, `FixedTick()`, `LateFrameTick()`, `OnUpdate()`, Burst jobs, jobs scheduled from those methods, or helpers called by those methods.
[FORBID] Calling `GlobalRegistry.Get<T>()` from `Awake()` to wire another system.
[FORBID] Direct concrete references to another domain when an interface, SignalBus lane, or DataVault handle exists.
[FORBID] Lazy dependency lookup after the first gameplay frame. Missing dependency after injection is a fail-fast disable with telemetry, not a polling loop.

Batch 004/005 evidence: GlobalDataVault and cross-domain signal edits repeatedly created circular dependency pressure. The registry is a cold dependency spine. It is not a live query bus.

### RULE-09E - Global Authority Boundary

[RULE] Any new `GlobalRegistry` slot, global service access pattern, or registry rebound route must satisfy `Docs/ARCHITECTURE/GLOBAL_AUTHORITY_BOUNDARIES.md`.
[RULE] New subsystem setup starts owner-local and follows `Docs/ARCHITECTURE/GLOBAL_AUTHORITY_SETUP_PLAYBOOK.md` before adding registry surface.
[RULE] Any new or changed global authority route must include the route card required by `Docs/ARCHITECTURE/GLOBAL_AUTHORITY_ROUTE_CARD_TEMPLATE.md`.
[RULE] Any new or changed registry/global route must receive a `GREEN` review disposition from `Docs/ARCHITECTURE/GLOBAL_AUTHORITY_REVIEW_CHECKLIST.md` before merge.
[RULE] Registry surface growth must be paired with either deleted direct coupling, an interface extraction, or a written exception explaining why the service cannot remain domain-local.
[RULE] Registry migration work must update `Docs/ARCHITECTURE/GLOBAL_AUTHORITY_MIGRATION_LEDGER.md` when it changes the review queues, top offenders, or stop conditions.

[FORBID] Adding a registry slot for a future/absent service.
[FORBID] Adding a registry slot before proving owner-local field, cached owner interface, or existing signal/vault route is insufficient.
[FORBID] Adding registry slots to improve H-Phi or convenience without reducing actual coupling.
[FORBID] Treating registry rebound events as general gameplay event transport.
[FORBID] Approving registry access from a rationale that does not name owner, phase, cadence, failure mode, telemetry, and proof requirement.

### RULE-09F - Read Accessor Purity

[RULE] Any API named `Get*`, `TryGet*`, `Resolve*`, `Read*`, or equivalent accessor is a read contract.
[RULE] Runtime context owners publish state once from their own dispatcher phase, then consumers read immutable snapshots or cached owner interfaces.
[RULE] Hot-path dependencies resolved through the registry must be cached during bootstrap, `OnRegister`, `OnDependencyInject`, or owner initialization.

[FORBID] Publishing signals from a read-looking accessor.
[FORBID] Syncing scene hierarchy, transforms, player context, UI state, or registry rebound state from a read-looking accessor.
[FORBID] Allocating, growing DataVault/native buffers, completing jobs, mutating global state, or running scene searches from a read-looking accessor.
[FORBID] Using `GlobalDataVault.TryGetLatestCreated()` as routine domain runtime fallback from registry helper code.

Engineering rule: if a call can change global state, schedule work, or publish traffic, its name and phase must expose that fact and the route must have a route card.

## RULE-10 - Forbidden Patterns - Runtime Tick Violations

The following patterns are unconditionally forbidden in any method called per-frame.

FORBIDDEN                               REASON

GameObject.Find("Name")                 O(N) scene graph string search. Allocates.
FindObjectOfType<T>()                   O(N) scene graph type scan. No caching.
GetComponentInChildren<T>()             O(depth) tree traversal. Allocates array.
Resources.Load(path)                    Synchronous disk I/O in tick. Hitches.
new List<T>() / LINQ inside Tick()      Heap allocation -> GC pressure.
Dictionary lookup per registered item   Hash compute + potential collision chain.
Nested registry bucket lookups          Breaks cache locality. Use flat arrays only.

[FORBID] All entries in this table inside any `Tick()`, `Update()`, `FixedUpdate()`, or `LateUpdate()` path.
[RULE] All scene object references required at runtime MUST be resolved at `Initialize()` time and cached.
