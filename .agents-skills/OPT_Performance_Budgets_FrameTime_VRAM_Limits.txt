## Section4 - PHYSICS BUDGET

### 4.1 PhysX / Havok Integration Rules

Fixed timestep: 0.02s (50Hz) - NEVER go lower.
Max substeps per frame: MINIMAL=1, MED=2, ULTRA=3.
Substep overshoot clamp: if (accumulator > 3 * fixedDelta) -> drop excess.
  -> Prevents spiral-of-death on frame-time spikes.

Solver iterations: position=4, velocity=1 (MINIMAL)
                   position=6, velocity=2 (MED/ULTRA)
Contact pairs cap: 2048 active per frame.
Broadphase: SAP (Sweep-And-Prune). MBP for open-world quadrant handoff.

### 4.2 Collision Layer Budget

Active rigidbodies:    MINIMAL=80,  MED=200,  ULTRA=400
Kinematic bodies:      MINIMAL=200, MED=500,  ULTRA=1000
Trigger volumes:       MINIMAL=100, MED=250,  ULTRA=500
Cloth simulated meshes: MINIMAL=0,  MED=2,    ULTRA=6
Soft-body (custom):    MINIMAL=0,  MED=0,    ULTRA=3

Layer matrix: disable all non-essential cross-layer queries.
Creature<->Creature collision: DISABLED on MINIMAL tier. Use overlap sphere approximation.

### 4.3 Buoyancy Simulation

Voxel-based buoyancy budget:
  MINIMAL: 1 voxel/object (center-of-mass approx)
  LOW:     4 voxels/object
  MED:    16 voxels/object
  ULTRA:  64 voxels/object

Per-voxel force calc:
  F_buoy = rho_water * g * V_submerged_voxel
  _water = 1025 kg/m^3 (seawater constant)
  V_submerged = voxel_volume * clamp01((water_surface_y - voxel_y) / voxel_height)
  Apply as AddForceAtPosition() -> atPoint = voxel_world_pos

Buoyancy tick rate: every 3 physics frames (not every substep).
Max buoyant objects simultaneous: MINIMAL=8, MED=20, ULTRA=50.

### 4.4 Fluid / Current Simulation

Current field: 3D vector field, resolution per quality:
  MINIMAL: 4x4x4 = 64 cells
  MED:     8x8x8 = 512 cells
  ULTRA:  16x16x8 = 2048 cells

Sample method: trilinear interpolation. Cost: O(1) per entity.
Update cadence: full field recompute every 2s. Linear interpolate between.
Turbulence layer: additive Perlin noise (2 octaves MINIMAL, 4 ULTRA).
  noise_freq = 0.15, noise_amp = current_speed * 0.3
Entity receives: velocity_applied = lerp(entity_vel, current_vel, drag_coeff * dt)
  drag_coeff: creature=0.8, debris=0.95, player=0.4

## Section5 - LOGIC / AI BUDGET

### 5.1 Tick Rate Architecture

TICK CLASSIFICATION

HotTick   (every frame, main thread):  Input, Player state, Camera
WarmTick  (every 3 frames, jobified):  Near creature AI, Inventory
SlowTick  (every 10 frames, staggered): Far creature AI, Ambiance, Env queries
ColdTick  (every 60 frames, async):    World state eval, Spawn budget recalc
FrostTick (every 300 frames, async):   Memory audit, LOD bias recalc, Save hint

SlowTick stagger formula:
  entity_tick_frame = entity_id % SLOW_TICK_INTERVAL
  -> entity updates on frame where (frame_count % 10 == entity_id % 10)
  -> 1/10th of all SlowTick entities update per frame -> flat cost curve

### 5.2 Entity Update Budget

ENTITY COUNT CAPS

Creature archetype caps:

  Mid-tier creatures: 4        8     16    32
  Small schooling:    20       50    100   200  (Boids system)
  Ambient fauna:      40       80    160   300  (SlowTick only)

### 5.3 Boid Simulation Budget

Boid compute shader tiers:
  MINIMAL: CPU boids, 20 max, O(n^2) capped at n=20 -> 400 comparisons
  LOW:     CPU boids, 50 max, spatial hash O(n) amortized
  MED:     GPU compute, 100 boids, 1 dispatch/frame
  ULTRA:   GPU compute, 200 boids, 1 dispatch/frame

Boid rule weights (normalized, must sum = 1.0):
  separation: 0.4
  alignment:  0.35

Neighborhood query radius: 8m. Bin size: 4m (2x smaller = 8 bins/radius sphere).
GPU dispatch: 1 thread/boid. GroupSize=64. Groups=ceil(boid_count/64).

### 5.4 AI Pathfinding Budget

Navigation mesh: voxel-based, baked offline.
Voxel size:  MINIMAL=1.0m, MED=0.5m, ULTRA=0.25m
Max agent radius classes: 3 (Small=0.4m, Med=1.0m, Large=2.5m)

  20m-80m from player -> flow field shared per species

Path cache: store last 3 waypoints. Reuse if destination delta < 2m.
Max simultaneous A* queries/frame: MINIMAL=2, MED=6, ULTRA=12.
A* node limit per query: 512 nodes hard cap -> returns best partial path.

## Section6 - LOAD-SHEDDING PROTOCOL

### 6.1 VRAM Pressure Response

TRIGGER:  usedVRAM / totalVRAM > 0.90
SEQUENCE (execute in order, stop when pressure relieved):
  Step 1: RequestAsyncMipDowngrade(allStreamingTextures, mipBias += 1)
          -> Expected relief: 200-400MB
  Step 2: EvictQueue.DrainSynchronously() on released Addressables only
          -> Expected relief: 50-150MB
  Step 3: Reduce RenderTexture resolution * 0.75 for non-primary cameras
          -> Expected relief: 80-200MB
  Step 4: Force LOD bias += 0.5 globally (objects LOD earlier)
  Step 5: If still > 0.90 after 5 frames -> drop to MINIMAL render tier

RECOVERY: pressure < 0.75 for 10 consecutive frames -> restore one step at a time.
Restore cadence: 1 step per 30 frames. Prevents thrash oscillation.

### 6.2 Frame-Time Spike Response

DETECTION:
  rolling_avg = sum(frameTimes[last 8 frames]) / 8
  spike_detected = (currentFrameTime - rolling_avg) > 5ms

SUSTAINED OVERLOAD (frame_time > 25ms for 3+ consecutive frames):
  Step 1: Disable volumetric shadow casting (saves ~1-2ms)
  Step 2: Reduce active Boid count by 50% (pool remainder, re-enable on recovery)
  Step 3: Increase SlowTick interval: 10 -> 20 frames
  Step 4: Disable SSR, reduce custom SSDO samples by 50%
  Step 5: Raymarching step count -> MINIMAL tier values
  Step 6: Reduce max active rigidbodies by 40%
  Step 7: Disable post-process passes beyond Color Grade and required underwater distortion

CRITICAL (frame_time > 33ms for 2+ frames):
  -> Force resolution scale to 0.6
  -> Disable all non-player physics
  -> Cull all entities > 40m
  -> Log CRITICAL_PERF_EVENT with system snapshot

RECOVERY: frame_time < 18ms for 15 consecutive frames -> restore 1 step per 10 frames.

### 6.3 Thermal Throttle Detection

DETECTION METHOD:
  thermal_trend = linearRegression(frameTimes[last 60 frames]).slope
  throttling = thermal_trend > 0.05ms/frame (consistently worsening)

RESPONSE:
  Step 1: Enable aggressive view-frustum culling (tighten FOV cull margin: 5 deg -> 0 deg)
  Step 2: Reduce SlowTick to 1/15th (from 1/10th)
  Step 3: Drop max substeps to 1
  Step 4: Emit ThermalThrottleEvent -> UI hint "Performance mode active"
  Step 5: Persist throttle state until 120-frame stability confirmed

linearRegression on 60 samples: O(n) Welford-variant. No heap alloc. Stack only.

### 6.4 Memory Pressure Response

TRIGGER: managedHeap > 220MB OR totalRAM > 5.8GB

Step 1: Force GC.Collect() - only acceptable call site for GC
        -> Must occur on a frame where frame_time < 14ms (safe window)
Step 2: Flush audio streaming buffers not accessed in 30s
Step 3: Reduce chunk ring buffer from 512MB -> 384MB (unload distant chunks)
Step 4: Disable procedural ambient audio generation
Step 5: If totalRAM > 6.2GB -> emergency unload of 2 farthest world sectors

Heap monitoring: sample every 10 frames. No per-frame overhead.

## Section7 - WORLD STREAMING BUDGET

### 7.1 Chunk System Architecture

Chunk size: 64m x 64m x 32m (underwater columns)
Ring buffer radius:  MINIMAL=2 chunks, MED=3 chunks, ULTRA=4 chunks
                     (counts in all directions from player)

Active chunks:  MINIMAL=25,  MED=49,  ULTRA=81  (2r+1)^2
Chunk load time budget: 5ms per frame MAX for streaming ops.
Load strategy: async read -> decompress on worker -> main thread integrate < 1ms.

Chunk state machine:
  UNLOADED -> QUEUED -> LOADING(async) -> INTEGRATING(main,<1ms) -> ACTIVE
  ACTIVE -> UNLOADING(async) -> UNLOADED

Priority queue: distance^2 + player_velocity_projection (predictive preload).
Preload distance: player_speed * 4s lookahead in movement direction.

### 7.2 Occlusion & Culling Strategy

Hierarchical Z-Buffer culling: mandatory.
Occlusion proxy meshes: max 100 triangles per chunk proxy.
Culling update: every 2 frames on MINIMAL, every frame on ULTRA.

Underwater-specific: reverse frustum importance (close objects priority).
Volumetric occlusion zones (rock formations): pre-baked PVS sectors.
PVS cell size: 8m. Max visible cells from any cell: 48 (MED), 96 (ULTRA).
Portal-based transitions (cave -> open water): PVS handoff at portal crossing.

CPU occlusion queries: max 32 per frame (MINIMAL), 128 per frame (ULTRA).
Results consumed 2 frames later (async). Stale results = visible (safe default).

## Section10 - SCALABILITY DECISION TREE

ON SESSION START:
  1. Benchmark GPU: run 50-frame headless draw call stress test
  2. Benchmark CPU: measure JobSystem throughput with dummy workload
  3. Query VRAM: GraphicsDeviceMemory API
  4. Query RAM: SystemInfo.systemMemorySize
  5. Map to tier via hardware table Section0
  6. Apply all tier defaults from Section3-Section9
  7. Allow user override +/-1 tier (enforced, not advisory)

ON SETTINGS CHANGE:
  Validate: new_settings must not push any budget over 95% utilization
  If violation: revert setting + display specific conflict reason

RUNTIME ADAPTIVE:
  Every 300 frames: re-evaluate all Section6 triggers
  Hysteresis requirement: must exceed threshold for N frames before acting:
    N=3 frames (spike), N=15 frames (sustained), N=60 frames (thermal)
  Hysteresis prevents single-frame anomaly from triggering cascade.
