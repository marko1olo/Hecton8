## SECTION 1: EXECUTION POLICY

### Non-Negotiable Rules
1. NO UNITY JOINTS. `HingeJoint`, `SpringJoint`, `ConfigurableJoint`, and all derivatives are FORBIDDEN on any tether-classified object. Violation fails code review.
2. ForceMode.Acceleration is mandatory for all spring force application. `ForceMode.Force` is forbidden for tether springs. `ForceMode.Impulse` is reserved exclusively for the Wipeout snap event.
3. Bend point calculation runs only when LOS is broken. Do not run `RaycastNonAlloc` bend logic every frame if the direct Player→Payload segment is unobstructed. Cache the result.
4. Verlet position correction fires before spring force. The hard distance constraint (Section 5) is a pre-pass. It is not a competing system; it is a floor beneath the spring.
5. All tether logic executes in `FixedUpdate`. Visual segment positions update in `LateUpdate`. Zero tether physics in `Update`.
6. Stress timer is cumulative, not instantaneous. A single frame of high tension does not snap a cable. The `_stressTimer` must breach the threshold duration.

### Enforcement
Any script applying a tether spring force that does not use `ForceMode.Acceleration` will be rejected at PR. The reviewer will leave the comment: `MANDATE #3 VIOLATION: ForceMode`.

## SECTION 3: MATH TRUTH

### 3.1 Reduced Mass
Used to make the damping coefficient physically meaningful for a two-body system.

reducedMass = (m_player * m_payload) / (m_player + m_payload)

If `payloadRb.isKinematic` is true (e.g., anchored grapple point), treat `m_payload = ∞`, so `reducedMass = m_player`.

### 3.2 Critical Damping Coefficient
Calculated once when the tether is attached, and recalculated if payload mass changes (e.g., voxel destruction lightens the wreck).

c_critical = 2 * sqrt(k * reducedMass)
c_actual   = c_critical * overDampingMultiplier

- `TowCable`: `overDampingMultiplier` = 1.2 (mandatory minimum).
- This eliminates oscillation in tow scenarios. The cable will not "bounce" the wreck.

### 3.3 Spring Force in Acceleration Space

For each segment between anchor A and anchor B (where B may be a bend point or the payload):

// 1. Geometry
delta         = B.position - A.position
currentDist   = delta.magnitude
direction     = delta / currentDist          // normalized

// 2. Spring extension (only pulls, never pushes — cable, not rod)
extension     = currentDist - segmentRestLength
if (extension <= 0) → skip force application for this segment

// 3. Relative velocity along cable axis
relVel        = B.velocity - A.velocity      // use Rigidbody.velocity for dynamic bodies
                                             // use Vector3.zero for static bend points
relVelAlongCable = Vector3.Dot(relVel, direction)

// 4. Raw spring-damper force magnitude (Newtons, conceptual)
F_spring  = k * extension
F_damping = c * relVelAlongCable
F_total   = F_spring + F_damping             // positive = attractive

// 5. Convert to acceleration (mass-independent) — THIS IS WHY WE USE ForceMode.Acceleration
// ForceMode.Acceleration applies: force_applied = acceleration (Unity multiplies by mass internally)
// So we simply pass the acceleration vector directly.
acceleration_A = +direction * F_total       // pulls A toward B
acceleration_B = -direction * F_total       // pulls B toward A

// 6. Apply
playerRb.AddForce(acceleration_A, ForceMode.Acceleration)
payloadRb.AddForce(acceleration_B, ForceMode.Acceleration)

Why Acceleration mode prevents energy spikes on heavy objects:
With `ForceMode.Force`, `a = F/m`. A 50,000 kg wreck yields near-zero acceleration from moderate spring forces, causing the spring to overextend and accumulate massive energy. With `ForceMode.Acceleration`, the acceleration is mass-independent — the heavy wreck moves at the same corrective rate as a light object, and energy is bounded by `k` and `c`, not by mass ratio.

### 3.4 Chain Tension Through Bend Points

Bend points are massless virtual pivots. They do not receive force. Tension propagates through them geometrally.

For a chain: Player → BP[0] → BP[1] → Payload

Segment[0]: Player   → BP[0]    restLength = restLength * segmentFraction[0]
Segment[1]: BP[0]   → BP[1]    restLength = restLength * segmentFraction[1]
Segment[2]: BP[1]   → Payload  restLength = restLength * segmentFraction[2]

Each segment fraction = `segmentLength_at_attach / totalLength_at_attach`.

Apply Section 3.3 logic independently per segment. Only Player and Payload Rigidbodies receive `AddForce`. Bend points update their world position to remain on their registered voxel corner (they do not drift).

Tension scalar for stress evaluation = the largest `F_total` across all active segments.

### 3.5 Non-Elastic Hard Constraint (Verlet Correction)

Fires in `FixedUpdate` before spring force is applied. Only activates when `currentLength > restLength * nonElasticLimitRatio`.

// Per segment (or direct Player→Payload if no bend points)
overExtension   = currentDist - (segmentRestLength * nonElasticLimitRatio)
if (overExtension <= 0) → skip

// Correction split proportional to inverse mass (heavier body moves less)
totalInvMass    = (1/m_player) + (1/m_payload)
correctionA     = direction *  overExtension * (1/m_player) / totalInvMass
correctionB     = direction * -overExtension * (1/m_payload) / totalInvMass

playerRb.position  += correctionA
payloadRb.position += correctionB

// Kill velocity component along cable that caused overextension
relVelAlongCable = Vector3.Dot(relVel, direction)
if (relVelAlongCable > 0):  // bodies moving apart
    velCorrection        = direction * relVelAlongCable
    playerRb.velocity   -= velCorrection * (1/m_player) / totalInvMass
    payloadRb.velocity  += velCorrection * (1/m_payload) / totalInvMass

This is a positional correction pass, not a force. It is the inelastic floor.

### 3.6 Stress Accumulation & Snap Protocol

// In FixedUpdate, after force application:
float peakTension = GetPeakSegmentTension(); // Max F_total across segments

if (peakTension > profile.snapTensionThreshold)
{
    _stressTimer += Time.fixedDeltaTime;
}
else
{
    // Recover at half the accumulation rate (cable "heals" slowly)
    _stressTimer = Mathf.Max(0f, _stressTimer - Time.fixedDeltaTime * 0.5f);
}

if (_stressTimer >= profile.snapStressDuration)
{
    InvokeSnapProtocol();
}

SnapProtocol:

private void InvokeSnapProtocol()
{
    isSnapped = true;

    // 1. Wipeout impulse — direction is AWAY from payload (cable recoil)
    Vector3 snapDir = (playerRb.position - payloadRb.position).normalized;
    playerRb.AddForce(snapDir * profile.wipeoutImpulseMagnitude, ForceMode.Impulse);

    // 2. Detach payload — zero out any residual tether velocity contribution
    //    (do NOT zero payload velocity — it should continue moving under momentum)

    // 3. Notify TetherManager for cleanup
    TetherManager.Instance.OnTetherSnapped(this);

    // 4. Trigger VFX/SFX event (via event bus, not direct reference)
    GameEvents.TetherSnapped?.Invoke(transform.position);
}

## SECTION 4: SCALE & PERFORMANCE

### 4.1 LOS Check Amortization

// Do NOT run bend-point detection every FixedUpdate.
// Stagger checks across frames.

losCheckCooldownFrames--;
if (losCheckCooldownFrames <= 0)
{
    bool currentLOS = CheckDirectLOS(playerPos, payloadPos);
    if (currentLOS != losBlocked || bendPoints.Count == 0)
    {
        RecalculateBendPoints();
    }
    losBlocked = !currentLOS;
    losCheckCooldownFrames = 3; // Re-check every 3 fixed frames (~20Hz at 60Hz physics)
}

### 4.2 Bend Point Detection: `RaycastNonAlloc`

private static RaycastHit[] _bendHitBuffer = new RaycastHit[16]; // Static, no alloc

private void RecalculateBendPoints()
{
    bendPoints.Clear();

    Vector3 origin = playerRb.position;
    Vector3 target = payloadRb.position;
    int segmentsToCheck = bendPoints.Count + 1; // Iterative: walk the existing chain

    for (int i = 0; i < profile.maxBendPoints; i++)
    {
        Vector3 dir = target - origin;
        float dist  = dir.magnitude;
        dir /= dist;

        int hitCount = Physics.RaycastNonAlloc(origin, dir, _bendHitBuffer, dist, voxelLayerMask);

        if (hitCount == 0) break; // LOS clear from this point forward

        // Find closest hit
        RaycastHit closest = GetClosestHit(_bendHitBuffer, hitCount);

        // Project onto the nearest voxel corner
        Vector3 cornerPos = SnapToNearestVoxelCorner(closest.point, closest.normal);
        bendPoints.Add(cornerPos);

        // Advance origin to the new bend point and continue checking toward payload
        origin = cornerPos + dir * profile.bendPointClearanceRadius;
    }
}

`SnapToNearestVoxelCorner` must query the VoxelGrid system (Mandate #1) to find the nearest corner vertex of the intersected voxel cell. It does NOT use `closest.point` raw — raw hit points will drift mid-face, causing cable slide.

### 4.3 Single Line vs. Visual Segments

| System | Representation | Update Rate | Purpose |
|---|---|---|---|
| Physics | Direct Rigidbody↔Rigidbody segments through bend points | Every `FixedUpdate` | Force, stress, constraint |
| Visual | `visualSegmentCount` interpolated points with catenary sag | Every `LateUpdate` | Rendering only |

Visual catenary generation (LateUpdate):

// Between each physics anchor pair, generate N visual points.
// Sag is approximated by a parabolic offset perpendicular to the segment,
// scaled by segmentLength and a sag factor (0.05 * segmentLength).
// Smoothly Lerp each visual point toward its target each frame (no jitter).

Visual segments have no Colliders, no Rigidbodies. They are `LineRenderer` control points only.

### 4.4 Budget
| Active Tethers | Max Bend Points Each | Physics Segments | Max FixedUpdate Raycasts |
|---|---|---|---|
| 4 | 4 | 5 per tether = 20 | 4 × 1 amortized per 3 frames = ~1.3/frame |

If active tether count exceeds 4, the 5th+ tethers use Single Line Approximation only (no bend detection) until count drops below 4.

## SECTION 5: VOXEL INTEGRITY — ANTI-SLICING

### 5.1 The Problem
A cable connecting Player at position A and Payload at position B will, in a single physics tick, have its endpoints move. If endpoint motion causes the straight-line segment A→B to pass through a voxel wall without a bend point registered, the cable visually "clips" through geometry. This is forbidden.

### 5.2 Sweep Validation (Post-Force, Pre-Render)

// After force application, sweep each physics segment for new intersections.
// This is a DETECTION pass, not a correction pass.
// Correction = spawning a new bend point next RecalculateBendPoints() call.

private void ValidateCableIntegrity()
{
    Vector3 prev = playerRb.position;
    List<Vector3> anchors = BuildAnchorChain(); // Player → BendPoints → Payload

    for (int i = 1; i < anchors.Count; i++)
    {
        Vector3 curr = anchors[i];
        Vector3 dir  = curr - prev;
        float dist   = dir.magnitude;

        int hits = Physics.RaycastNonAlloc(prev, dir.normalized, _bendHitBuffer, dist, voxelLayerMask);
        if (hits > 0)
        {
            // Flag: LOS broken in a segment that should be clear.
            // Force an immediate RecalculateBendPoints() next FixedUpdate (bypass cooldown).
            losCheckCooldownFrames = 0;
            break;
        }
        prev = curr;
    }
}

### 5.3 Forbidden Condition
A tether segment is considered "slicing" if:
- A `Raycast` along any physics segment returns a voxel hit, AND
- No bend point exists at or near that intersection.

If slicing is detected for 3 consecutive FixedUpdate frames on the same segment (debounced to avoid false positives from ragged voxel geometry), the cable is force-snapped via `InvokeSnapProtocol()` with `wipeoutImpulseMagnitude = 0` (no player knockback — this is a safety release, not a gameplay event). Log a warning: `[TETHER] Anti-slice emergency detach on TetherInstance [{id}]`.

## SECTION 8: QUICK-REFERENCE FORMULA CARD

reducedMass          = (mA * mB) / (mA + mB)
c_critical           = 2 * sqrt(k * reducedMass)
c_actual             = c_critical * overDampingMultiplier     [TowCable: min 1.2]

extension            = currentDist - restLength               [cable: clamp to >= 0]
F_spring             = k * extension
F_damping            = c * dot(relVel, cableDir)
acceleration_applied = (F_spring + F_damping) / 1.0           [ForceMode.Acceleration — Unity handles mass]

hardConstraintFires  = currentDist > restLength * 1.10
stressTimer         += deltaTime  if tension > threshold
stressTimer         -= deltaTime * 0.5  if tension <= threshold
SNAP                 = stressTimer >= snapStressDuration
