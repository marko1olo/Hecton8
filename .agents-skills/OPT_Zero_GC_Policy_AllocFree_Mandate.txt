## SECTION 0: EXECUTIVE DECLARATION

The MX350 and all target mobile silicon are allergic to Garbage Collector.
One kilobyte of heap allocation in hot path produces frame hitch. One frame hitch breaks immersion. Broken immersion kills product.

This document is Holy War against heap. It is not guideline. It is not suggestion. It is load-bearing engineering constraint with same authority as structural spec in bridge design. Violations are build-blocking defects. Repeated violations are performance review event.

The GC budget for all `Tick` and `FixedTick` paths is: `0 BYTES`.

You will internalize this number. You will design around this number. You will audit your PRs against this number.

## SECTION 2: FORBIDDEN LIST - ABSOLUTE BANS IN `Tick` / `FixedTick`

These constructs are prohibited with zero tolerance inside `Tick()`, `FixedTick()`, and any method they directly or transitively call. compiler does not warn you. linter will. But you must also know these by reflex.

### 2.1 LINQ - BANNED

//  FORBIDDEN - Produces heap garbage every frame
var enemies = allUnits.Where(u => u.IsEnemy).ToList();
float total = damages.Sum();
var first = targets.FirstOrDefault(t => t.IsVisible);

//  CORRECT - Manual loop, zero allocation
var enemies = _enemyScratchBuffer; // pre-allocated List<Unit> or NativeArray
int enemyCount = 0;
for (int i = 0; i < _allUnitsCount; i++)
{
    if (_allUnits[i].IsEnemy)
        enemies[enemyCount++] = _allUnits[i];
}

No exceptions. Not for "just one query." Not for "it's small list." Banned.

---

### 2.2 `foreach` on Dictionaries and Interfaces - BANNED

// FORBIDDEN - IEnumerable<T> iteration causes boxing. Direct foreach on Dictionary is allocation-free in modern Unity, but we ban it to enforce index-based patterns for cache locality.
foreach (var kvp in _unitRegistry)
{
    kvp.Value.Tick(dt);
}

//  FORBIDDEN - IEnumerable<T> parameter forces boxing
void TickAll(IEnumerable<Unit> units) { foreach (var u in units) { ... } }

//  CORRECT - Iterate Values list directly via index
// Registry exposes flat array/List, not dictionary iteration
for (int i = 0; i < _registryCount; i++)
{
    _registryValues[i].Tick(dt);
}

Rule: If you cannot iterate with `for(int i ...)`, data structure is wrong. Fix data structure, not loop.

---

### 2.3 `new` Class Instances - BANNED

//  FORBIDDEN - Heap allocation every frame
var cmd = new MoveCommand(unit, destination);
_commandQueue.Enqueue(cmd);

//  FORBIDDEN - Creating containers mid-frame
var hits = new List<RaycastHit>();

//  CORRECT - Object pool pattern
var cmd = _moveCommandPool.Rent(); // Returns pre-allocated, reset instance
cmd.Init(unit, destination);
_commandQueue.Enqueue(cmd);

// On completion:
_moveCommandPool.Return(cmd);

Structs do not trigger heap allocation when used correctly. See Section 8.
`new` on struct is fine. `new` on class in hot path is not.

### 2.4 String Concatenation and Interpolation - BANNED

//  FORBIDDEN - New string object allocated every frame
hudLabel.text = $"HP: {currentHP}";
hudLabel.text = "Score: " + score.ToString();
hudLabel.text = string.Format("AMMO: {0}/{1}", current, max);

## SECTION 3: STRING-FREE HUD - BUFFER MANDATE

### 3.1 Core Principle

The HUD must update every frame on some elements. HUD must never allocate string to do so. These two facts are reconciled by writing integers directly into pre-allocated `char[]` buffer and passing that buffer to TextMeshPro without ever creating `string` object.

### 3.2 `IntToBuffer` Utility

A shared `StringUtils` static class provides allocation-free integer-to-character conversion. This is your only approved method for converting numeric game state to displayable text.

/// <summary>
/// Writes decimal representation of 'value' into 'buffer'
/// starting at 'offset'. Returns number of characters written.
/// Zero allocation. Handles negative values.
/// </summary>
public static int IntToBuffer(int value, char[] buffer, int offset)
{
    if (value == 0)
    {
        buffer[offset] = '0';
        return 1;
    }

    int start = offset;
    bool negative = value < 0;
    if (negative) value = -value;

    int end = offset;
    while (value > 0)
    {
        buffer[end++] = (char)('0' + (value % 10));
        value /= 10;
    }

    if (negative) buffer[end++] = '-';

    // Reverse written segment
    int left = start, right = end - 1;
    while (left < right)
    {
        (buffer[left], buffer[right]) = (buffer[right], buffer[left]);
        left++; right--;
    }

    return end - start;
}

### 3.3 Mandatory HUD Update Pattern

public class HealthDisplay : MonoBehaviour
{
    [SerializeField] private TMP_Text _label;

    // Pre-allocated buffer. Never replaced. Never resized.
    // Sized for worst-case string: "HP: -2147483648/999" = 20 chars, allocate with margin.
    private readonly char[] _buffer = new char[32];

    private void Awake()
    {
        // Write static prefix once at init - no per-frame cost for prefix
        _buffer[0] = 'H';
        _buffer[1] = 'P';
        _buffer[2] = ':';
        _buffer[3] = ' ';
    }

    // Called from UI tick - NOT from Update() directly if batching is possible
    public void UpdateDisplay(int currentHP, int maxHP)
    {
        // Write current HP starting at index 4
        int cursor = 4;
        cursor += StringUtils.IntToBuffer(currentHP, _buffer, cursor);

        _buffer[cursor++] = '/';

        cursor += StringUtils.IntToBuffer(maxHP, _buffer, cursor);

        //  TMP SetText overload accepts char[], start index, length - ZERO allocation
        _label.SetText(_buffer, 0, cursor);
    }
}

### 3.4 `.ToString()` - BANNED on Hot Paths

`.ToString()` on any numeric type or enum produces heap-allocated string. It is banned in `Tick`, `FixedTick`, and any per-frame UI update path.

// X FORBIDDEN
label.text = score.ToString();
label.text = ammoCount.ToString("D3");

// [OK] CORRECT
// Use IntToBuffer and TMP SetText(char[], int, int)

Exception: `.ToString()` is permitted in `Awake()`, `Start()`, `OnEnable()`, `OnDisable()`, Editor code, and logging paths that are guarded by `#if UNITY_EDITOR` or `Debug.isDebugBuild` checks.

### 3.5 `Span<char>` / `ReadOnlySpan<char>` Law

[RULE] `Span<char>` is the default formatting surface for hot UI text and localization assembly.
[RULE] Use `value.TryFormat(span, out written, format)` or `ZeroGCFormatter` into preallocated `char[]`, `FixedCharBuffer`, or arena-backed frame-local spans.
[RULE] `ReadOnlySpan<char>` is the default parser/templating input for localization, save diagnostics, and UI label composition.

[FORBID] `new string(span)` in hot paths.
[FORBID] `string.Create(...)` in hot paths. It still creates a managed string.
[FORBID] storing `Span<T>` in fields, captured lambdas, async methods, iterator methods, or job structs.
[FORBID] `stackalloc` above 256 bytes in gameplay frame paths. Larger scratch uses `CharBufferPool` or `HectonArenaAllocator`.
[FORBID] culture-sensitive `TryFormat` in hot paths unless the culture object is static/cached and the call is proven allocation-free.

[SAFE] `Span<T>` may wrap a persistent `char[]` field, a pooled buffer lease, or a frame-local arena allocation.
[SAFE] Burst jobs use `FixedString32Bytes`, `FixedString64Bytes`, or `FixedString128Bytes`; they do not use `Span<char>`.

## SECTION 4: REGISTRY PATTERN - REPLACE FIND OPERATIONS

### 4.1 Problem with Unity's Find APIs

`Resources.FindObjectsOfTypeAll<T>()`, `GameObject.Find()`, `FindObjectOfType<T>()`, and `GetComponentsInChildren<T>()` are banned at runtime (outside of initialization phases) because:

1. They iterate entire scene hierarchy - O(n) on all loaded objects.
2. They allocate new arrays for results every call.
3. They acquire Unity internal locks, causing hitches under threading.
4. They return null on failure with zero diagnostic context.

### 4.2 `Registry<T>` System

All locatable game objects must register themselves. Consumers query registry, not scene.

/// <summary>
/// Static O(1) registration and O(1) removal registry.
/// Uses swap-with-last for removal - preserves array density, no gaps.
/// Thread-unsafe by design: all access must be from main thread.
/// </summary>
public static class Registry<T> where T : class
{
    // Flat array - cache-friendly, index-iterable
    private static T[] _items = new T[256];
    private static int _count = 0;

    public static int Count => _count;

    /// <summary>O(1) registration. Call from OnEnable.</summary>
    public static void Register(T item)
    {
        if (_count >= _items.Length)
        {
            // Resize only during initialization phases - never in Tick
            // If this triggers during gameplay, your pool sizing is wrong
            Array.Resize(ref _items, _items.Length * 2);
            Debug.LogWarning($"[Registry<{typeof(T).Name}>] Resized to {_items.Length}. Pre-warm your pools.");
        }
        _items[_count++] = item;
    }

    /// <summary>
    /// O(1) removal via swap-with-last.
    /// Preserves array density. Does not maintain order - callers must not
    /// depend on registration order for iteration semantics.
    /// Call from OnDisable.
    /// </summary>
    public static void Unregister(T item)
    {
        for (int i = 0; i < _count; i++)
        {
            if (ReferenceEquals(_items[i], item))
            {
                // Swap with last element
                _items[i] = _items[_count - 1];
                _items[_count - 1] = null; // Clear dangling reference for GC
                _count--;
                return;
            }
        }
        Debug.LogError($"[Registry<{typeof(T).Name}>] Attempted to unregister item not in registry.");
    }

    /// <summary>
    /// Direct array access for hot-path iteration.
    /// Use for(int i = 0; i < Registry<T>.Count; i++) pattern ONLY.
    /// Do NOT cache array reference across frames - resizing invalidates it.
    /// </summary>
    public static T GetAt(int index) => _items[index];

    /// <summary>Reset for scene transitions. Call from scene lifecycle manager.</summary>
    public static void Clear()
    {
        for (int i = 0; i < _count; i++) _items[i] = null;
        _count = 0;
    }
}

### 4.3 Mandatory Registration Pattern

public class EnemyUnit : MonoBehaviour
{
    private void OnEnable()
    {
        Registry<EnemyUnit>.Register(this);
    }

    private void OnDisable()
    {
        Registry<EnemyUnit>.Unregister(this);
    }
}

// Consumer - in manager's Tick():
public void Tick(float dt)
{
    int count = Registry<EnemyUnit>.Count;
    for (int i = 0; i < count; i++)
    {
        Registry<EnemyUnit>.GetAt(i).Tick(dt);
    }
}

`Resources.FindObjectsOfTypeAll` and `GameObject.Find` are BANNED at runtime. If you need to locate object, it must be in Registry. If it's not in Registry, architecture is incomplete - fix architecture.

## SECTION 5: COLLECTION ITERATION POLICY

### 5.1 Mandatory Loop Form

All iteration over collections in hot paths must use explicit index-based `for` loops:

// [OK] ONLY APPROVED HOT-PATH ITERATION PATTERN
for (int i = 0; i < _count; i++)
{
    _items[i].DoWork();
}

### 5.2 Why `IEnumerable<T>` is Boxing Hazard

`IEnumerable<T>` is interface. Interfaces are reference types. When value type (struct) is stored behind interface reference, runtime must box it - copy value from stack into heap-allocated wrapper object.

The `foreach` keyword calls `GetEnumerator()`. If collection implements `IEnumerable<T>`, return type is `IEnumerator<T>` - interface. Even if underlying enumerator is struct (as with `List<T>.Enumerator`), returning it as `IEnumerator<T>` boxes it.

// What foreach actually compiles to (simplified):
IEnumerator<Unit> enumerator = myList.GetEnumerator(); // <- BOXING if through interface
try {
    while (enumerator.MoveNext()) {
        Unit u = enumerator.Current;
        u.Tick(dt);
    }
} finally {
    enumerator.Dispose();
}

The boxing cost is:
- One heap allocation per `foreach` invocation.
- GC pressure accumulating across every hot-path frame.
- Virtual dispatch overhead on `MoveNext()` and `Current` through interface vtable.

### 5.3 Collection Type Priority Order

| Priority | Collection Type | Notes |
|----------|----------------|-------|
| 1st | `NativeArray<T>` / `NativeList<T>` | Unmanaged memory, Burst-compatible, zero GC |
| 2nd | `T[]` (raw array) | Stack-indexed, no GC overhead |
| 3rd | `List<T>` accessed by index | `list[i]` - no boxing, acceptable |
| 4th | `Registry<T>.GetAt(i)` | As defined in Section 4 |
| BANNED | `IEnumerable<T>` in hot path | Boxing hazard |
| BANNED | `Dictionary<K,V>` iteration in hot path | Enumerator boxing |

If you need dictionary lookup by key in hot path: Pre-compute key lookup in `Awake` and cache reference. Do not call `dict[key]` inside `Tick` unless it is `NativeHashMap` or equivalent.

### 5.4 GlobalDataVault Native Sovereignty

[RULE] All NativeArrays must be requested from GlobalDataVault. Local instantiation is banned.
[RULE] `NativeArray<T>`, `NativeList<T>`, `NativeHashMap<TK,TV>`, `NativeParallelHashMap<TK,TV>`, `NativeQueue<T>`, and unmanaged scratch buffers used beyond one cold method scope must come from a DataVault-owned buffer handle with owner id, capacity, generation, lifetime, and disposal path.
[RULE] A system may cache a DataVault handle or a read-only slice after dependency injection. It may not allocate an independent persistent NativeArray because it is convenient.
[RULE] Temporary local native allocation is permitted only for a single cold conversion/import method, never for Tick, FixedTick, LateFrameTick, Burst job steady-state, renderer upload cadence, or gameplay simulation.
[RULE] Resize requests go through the vault owner. Systems request capacity; the vault decides allocation, relocation, and generation increment.

[FORBID] `new NativeArray<T>(..., Allocator.Persistent)` inside gameplay systems outside GlobalDataVault or an explicitly named vault-owned allocator.
[FORBID] `new NativeArray<T>(..., Allocator.TempJob)` as a hidden substitute for persistent system state.
[FORBID] Passing raw local native containers across domain boundaries.
[FORBID] Holding stale NativeArray aliases after a vault relocation, capacity change, scene unload, or generation mismatch.

Required DataVault fields:
- BufferID
- SystemID
- element stride
- logical count
- capacity
- generation
- owner phase
- active producer JobHandle
- last validation frame

Evidence from Batch 004/005: repeated GlobalDataVault drift created compile walls, circular assembly pressure, and false data sovereignty claims. The fix is not another local native allocation. The fix is one vault, one owner, typed handles, and generation checks.

## SECTION 6: DELEGATE CACHING MANDATE

### 6.1 Lambda Allocation Problem

Anonymous lambdas and closures defined at call site allocate new delegate object on heap every time they are created. If they capture local variables or `this`, they also allocate closure object. In hot path, this is per-frame allocation.

//  FORBIDDEN - New delegate object allocated every frame
void Tick(float dt)
{
    _units.ForEach(u => u.Tick(dt));                    // lambda allocation
    _eventSystem.Subscribe("damage", (e) => Handle(e)); // allocation + potential closure
    StartCoroutine(DoWork());                            // Coroutine = iterator state machine = heap
}

### 6.2 Mandatory Delegate Caching Pattern

All delegates used in hot paths must be pre-allocated as instance fields and initialized in `Awake()`. delegate points to named method, not anonymous lambda.

public class CombatSystem : MonoBehaviour
{
    //  CORRECT - Delegate cached as field, allocated ONCE in Awake
    private Action<Unit> _cachedTickDelegate;
    private Predicate<Unit> _cachedIsEnemyPredicate;
    private Action _cachedOnDamageDelegate;

    private void Awake()
    {
        _cachedTickDelegate       = TickUnit;         // Named method - no allocation
        _cachedIsEnemyPredicate   = IsEnemyUnit;      // Named method - no allocation
        _cachedOnDamageDelegate   = OnDamageReceived; // Named method - no allocation
    }

    private void TickUnit(Unit u)       => u.Tick(Time.deltaTime);
    private bool IsEnemyUnit(Unit u)    => u.Faction == Faction.Enemy;
    private void OnDamageReceived()     { /* handler */ }

    private void Tick(float dt)
    {
        //  Using cached delegate - zero allocation
        _eventSystem.Subscribe(EventType.Damage, _cachedOnDamageDelegate);
    }
}

### 6.3 Coroutines in Hot Paths - BANNED

Unity Coroutines (`IEnumerator` / `yield return`) create iterator state machine objects on heap. They are permitted for initialization sequences and cinematic flows. They are banned for any logic that runs repeatedly in hot-path frame loop. Use explicit state machines implemented as `switch` statements or `enum`-driven update logic instead.

// X FORBIDDEN in hot paths
IEnumerator AttackSequence() {
    yield return new WaitForSeconds(0.5f); // Two allocations
    PerformAttack();
}

//  CORRECT - Explicit state machine, zero allocation
private enum AttackState { Idle, Windup, Strike, Recovery }
private AttackState _attackState;
private float _attackTimer;

private void Tick(float dt)
{
    switch (_attackState)
    {
        case AttackState.Windup:
            _attackTimer -= dt;
            if (_attackTimer <= 0f) { _attackState = AttackState.Strike; PerformAttack(); }
            break;
        // ...
    }
}

## SECTION 7: PHYSICS NON-ALLOC MANDATE

### 7.1 Allocating Physics APIs - BANNED

The following Unity Physics APIs return new arrays on every call. They are banned in `Tick`, `FixedTick`, and any per-frame code path:

//  BANNED - Allocates new RaycastHit[] every call
RaycastHit[] hits = Physics.RaycastAll(ray, maxDistance);

//  BANNED - Allocates new Collider[] every call
Collider[] nearby = Physics.OverlapSphere(position, radius);

//  BANNED - Allocates new Collider2D[] every call
Collider2D[] contacts = Physics2D.OverlapCircleAll(point, radius);

### 7.2 Mandatory NonAlloc Pattern

All physics queries must use `*NonAlloc` variants with pre-allocated static buffers.

public class WeaponSystem : MonoBehaviour
{
    //  Pre-allocated buffer - sized for maximum expected results
    // Static: shared across all instances of this system type
    // If per-instance isolation is needed, use instance field initialized in Awake
    private static readonly RaycastHit[] _raycastBuffer   = new RaycastHit[32];
    private static readonly Collider[]   _overlapBuffer   = new Collider[64];

    private void PerformRaycast(Vector3 origin, Vector3 direction, float range)
    {
        //  CORRECT - Writes into pre-allocated buffer, returns count only
        int hitCount = Physics.RaycastNonAlloc(origin, direction, _raycastBuffer, range, _layerMask);

        for (int i = 0; i < hitCount; i++)
        {
            ProcessHit(ref _raycastBuffer[i]);
        }
        // Buffer is NOT cleared - hitCount is valid window. Data beyond hitCount is stale but harmless.
    }

    private void PerformOverlap(Vector3 center, float radius)
    {
        int count = Physics.OverlapSphereNonAlloc(center, radius, _overlapBuffer, _layerMask);

        for (int i = 0; i < count; i++)
        {
            ProcessCollider(_overlapBuffer[i]);
        }
    }
}

### 7.3 Buffer Sizing Policy

- Size buffers for worst-case + 25% margin based on level design constraints.
- If `hitCount == bufferSize`, results are truncated. Log warning in development builds:

#if DEVELOPMENT_BUILD || UNITY_EDITOR
if (hitCount == _raycastBuffer.Length)
    Debug.LogWarning($"[WeaponSystem] RaycastNonAlloc buffer saturated ({hitCount}). Results truncated. Increase buffer size.");
#endif

| Allocating (BANNED) | NonAlloc Replacement (REQUIRED) |

## SECTION 8: STRUCTS vs. CLASSES - IDENTITY RULE

### 8.1 Governing Principle

> If data container does not require object identity, reference sharing, or inheritance, it MUST be `struct`.

"Object identity" means: two separate instances with identical data are meaningfully different objects that must be distinguished by reference, not by value.

### 8.2 Decision Flowchart

Does this type need to be passed by reference to maintain shared mutable state?
   YES -> Is class.
   NO
     Does this type need to be stored in Unity's component system (MonoBehaviour/ScriptableObject)?
        YES -> Must be class.
        NO
          Does this type need virtual dispatch / polymorphism at runtime?
             YES -> Consider class or interface + struct implementation.
             NO
               Does this type hold primarily data with logic that acts on that data?
                  YES -> MUST be struct.
                  NO -> Evaluate case by case, default to struct.

### 8.3 Mandatory Struct Candidates

The following categories must be implemented as structs on HECTON-8:

//  CORRECT - Pure data, no identity required
public struct DamageEvent
{
    public int     Amount;
    public Vector3 Origin;
    public byte    DamageTypeFlags;
}

public struct PhysicsState
{
    public Vector3 Position;
    public Vector3 Velocity;
    public float   AngularVelocity;
}

public struct BulletData
{
    public Vector3 Position;
    public Vector3 Direction;
    public float   Speed;
    public float   Lifetime;
    public int     OwnerID;
}

public struct AbilityParameters
{
    public float Range;
    public float Cooldown;
    public int   BaseDamage;
}

### 8.4 Struct Safety Rules

Structs eliminate heap allocation when used correctly. They become dangerous when misused:

| Rule | Reason |
|------|--------|
| Keep structs under 64 bytes total | Larger structs negate copy-efficiency benefits; split oversized data |
| Pass large structs with `ref` or `in` | Avoids per-call copy cost: `void Process(in BulletData b)` |
| Never store mutable structs in `readonly` fields | Compiler creates defensive copies, defeating purpose |
| Never box struct by assigning to interface | Defeats zero-allocation guarantee; use generic constraints instead |
| Structs stored in `List<T>` are safe | `List<T>` uses array internally; indexed access does not box |
| Structs behind `IMyInterface` are boxed | If interface dispatch is needed, type may need to be class |

//  BOXING - struct behind interface
IUpdateable updatable = new PhysicsState(); // Box allocation

//  NO BOXING - generic constraint
void Process<T>(ref T state) where T : struct, IPhysicsProcessable { ... }

## SECTION 9: EXECUTION POLICY - ENFORCEMENT MECHANISMS

### 9.1 Automated Enforcement

The following automated checks are part of CI/CD pipeline and will fail build:

- Roslyn Analyzer: `HectonGCAnalyzer` - Flags LINQ usage, `foreach` on Dictionary/Interface, `new` class in methods named `Tick` or `FixedTick`, and string interpolation in hot-path methods.
- Unity Memory Profiler Gate - Automated profiler sessions on reference hardware (MX350 target device) run nightly. Any session showing >0 bytes allocated in gameplay hot paths during 60-second stress scenario fails gate.
- PR Label Policy - Any PR touching files under `Runtime/Systems/` or `Runtime/Combat/` requires `gc-reviewed` label, which is applied by reviewer after confirming compliance.

### 9.2 Developer Verification Workflow

Before every PR touching hot-path code, author must:

1. Run Unity Profiler with Deep Profile OFF (Deep Profile itself allocates) - use standard profiler with allocation tracking enabled.
2. Enter Play Mode, navigate to gameplay scenario covered by change.
3. Open Memory Profiler -> GC Alloc column in Profiler window.
4. Confirm 0 bytes GC Alloc in `Tick` and `FixedTick` call stacks for minimum of 300 frames.
5. Screenshot profiler output and attach it to PR.

PRs without profiler screenshot for hot-path changes are auto-rejected.

### 9.3 Known Allocation Sites Registry

Some allocations are unavoidable (Unity engine internals, third-party SDKs, initialization paths). These must be documented. file `/Docs/KnownAllocationSites.md` tracks:

- What allocates
- Why it cannot be eliminated
- Which frame phase it occurs in
- Whose name is on waiver

This document requires CTO approval for each entry. It is not dumping ground for laziness.

## SECTION 12: SAFE - PERMITTED ALLOCATION ZONES

Not everything is hot path. These zones have relaxed allocation policies:

| Zone | Allocation Policy |
|------|------------------|
| `Awake()` / `Start()` | Unlimited - this is initialization |
| `OnEnable()` / `OnDisable()` | Permitted for registration logic only |
| Scene load / unload handlers | Unlimited |
| `#if UNITY_EDITOR` blocks | Unlimited |
| Debug logging guarded by `Debug.isDebugBuild` | Permitted |
| Cutscene / cinematic state (non-interactive) | Relaxed - document allocations |
| Asset loading callbacks | Unlimited |
| Network message deserialization | Isolated - must not touch gameplay state within same frame |

Everything else is hot path. Default to zero.
