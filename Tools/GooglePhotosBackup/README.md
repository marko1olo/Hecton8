# Инструкция по использованию скрипта бэкапа в Google Фото

Этот скрипт позволяет автоматически сканировать папку на вашем ПК и загружать медиафайлы (фотографии и видео) в Google Фото. Он умеет сохранять прогресс в локальную базу данных SQLite, поэтому если процесс прервется, его можно перезапустить, и он продолжит с места остановки без создания дубликатов.

---

## Шаг 1. Установка зависимостей (Python)

Для работы скрипта требуется **Python 3**.
Откройте терминал/PowerShell в папке `Tools/GooglePhotosBackup` и выполните установку библиотек:

```bash
pip install -r requirements.txt
```

---

## Шаг 2. Настройка доступа на стороне Google (Google Cloud)

Поскольку бэкап работает напрямую с вашим аккаунтом, вам нужно получить файл авторизации (`credentials.json`). Это бесплатная процедура:

1. Перейдите в консоль [Google Cloud Console](https://console.cloud.google.com/).
2. Создайте новый проект (кнопка вверху экрана **New Project**), назовите его, например, `Photos Local Backup`.
3. В строке поиска вверху найдите **Photos Library API** и нажмите кнопку **Enable** (Включить).
4. Настройте экран согласия (OAuth Consent Screen):
   - Перейдите в боковом меню: **APIs & Services** -> **OAuth consent screen**.
   - Выберите тип пользователя: **External** (Внешний) и нажмите **Create**.
   - Заполните обязательные поля:
     - **App name**: `Local Backup Tool`
     - **User support email**: ваш email.
     - **Developer contact information**: ваш email.
   - Нажмите **Save and Continue**.
   - В разделе **Scopes** (Разрешения) нажмите **Add or Remove Scopes**, добавьте вручную этот scope (разрешение):
     `https://www.googleapis.com/auth/photoslibrary`
     *(если Photos Library API уже включен в проекте, этот scope появится в списке)*.
   - **ВАЖНЫЙ ШАГ (Test Users)**: На шаге **Test users** нажмите кнопку **Add Users** и введите **свою Google почту** (куда вы будете загружать фотографии). Без этого Google заблокирует авторизацию.
   - Сохраните и завершите настройку.
5. Получите ключи (Credentials):
   - Перейдите в боковом меню: **APIs & Services** -> **Credentials**.
   - Нажмите **+ Create Credentials** -> **OAuth client ID**.
   - В поле **Application type** выберите **Desktop app** (Приложение для компьютера).
   - Задайте имя (например, `Backup Client`) и нажмите **Create**.
   - Появится окно с подтверждением. Нажмите кнопку **Download JSON** в этом окне.
6. Переименуйте скачанный файл в `credentials.json` и положите его в папку со скриптом (`Tools/GooglePhotosBackup/`).

## Шаг 3. Использование скрипта

### 1. Обычный запуск (загрузка папки)
По умолчанию скрипт ищет файлы `.jpg, .jpeg, .png, .gif, .webp, .mp4, .mov`.
```bash
python backup.py --src-dir "C:\Путь\К\Вашим\Картинкам"
```

### 2. Загрузка в конкретный альбом Google Фото
Если вы хотите, чтобы фотографии автоматически добавлялись в определенный альбом (если его нет, скрипт создаст его сам):
```bash
python backup.py --src-dir "C:\Путь\К\Вашим\Картинкам" --album "Бэкап с ПК"
```

### 3. Изменение типов файлов
Если нужно загрузить только определенные форматы:
```bash
python backup.py --src-dir "C:\Путь\К\Вашим\Картинкам" --types ".jpg,.png"
```

## Первая авторизация

При первом запуске скрипта откроется окно браузера с просьбой войти в ваш Google аккаунт:
1. Выберите тот аккаунт, почту которого вы указали в **Test Users** на шаге настройки OAuth.
2. Google покажет предупреждение: *"Google hasn't verified this app"* (это нормально, так как приложение создали вы сами для личного использования).
3. Нажмите **Advanced** (Дополнительно) -> **Go to Local Backup Tool (unsafe)**.
4. Разрешите доступ к вашей библиотеке Google Фото.
5. После успешного входа в браузере появится надпись *"The authentication flow has completed..."*, вкладку можно закрыть.
6. В папке скрипта автоматически создастся файл `token.json` — он будет использоваться для последующих автоматических запусков без необходимости открывать браузер.

## Как это работает?

* **База данных (`backup_state.db`)**: Скрипт сканирует папку и сохраняет пути файлов, размер и дату изменения в базу данных. 
  * Статус `uploaded` означает, что файл уже успешно загружен. Скрипт его пропустит.
  * Если файл изменился на диске (дата изменения или размер обновились), статус сбросится на `pending`, и он загрузится заново.
  * Если вы прервали выполнение скрипта (нажав `Ctrl+C`), при повторном запуске он просто продолжит работу.
* **Логи (`backup.log`)**: Вся детальная информация сохраняется в текстовый файл `backup.log` в папке скрипта для отладки ошибок.
