Executive verdict:

2. Floating origin is not atomic. `HectonFloatingOrigin.ShiftWorld()` bulk-mutates scene root transforms, syncs physics, and only then informs listeners. Async voxel generation and geology seam systems are not visibly shift-aware.
3. Inventory flows contain real item-loss paths. Pickup deactivates itself before inventory success is guaranteed. PDA drop removes inventory state before validating spawn prerequisites.
4. The player-force stack is too wide. Tow, snap release, grapple, entanglement, currents, thermal flow, wipeout, and hull-stress modifiers all converge in the same movement owner with no single kinetic budget governor.
5. MX350 protection is fragmented. Documentation defines an emergency ladder, but runtime ownership is split between separate monitors/controllers with no single authoritative sacrifice order.

System Collision Analysis
1. [KRAKEN][ACTIVE] Floating-origin mid-bake split: voxel density uses `ShiftAtStart`, welded mesh build uses the same old offset, and only the spawned root is compensated with `currentShift`. Any origin shift during bake can produce geometry derived from one coordinate frame and placed in another (`HectonVoxelEngine.cs:2427-2494`, `2993`, `3741-3749`).
2. [KRAKEN][ACTIVE] Floating origin is not atomic: `ShiftWorld()` mutates every root transform first, then calls `Physics.SyncTransforms()`, then emits `OnWorldShift`. Systems that rely on event-based compensation are already one phase late (`HectonFloatingOrigin.cs:154-185`).
3. [RED][ACTIVE] Physics broadphase sees a rewritten world before all rebase listeners finish. This is the exact setup for one-frame false penetration, false clearance, or stale sweep outcomes during transport/tow movement (`HectonFloatingOrigin.cs:174-182`).
4. [RED][ACTIVE] Vegetation is shift-aware; voxel and geology seam systems are not visibly shift-aware. That means surface dressing, voxel caves, and seam repair can disagree after the same origin shift (`HectonMapMagicVegetationBridge.cs:10713-10733`; no matching shift handler found in voxel/geology owners).
5. [RED][ACTIVE] Terrain seam application resolves terrain by world XZ and falls back to `Terrain.activeTerrain` / `Terrain.activeTerrains`. If seam plans are stale across an origin shift or slow-tick boundary, the wrong terrain tile can be modified (`WorldGenerativeGeologyTerrainSeamApplier.cs:87`, `477-499`).
6. [RED][ACTIVE] Seam runtime visuals are cubes and cylinders, not actual matched terrain-voxel topology. That makes seam collision/clearance a proxy, not truth, and proxy geometry is what cables and hulls will collide against in stress cases (`WorldGenerativeGeologySeamExecutionDirector.cs:335`, `372-403`).
7. [RED][ACTIVE] `GetOrCreateSeamRuntime()` parents seam runtime under the host transform. If host transform rebases but seam plan data is old-frame, local and world seam coordinates diverge silently (`WorldGenerativeGeologySeamExecutionDirector.cs:319`, `447-473`).
8. [RED][LATENT] `OnWorldShift` is a static event and is explicitly nulled on teardown. A shift coinciding with scene teardown/load can drop listeners and strand runtime owners in pre-shift coordinates (`HectonFloatingOrigin.cs:45`, `117`).
9. [RED][ACTIVE] The geology seam system reconciles in `SlowTick` cadence, not at the same phase as origin shift or voxel bake completion. This increases stale-plan windows exactly where the mandates demand shift-safe seam data (`WorldGenerativeGeologyTerrainSeamApplier.cs:50`, `62`, `79`, `87`).
10. [RED][LATENT] `PickupItem` persistence identity caches `transform.position` as the world-state anchor. Floating-origin rebases change world coordinates; if identity resolves before or after shift on different runs, pickup persistence can desync (`PickupItem.cs:264-279`).
11. [RED][ACTIVE] Transport-local movement keeps buffered collision and environmental force queues, but no shift-specific queue flush was found. A world shift can rebase transforms while queued forces still describe the old frame (`HectonPlayerMovement.cs:1139-1141`, `1511-1537`, `1584-1609`, `3261-3295`).
12. [RED][LATENT] `HectonVoxelVolume` has queued rebuild processing, but no visible shift invalidation or shift epoch. Runtime volume rebuilds can replay obsolete spatial assumptions after an origin move (`HectonVoxelVolume.cs:468-487`).
13. [RED][LATENT] MapMagic detail tasks can be active or enqueued while world data is changing. Vegetation bridge rebases chunk data, but no evidence was found that all upstream terrain/seam producers are blocked during shift (`MapMagicBridge.cs:1246`; `World/HectonMapMagicVegetationBridge.cs:4633-4646`).
14. [RED][ACTIVE] The exact scenario requested by QA is already structurally unsafe: moving transport plus async voxel bake plus origin shift relies on multiple subsystems sharing one coordinate truth, but only some of them rebase explicitly.

Physics Abuse Scenarios
15. [KRAKEN][ACTIVE] Tow pathing uses at most one bend point from a single line-of-sight test. In a winding cave or voxel tunnel, the solver underestimates real cable path length and can inject acceleration into the player/payload pair (`HeavyTowWinch.cs:530`, `557-615`).
16. [KRAKEN][ACTIVE] The cable solver applies equivalent capped acceleration logic to both player and payload. If the payload arrests on geometry while the player still receives release energy, the system becomes a slingshot (`HeavyTowWinch.cs:456-505`, `675-705`).
17. [RED][ACTIVE] External snare force is applied on top of the core tow solve instead of arbitrated through one constraint owner. Multi-source pull means the stress model is not the same as the force model (`HeavyTowWinch.cs:438`, `647-661`).
18. [RED][ACTIVE] Catastrophic tow release injects an explicit velocity change and trauma impulse into player movement. This is a designed momentum spike, so any collision tolerance, seam gap, or tunnel wedge at that frame becomes a catapult opportunity (`HeavyTowWinch.cs:743-760`; `HectonPlayerMovement.cs:1359-1376`).
19. [RED][ACTIVE] Player movement already stacks grapples, sargassum entanglement, abyssal cable entanglement, currents, turbulence, thermal updrafts, undertow, and tow snap responses. No single kinetic budget or priority arbiter was found (`HectonPlayerMovement.cs:2878-3181`, `4736-5143`, `6978-7211`).
20. [RED][ACTIVE] Collision intake is capped to an 8-entry ring buffer. High-speed slingshot impact storms can overflow the queue and drop collision evidence, damage, or feedback ordering (`HectonPlayerMovement.cs:1139-1141`, `3276-3295`).
21. [RED][ACTIVE] Massive wreck into 1-voxel tunnel has no swept-volume occupancy gate, no wedge detector, and no "abort tow" state when the payload width exceeds tunnel width. Expect jitter pumping, solver explosion, or hard lock.
22. [RED][ACTIVE] Seam collars and skirts are primitive proxies, not true contact geometry. A cable can believe it has clearance where the real tunnel is blocked, or believe it is blocked by a proxy that has no matching physical corridor (`WorldGenerativeGeologySeamExecutionDirector.cs:372-403`).
23. [RED][ACTIVE] Snap timing is hold-based, not energy-based. Oscillating around `tetherSnapExtensionThreshold` can repeatedly arm and clear the hold timer, creating "near break" states players can probe for momentum ratchets (`HeavyTowWinch.cs:732-748`).
24. [RED][ACTIVE] `maxCableForce` is a scalar cap, not an energy budget. In narrow-space collisions, the system can keep shoving every fixed step until geometry, not design intent, decides the result (`HeavyTowWinch.cs:56`, `487-497`).
25. [RED][ACTIVE] Player entanglement forces are transport-aware because propulsion reference scales the resistance model. That means transport states can amplify constraint behavior instead of safely containing it (`HectonPlayerMovement.cs:2691-2694`, `2896`, `2946`).
26. [RED][ACTIVE] `ClampVelocity()` is late in the movement pipeline, after transport bailout and multiple environment/tow modifiers have already executed. That contains end-of-step speed, not intermediate collision severity (`HectonPlayerMovement.cs:4378-4440`, `7510`).
27. [RED][ACTIVE] Transport bailout can trigger while fatal pressure sequence or wipeout timers are near activation. This creates stacked fail states rather than one readable fail state (`HectonPlayerMovement.cs:5051`, `5158-5182`).
28. [RED][ACTIVE] Hull stress uses vertical speed and depth rate, so a tow-catapult downward or upward can spike pressure drama independent of actual depth-gate fairness (`HectonPlayerMovement.cs:5018-5025`).
29. [AMBER][LATENT] Moving transport changes collision radius/height/center via preset. Cable path resolution does not appear to account for these live collision-shape changes before force solve (`HectonPlayerMovement.cs:2339-2388`).
30. [RED][ACTIVE] The requested Mach-1 question resolves to "yes, under exploit conditions." The code contains force caps and a late velocity clamp, but no global kinetic-energy budget, no tunnel wedging detector, and a deliberate snap-release velocity injection.

Exploit Prevention And Depth-Gating Loopholes
51. [KRAKEN][ACTIVE] Hard exploit confirmed: `TransportPreset_MicroSub.asset` sets `pressureDamageScale: 0`. `HectonSurvivalSystem.ApplyPressureDamage()` exits immediately when `pressureDamageScale <= 0f` (`TransportPreset_MicroSub.asset:39`; `HectonSurvivalSystem.cs:446-452`).
52. [KRAKEN][ACTIVE] The same zero scale also zeroes live pressure telemetry through `ResolveCurrentPressureDamagePerSecond()`. The player is not just protected; the danger meter itself is falsified (`HectonSurvivalSystem.cs:1328-1338`).
53. [KRAKEN][ACTIVE] Depth-zone gating is warning-only. `DepthZoneDirector.CheckHullWarning()` compares hull tier and then only calls `NotificationEvents.PushWarning(...)` (`DepthZoneDirector.cs:219-229`).
54. [RED][ACTIVE] `requiredHullTier` therefore has no hard enforcement path. A player can knowingly or unknowingly enter forbidden depth with only UI text as resistance (`DepthZoneDirector.cs:226-229`; `DepthZone_TheDropUpper.asset:37`; `DepthZone_DeepAbyss.asset:38`; `DepthZone_ThermalFields.asset:39`).
55. [RED][ACTIVE] Hull-stress math and survival pressure math disagree. `UpdateHullStress()` floors transport protection to `0.1`, while survival damage honors raw zero. The player can see stress drama while taking no real pressure damage (`HectonPlayerMovement.cs:5001-5025`; `HectonSurvivalSystem.cs:451-452`).
56. [RED][ACTIVE] Because transport safe-depth bonuses and pressure scaling are separate, a transport can simultaneously extend the safe envelope and nullify damage. That is a progression skip if the asset author is careless (`HectonSurvivalSystem.cs:704-723`).
57. [RED][ACTIVE] External systems can request hull stress directly via `RequestExternalHullStress()`. Hull UI is therefore not a trustworthy indicator of depth rule violation, which makes exploit scouting easier (`HectonPlayerMovement.cs:1448-1457`, `1584-1609`; `SargassumMicroFaunaBoids.cs:2427-2431`).
58. [RED][ACTIVE] One-time hull warning behavior is abusable. Once `_hullWarningShown` is set, the system stops escalating that specific warning and the player re-enters with less friction (`DepthZoneDirector.cs:219-229`).
59. [RED][ACTIVE] `WorldReadabilityDirector` amplifies the problem by converting depth danger into more queueable advisory text. Once the player notices text does not equal enforcement, the whole readability layer becomes bluff (`WorldReadabilityDirector.cs:290-325`, `492-529`).
60. [RED][LATENT] Any future transport preset with `pressureDamageScale <= 0` or an oversized safe-depth bonus will instantly become another bypass because no asset-validation guard was found in this review (`PlayerTransportPreset.cs:293`; `HectonSurvivalSystem.cs:719-723`).
61. [AMBER][LATENT] Depth zones are discrete authored assets, while overpressure is continuous depth. Cave shortcuts, untagged shafts, or seam-created detours can move the player into deep space without crossing the intended narrative gate first.
62. [RED][ACTIVE] Combined optimal exploit route: stay mounted in MicroSub, ignore warning-only hull tier messages, bypass pressure damage entirely, and use the slow/noisy inventory flow as justification to avoid dismounting. That collapses both progression and intended horror cadence.

Emergency load-shedding triggers the runtime should enforce, not merely document:
1. Trigger A: if smoothed frame time exceeds 20 ms for 8 consecutive frames, suspend non-critical readability spam, subtitle waveform animation, and far-field boid simulation cadence. Reason: buy CPU before the player feels a hard hitch.
2. Trigger B: if frame time exceeds 25 ms for 3 consecutive frames, enforce the documented MX350 ladder immediately: disable flora vertex animation, cut GPU boids by 50 percent, activate `_QUALITY_MX350`, disable Bloom/DoF/Vignette, force volumetric fog half-res (`Docs/SYSTEMS_CONTRACTS.md:113-117`).
3. Trigger C: at Trigger B, also stop launching new voxel caves and defer seam reconcile work until frame pressure recovers. Generation under pressure is optional; missed frame budget is not.
4. Trigger D: if `VRAMMonitor.PressureState == Critical` for two samples, drain non-essential RT pools, cut boids to 25 percent, and disable seam proxy visuals outside the player threat radius. Texture/RT collapse on MX350 will not be fixed by render-scale alone.
5. Trigger E: if cave/terrain async queues back up while frame pressure is non-stable, freeze queue growth and drop low-priority launches. Backlog plus pressure equals guaranteed hitch debt.

Regression model:
CPU: highest risk in async voxel launch, seam reconcile, boid compute/readback, and wide player-force arbitration.
GC: this report does not claim GC regressions or improvements because no runtime changes were performed. Measured proof absent.
Memory: highest risk in boid buffers, RT pressure, and seam/cave overlap zones where geometry and effects stack.
Cadence: main failure pattern is cross-phase desync. Shift, slow-tick seam repair, async voxel bake, and fixed-step movement do not share one synchronization barrier.
Correctness: current correctness risk is not isolated bugs; it is ownership overlap between world-shift, world-generation, transport physics, and UI warning systems.

Hot path impact:
1. Player movement is the highest-risk hot path because it aggregates transport, entanglement, currents, hull stress, bailout, and clamp logic in one owner.
2. Tow solve is the second highest-risk hot path because it creates artificial acceleration and snap events under cave/tunnel constraints.
3. Boid simulation is the highest GPU-side hot path because it scales with swarm count and mode complexity, not just camera visibility.

Failure modes:
1. False clearance: cable or transport fits through a proxy seam that the true geometry would block.
2. False blockage: seam proxy or rebased collider blocks a corridor that should be traversable.
3. Ghost collision: physics sees post-shift transforms while generation/seam systems are pre-shift.
4. Silent progression bypass: player survives forbidden depth because data and gating disagree.
5. Silent item loss: pickup/drop removes world or inventory state before success is guaranteed.
6. Warning burial: critical alerts are pushed out by lower-value guidance traffic.
7. Pressure camouflage: hull-stress feedback exists while actual pressure damage is zero.
8. Hardware brownout: frame time collapse begins in generation/compute, but mitigation reacts too late or cuts the wrong systems first.
