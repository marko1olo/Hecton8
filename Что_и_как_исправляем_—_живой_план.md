## Что не делать сейчас

### Не топтаться в reload-cleanup
- Не продолжать бесконечную серию микро-фиксов editor hooks.
- Причина:
- safe-польза почти выжата
- дальше растёт риск ковыряния protected visual workflow и vendor core

### Не уводить песочницу в рельсы
- Удалён/ослаблен прошлый уклон в `corridor / primary route / expedition loop` мышление.
- Держим принцип:
- мир должен тянуть игрока нуждой, памятью места, сюжетом, риском и наградой
- а не ощущением “правильного маршрута”

### Не трогать без особой причины

## Биомы: честная реальность на сейчас

### Что уже есть
- В проекте реально есть большой biome data-layer:
- `BiomeMatrixDirector`
- `HectonBiomeMatrixCatalog`
- `HectonBiomeMatrixProfile`
- `HectonBiomeFamilyProfile`
- `HectonBiomeResourcePlanProfile`
- family profiles
- resource plans
- landmark guidance
- atmosphere / fauna / reward hooks
- На диске сейчас:
- `216` biome matrix profile assets
- `26` biome family profile assets
- `18` world zone plan assets
- `20` world content profile assets

### Что это значит по-честному
- Биомы уже умеют:
- определять текущий biome slot по глубине и региону
- давать family / mood / resource / landmark / threat diagnostics
- влиять на world population selection
- влиять на zone diagnostics и content recommendations

### Чего ещё нет
- Это ещё не полноценный визуально и геймплейно разведённый подводный мир.
- Пока не хватает:
- реального live world fill по biome families
- реальных resource pockets / salvage / hazards в большом масштабе
- cave ↔ biome ↔ MapMagic связки
- live boid/fauna population в мире как части биомов
- map graph masks и terrain-family refactor для 5-biome enterprise graph
- заполнения placeholder biome gaps содержанием, а не только названиями и профилями

### Ключевой вывод
- Биомы у нас уже не бумажные.
- Но они пока больше “мозг и паспорт мира”, чем “сам живой подводный мир”.
- Следующий смысловой шаг:
- не плодить новые biome asset-классы
- а заставить biome layer реально размещать и объяснять:
- где что искать
- где что бояться
- где что запоминать
- где зачем возвращаться

### Направление 2: Live world fill
- Поднимать не только data-layer, а реальный контентный слой:
- salvage pockets
- service scars
- power routes
- relay canyons
- biolum pockets
- abyss edges
- colony ruins

### Что уже стартовало по этому направлению
- Под procedural world fill уже заложен enterprise foundation:
- расширенные `WorldPrefabFamilyProfile`
- `WorldProceduralPlacementRule`
- authoring tool для family/rule assets
- генерация proxy prefab library
- scene builder для proxy instances от `WorldContentSocket`
- Это уже не “идея на потом”, а реальный каркас первой важности.
- Новый факт:
- procedural fill уже поднят как runtime manager, а не только authoring tooling
- `WorldProceduralFillDirector` сидит в `[MANAGERS]`
- world bootstrap автоматически подхватывает procedural families и procedural rules
- `WorldContentSocket` уже хранит resolved procedural diagnostics
- `WorldContentDirector` уже показывает nearest procedural read
- proxy scene реально собирается в `__PROCEDURAL_PROXY_WORLD`
- в текущей сцене уже найдено `157` proxy instances
- новый факт:
- поднят `WorldProceduralFieldSampler`
- поднят `WorldProceduralScatterDirector`
- добавлено меню `Hecton/Authoring/Rebuild Procedural Scatter Preview`
- теперь procedural world fill умеет строиться не только от заранее размеченных sockets, но и от самой местности вокруг игрока
- в текущей сцене уже существует `__PROCEDURAL_SCATTER_WORLD`
- после rebuild scatter preview в сцене уже появились новые field-driven proxy instances
- честный технический нюанс:
- в editor-preview `MapMagicBridge` не всегда отдаёт высоту terrain в этой сцене
- поэтому sampler сейчас работает так:
- сначала пробует MapMagic height
- потом raycast по миру
- потом синтетическое preview-дно под водой
- это не финальный runtime-режим мира, а полезный authoring fallback

### Направление 3: Live wiring уже существующих систем
