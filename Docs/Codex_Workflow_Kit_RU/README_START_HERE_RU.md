# Codex Workflow Kit

Это переносимый набор инструкций для людей, которые хотят заставить Codex работать как автономный технический оператор: читать локальные правила проекта, управлять окнами/браузером/Unity или другим редактором, запускать проверки, делать реальные артефакты, а не писать пустые отчеты.

Это не HECTON-8 документация. Не надо отдавать друзьям все файлы чужого проекта. У них должны быть свои проектные правила и свои референсы. Этот kit объясняет схему.

## Что Отдать Codex В Любом Проекте

Минимальный набор в корне проекта:

- `AGENTS.md` - главные правила для Codex.
- `TASTE.md` или `PRODUCT_TASTE.md` - что считается хорошим результатом.
- `VISION_LOCKS.md` или `PRODUCT_LOCKS.md` - решения владельца проекта, которые нельзя переинтерпретировать.
- `PROJECT_BIBLES.md` или `DOCS_INDEX.md` - карта важных документов.
- Доменные документы: `graphics.md`, `gameplay.md`, `ui.md`, `audio.md`, `performance.md`, `lore.md`, `marketing.md` и т.п.
- Папка `Docs/Reports/` или аналог - только для реальных отчетов, если они нужны.
- Папка `Docs/Screenshots/` или аналог - для proof screenshots, чтобы не провоцировать import/rebuild loops.

Не надо давать Codex огромную свалку файлов без маршрута. Надо дать ему карту: какие документы читать для какой задачи.

## Главный Принцип

Codex должен не "планировать работу", а реально делать:

- читать только релевантные документы;
- править файлы;
- запускать проверки;
- смотреть скриншоты;
- управлять GUI, если это часть задачи;
- фиксировать, что доказано, а что пока только гипотеза;
- не заявлять успех без proof.

## Структура Этого Kit

- `01_CODEX_PROJECT_RULES_TEMPLATE_RU.md` - шаблон правил проекта.
- `02_CODEX_OPERATOR_PROMPT_RU.md` - prompt, который можно вставить Codex.
- `03_MANUAL_ORCHESTRATION_PROMPT_RU.md` - prompt для оркестрации нескольких агентов.
- `04_GEMINI_IMAGE_ASSET_WORKFLOW_RU.md` - как вручную генерировать картинки/текстуры через Gemini в браузере.
- `05_IMAGE_PROMPT_TEMPLATES_EN.md` - английские templates для image/texture prompts.
- `06_PROOF_AND_REPORTING_RULES_RU.md` - как требовать доказательства и не принимать фейковые отчеты.
- `07_WHAT_TO_ATTACH_TO_FRIENDS_RU.md` - что реально скидывать людям, а что не надо.

## Быстрый Старт

1. В своем проекте создайте `AGENTS.md` по шаблону.
2. Создайте `TASTE.md` или краткий документ с визуальным/продуктовым стандартом.
3. Дайте Codex prompt из `02_CODEX_OPERATOR_PROMPT_RU.md`.
4. Если надо много параллельной работы, используйте `03_MANUAL_ORCHESTRATION_PROMPT_RU.md`.
5. Если нужны картинки/текстуры, используйте `04_GEMINI_IMAGE_ASSET_WORKFLOW_RU.md` и prompts из `05_IMAGE_PROMPT_TEMPLATES_EN.md`.
