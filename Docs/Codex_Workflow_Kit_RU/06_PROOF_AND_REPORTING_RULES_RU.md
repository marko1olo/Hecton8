# Proof And Reporting Rules

Codex часто пишет уверенно. Это не значит, что работа сделана.

## Что Считать Proof

Для кода:

- тесты прошли;
- билд/компиляция прошли;
- ошибка воспроизведена и исчезла;
- измененный путь реально выполнен.

Для GUI/UI:

- есть screenshot до/после;
- видны нужные элементы;
- нет перекрытия/обрезания;
- workflow пройден руками или автоматизацией.

Для визуала:

- screenshot из редактора/game view;
- сравнение с референсом;
- критика проблем;
- повторная проверка после исправления.

Для asset generation:

- файл скачан;
- путь указан;
- дубликаты удалены;
- tileability/preview проверены;
- asset импортирован и назначен, если заявляется "в игре".

## Что Не Считать Proof

- "Я подготовил план".
- "Должно работать".
- "Выглядит приемлемо" без скриншота.
- "Сгенерировал ассет", если файл не найден.
- "Интегрировано", если файл лежит только в Downloads.
- "Оптимизировано", если нет профиля/измерений или хотя бы разумной проверки.

## Формат Хорошего Отчета

```text
Сделано:
- [конкретный файл/сцена/asset]

Проверено:
- [команда/скриншот/тест/ручной workflow]

Не проверено:
- [что осталось без proof]

Проблемы:
- [реальные блокеры]

Следующий шаг:
- [один-два практических шага]
```

## Как Ругать Codex Правильно

Плохо:

```text
Сделай нормально.
```

Лучше:

```text
Не принимай результат без proof.
Если это визуальная задача, сделай screenshot и сравни с reference.
Если это код, запусти тест/билд или объясни, почему сейчас нельзя.
В отчете раздели реальные изменения, проверки, непроверенное и блокеры.
```
