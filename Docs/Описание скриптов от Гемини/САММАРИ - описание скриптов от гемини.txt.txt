ТЕХНИЧЕСКИЙ ДОКУМЕНТ: HECTON-8 — ПОЛНЫЙ РАЗБОР КОДОВОЙ БАЗЫ
РАЗДЕЛ 1: CORE & MEMORY MANAGEMENT (Ядро и управление памятью)
ITickable.cs / ISlowTickable.cs
Что это: Интерфейсы-контракты. Любой класс, который хочет получать обновления каждый кадр, обязан реализовать ITickable (метод Tick(float dt)). Для редких обновлений (2 раза в секунду) — ISlowTickable (метод SlowTick(float dt)).

Зачем нужно: Полная замена MonoBehaviour.Update(). Unity вызывает Update через слой C++ -> C# маршаллинга, что стоит порядка 500 наносекунд на объект. Прямой вызов интерфейса через цикл for стоит около 5 наносекунд. При тысячах активных объектов разница критична.

Как работает: Классы регистрируются в GameTickManager при старте и отписываются при уничтожении. Никакого Reflection, никаких накладных расходов Unity.

GameTickManager.cs
Что это: Центральный диспетчер всех игровых обновлений. Единственный MonoBehaviour в системе, у которого есть Update().

Внутреннее устройство:

Использует вложенный класс TickList<T> — буферизованную коллекцию с методами BeginIteration() и EndIteration().
При добавлении или удалении объектов во время итерации изменения складываются во временные буферы _toAdd и _toRemove. Применяются только после завершения текущего прохода.
Это исключает InvalidOperationException при уничтожении объекта внутри его собственного Tick.
Производительность: Обход коллекции через for (int i = 0; i < _tickList.Count; i++) вместо foreach исключает выделение объекта-перечислителя (Enumerator) в куче.

SlowTick: Вызывается через внутренний таймер (~0.5 сек). Используется для систем ИИ, жизнеобеспечения и биомного анализа — там, где точность до кадра не нужна, но регулярность важна.

ObjectPoolManager.cs / IPoolable.cs
Что это: Глобальный пул объектов. Заменяет Instantiate и Destroy для всех игровых сущностей.

Устройство:

Хранит Dictionary<int, Queue<GameObject>>, где ключ — стабильный ID префаба из PrefabRegistry.
При запросе объекта: берет из Queue, вызывает SetActive(true), вызывает IPoolable.OnSpawn().
При возврате: вызывает IPoolable.OnDespawn(), SetActive(false), меняет родителя на контейнер пула, кладет в очередь.
Warmup (Прогрев): На старте сцены SceneBootstrap вызывает Warmup(prefab, count). Создает count копий объекта заранее, чтобы первый спавн не вызвал задержку. Прогрев выполняется порциями через await Awaitable.NextFrameAsync(), не блокируя экран загрузки.

DespawnTimer: Вложенный класс, реализующий ITickable. Регистрируется в GameTickManager только когда запущен. В режиме простоя не потребляет ресурсов. Используется для эффектов, снарядов и файеров.

PrefabRegistry.cs / RuntimeInstanceId.cs
Что это: Система стабильных идентификаторов для всех инстансов игровых объектов.

Проблема которую решает: GameObject.GetInstanceID() в Unity 6 не гарантирует стабильность между сессиями и не пригоден для использования в многопоточных Job-ах (доступ к Unity API из потока запрещен).

Решение:

RuntimeInstanceId — структура (struct) из 64 бит: старшие 32 бита — ID префаба из реестра, младшие 32 — порядковый номер инстанса (Sequence).
ID генерируется детерминированно на основе хэша мировых координат объекта.
Используется в системе сохранений для идентификации конкретных заспавненных объектов.
Передается в Job-ы без ограничений, так как является чистой структурой данных.
RaycastBatchHelper.cs / QueryCacheContext.cs
Что это: Система пакетной обработки физических запросов (Raycasts).

Проблема: Каждый инструмент, ИИ-агент и камера независимо пускают лучи в Physics. При сотнях объектов это тысячи синхронных вызовов на Main Thread, каждый из которых блокирует выполнение.

Решение:

Объекты регистрируют запросы (RaycastRequest) в RaycastBatchHelper вместо прямого вызова Physics.Raycast.
В конце кадра все запросы пакуются в NativeArray<RaycastCommand> и отправляются в RaycastCommand.ScheduleBatch — асинхронный Job на свободных ядрах CPU.
Результаты (NativeArray<RaycastHit>) доступны в следующем кадре.
QueryCacheContext: Кэширует результаты лучей в пределах одного кадра. Если два разных скрипта пускают луч в одном направлении из одной точки в одном кадре — физика считается только один раз.

HectonFloatingOrigin.cs
Что это: Защита от потери точности чисел с плавающей запятой (float) в огромных мирах.

Проблема: float имеет точность около 7 значащих цифр. На расстоянии 10 000 метров от нуля объекты начинают дрожать (Floating Point Jitter) из-за потери точности в дробной части координат.

Решение: Скрипт отслеживает позицию игрока. Когда она превышает порог (1000 метров от мирового нуля), все корневые объекты сцены сдвигаются обратно к нулю на величину смещения игрока. Игрок возвращается в начало координат, мир перемещается вместе с ним. Визуально ничего не меняется.

Интеграция: Уведомляет все системы (физику, камеры, Job-ы) о смещении через событие OnOriginShifted, чтобы те скорректировали свои внутренние координаты.

PerformanceMonitor.cs / RuntimeDiagnosticsTrace.cs
Что это: Встроенная система профилирования, работающая в финальном билде.

Механика:

PerformanceMonitor использует ProfilerRecorder для чтения нативных метрик Unity без накладных расходов: время кадра на CPU, аллокации GC за кадр, количество батчей и SetPass вызовов.
Данные усредняются по скользящему окну (последние N кадров).
RuntimeDiagnosticsTrace: При обнаружении аномалии (просадка FPS, GC Spike) пишет детализированный лог в файл сессии. Запись выполняется через StreamWriter на фоновом потоке, чтобы не добавлять задержку на Main Thread.

StringBuilderPool.cs
Что это: Пул объектов StringBuilder для формирования строк без аллокаций.

Устройство: Stack<StringBuilder>. При запросе — берет из стека или создает новый. При возврате — вызывает sb.Clear() и кладет обратно.

Где используется: В каждом UI-скрипте, который обновляет текст (HUD, панели PDA, оверлеи строительства). Исключает создание промежуточных строк при конкатенации.

ZeroGCStringCache.cs
Что это: Кэш для операций над строками, которые обычно создают мусор.

Конкретная задача: Кэширует результат string.ToUpperInvariant(). Нормальный вызов этого метода создает новую строку в куче каждый раз.

Устройство: Массив на 16 слотов с простой хэш-функцией (& 0xF). Хэш считается от исходной строки, результат кладется в соответствующий слот.

Ограничение: При более чем 16 разных входных строках начинаются коллизии и перезапись кэша. Эффективен только для небольшого фиксированного словаря строк (названия инструментов, биомов, команды HUD).

EntityChangeDetector.cs
Что это: Система детектирования изменений состояния сущностей на основе битовых масок.

Проблема которую решает: Классический подход — каждую систему проверяет каждую переменную каждый кадр (поллинг). Это расточительно.

Решение:

Каждая система, изменяющая состояние (здоровье, позиция, инвентарь), вызывает MarkDirty(EntityChangeFlag.Health).
EntityChangeFlag — это [Flags] enum (битовая маска).
В конце кадра FlushChanges() проверяет маску и рассылает события только по тем каналам, которые были помечены как грязные.
Подписчики получают уведомление и перерисовывают только нужные части UI или пересчитывают только нужные данные.
РАЗДЕЛ 2: PHYSICS & FLUID DYNAMICS (Физика и вода)
HectonFluidEngine.cs
Что это: Центральная система расчета водной физики для всех объектов в сцене одновременно.

Пайплайн:

Собирает данные всех зарегистрированных BuoyancyObject в NativeArray<BuoyancyParams> (позиция, скорость, плотность, объем).
Передает массив в BuoyancyJob (Burst Compiled, IJobParallelFor).
Job параллельно на всех ядрах CPU вычисляет: силу Архимеда, вязкое сопротивление (Drag), влияние глобальных течений.
Результаты (NativeArray<BuoyancyResult>) применяются обратно через Rigidbody.AddForce() на Main Thread.
LOD физики: Объекты за пределами заданного радиуса от игрока обсчитываются реже или полностью замораживаются (Rigidbody.isKinematic = true).

Сухие зоны: Параметр isInAir в BuoyancyParams выставляется модулями базы. Если объект внутри базы — Job пропускает расчет водных сил для него.

BuoyancyObject.cs / BuoyancyProfile.cs
Что это: Компонент, вешаемый на любой физический объект, который должен плавать.

BuoyancyProfile: ScriptableObject с параметрами: плотность материала, объем тела, высота центра вытеснения воды. Разделение данных и логики.

Ground Check: Объект периодически пускает луч вниз для определения контакта с дном. Проверка не выполняется каждый кадр — объекты распределены по времени (staggered), чтобы не было пика нагрузки.

Интеграция с базой: Слушает событие от BaseModule.OnDryZoneEntered/Exited и передает флаг в HectonFluidEngine для исключения из расчетов.

CurrentManager.cs / CurrentVolume.cs
Что это: Система подводных течений.

CurrentManager: Генерирует глобальный фоновый вектор течения через трехмерный Simplex Noise с анимированным смещением фазы. Течение медленно меняется со временем, создавая органическое поведение воды.

CurrentVolume: Компонент на триггере-коллайдере. Добавляет локальный вектор течения (например, поток из вентиляционной трубы базы или гейзер). Регистрируется в CurrentManager. При расчете финальной силы течения для объекта суммируется глобальный вектор и все активные локальные.

РАЗДЕЛ 3: PLAYER & SURVIVAL (Игрок и выживание)
HectonPlayerMovement.cs
Что это: Rigidbody-контроллер игрока с поддержкой пяти режимов передвижения.

Режимы (Locomotion Mode):

DryGroundWalk — движение по суше. Стандартная гравитация, прилипание к склонам.
DryInteriorWalk — движение внутри базы. Сниженная гравитация, отсутствие водной физики.
ShallowWadeWalk — движение вброд. Скорость снижается пропорционально глубине погружения.
SurfaceSwim — плавание на поверхности. Позиция Y фиксируется относительно высоты волн (интеграция с Crest Ocean).
UnderwaterSwim — полное подводное плавание. Трехмерное движение, водное сопротивление от HectonFluidEngine.
Переключение режимов: Определяется через серию SphereCast и Raycast проверок глубины и наличия поверхности воды над головой.

CameraJuiceProcessor.cs
Что это: Процессор процедурных эффектов камеры. Реализован как чистый struct без зависимостей от Unity API.

Эффекты:

Head Bobbing: Синусоида качания головы, частота и амплитуда зависят от режима движения и скорости.
Turn Lag Sway: При повороте камеры под водой добавляется инерционный наклон — имитация сопротивления воды шлему.
Collision Shake: При ударе о поверхность — короткая тряска на основе 3D Perlin Noise с затуханием.
Breath Rhythm: Ритмичное микросмещение камеры, синхронизированное с анимацией выдоха пузырей под водой.
FOV Compression: Угол обзора плавно сжимается с увеличением глубины. Создает ощущение клаустрофобии.
Архитектура: Работает только с чистыми числами (float, Vector3). Результат (CameraJuiceResult) передается наружу и применяется к трансформу камеры. Никаких зависимостей от MonoBehaviour.

HectonSurvivalSystem.cs / SurvivalStats.cs
Что это: Ядро механики выживания. Обрабатывает все жизненные показатели игрока.

Параметры:

О2 (Кислород): Расходуется под водой. При нуле начинается урон HP.
Энергия костюма: Тратится на фонарь, инструменты, активные модули скафандра.
HP (Целостность): Здоровье игрока.
Давление: Рассчитывается из текущей глубины. При превышении SafeDepth скафандр получает урон целостности.
Температура: Читается из локального биома (через HectonHazardManager). Критическая температура разряжает батарею быстрее.
Радиация: Накапливается в зонах излучения. Ухудшает все параметры при накоплении.
Голод и Жажда: Медленная деградация. При критическом уровне снижают скорость восстановления О2.
SurvivalStats: ScriptableObject с базовыми значениями параметров. RuntimeSurvivalStats — рантайм обертка, позволяющая модулям скафандра (SuitUpgradeData) динамически изменять базовые характеристики без изменения исходного ассета.

HectonPlayerHealth.cs
Что это: Отдельный компонент управления здоровьем игрока.

I-frames: После получения урона активируется период неуязвимости (Invincibility Frames). Исключает ситуацию, когда один удар монстра засчитывается несколько раз за один кадр из-за нескольких коллайдеров.

Интеграция: Получает урон от HectonSurvivalSystem (давление, температура) и от EnvironmentalHazard (ожоги, токсины, прямые удары фауны).

РАЗДЕЛ 4: TOOLS & EQUIPMENT (Инструменты)
PlayerTool.cs
Что это: Абстрактный базовый класс для всех инструментов игрока.

Контракт:

OnEquip() / OnUnequip() — анимация достания и убирания.
UsePrimary(bool held) / UseSecondary(bool held) — основное и вторичное действие.
Интеграция с ToolDurabilitySystem — каждый вызов UsePrimary уменьшает прочность.
Интеграция с IBatteryTool — расход энергии из батарейного слота инструмента.
PlayerToolManager.cs
Что это: Управление слотами быстрого доступа (1-4) и визуальной сменой инструментов.

State Machine смены:

Idle — инструмент в руке.
Lowering — рука плавно опускается вниз (Mathf.Lerp).
Swap — старый инструмент возвращается в пул, новый берется из пула.
Raising — рука поднимается обратно с новым инструментом.
Пулинг моделей: Визуальная 3D-модель инструмента в руке управляется через ObjectPoolManager. При смене инструмента — деспавн старой модели, спавн новой.

LaserCutter.cs
Что это: Лазерный резак. Используется для добычи руды и деконструкции модулей базы.

Механика нагрева:

При удержании ЛКМ накапливается параметр heat (0.0 — 1.0).
При heat > 0.7 урон по руде увеличивается на 15%.
При heat >= 1.0 — Overheat Lockout: инструмент блокируется на lockoutDuration секунд, издает звук перегрева.
При отпускании ЛКМ тепло рассеивается со скоростью coolingRate.
Режим деконструкции (ПКМ): При направлении на построенный модуль базы (BaseModule) — срезает HP модуля. При разрушении возвращает ресурсы в инвентарь (процент от стоимости постройки).

ScannerTool.cs
Что это: Сонар-сканер. Анализирует окружение.

Три режима:

Expedition — поиск точек интереса, входов в пещеры, сигналов.
Resources — поиск ресурсных узлов (HarvestableOutcrop).
Structures — поиск фрагментов чертежей (ScannableFragment) и модулей базы.
Механика: При активации спавнит ScannerPulseDrawer (визуальное расширяющееся кольцо через Shapes). Параллельно вызывает Physics.OverlapSphereNonAlloc с кэшированным массивом Collider[]. Найденные объекты фильтруются по режиму и отправляются в ScanEvents.

PropulsionTool.cs
Что это: Гравипушка. Толкает или притягивает физические объекты.

Push (ЛКМ): Rigidbody.AddForce(direction * pushForce, ForceMode.Impulse). Сила масштабируется обратно пропорционально массе — тяжелые объекты отлетают меньше.

Pull/Hold (ПКМ): Удержание объекта на дистанции holdDistance. Реализовано через Spring-Damper математику:

Вычисляется разница между текущей позицией объекта и целевой.
Прикладывается корректирующая сила с коэффициентом жесткости (stiffness) и демпфированием (damping).
Объект не дергается, а плавно стремится к целевой точке.
Ограничение по массе: Объекты с массой выше maxPullMass не могут быть притянуты. Визуально — инструмент гудит и показывает ошибку на дисплее.

HarpoonLauncherTool.cs
Что это: Гарпун с тросом для фиксации существ и транспортировки грузов.

Механика:

Выстреливает снаряд (из пула) с физическим Rigidbody.
При попадании в цель (существо или объект) снаряд фиксируется и создает виртуальный трос (LineRenderer).
Игрок может Reel (подматывать трос) короткими импульсами силы, притягивая цель.
Если цель — FaunaBrain, существо теряет возможность уйти за радиус троса.
При массе цели выше maxReelMass — подмотка невозможна, трос удерживает, но не тянет.
StunPistolTool.cs
Что это: Электрошокер для нейтрализации фауны.

Механика:

При попадании луча в существо ищет компонент FaunaBrain.
Если найден — на существо вешается временный компонент StunTargetRuntime (реализует ITickable).
StunTargetRuntime выставляет FaunaBrain.enabled = false и отсчитывает stunDuration.
По истечении таймера компонент снимается, FaunaBrain включается, компонент уходит в пул.
Отсутствие корутин: Вся логика таймера через ITickable, без StartCoroutine.

Оценка состояния цели перед выстрелом: Проверяет текущее состояние (FaunaState) существа. Спящее существо оглушается мгновенно и без звука. Агрессивное — с визуальным разрядом и повышенным расходом заряда.

BuilderTool.cs / PlayerBuilder.cs
Что это: Система строительства модулей базы. Разделена на два класса по зонам ответственности.

PlayerBuilder (Логика):

Ищет активные точки стыковки (ModuleSocket) через Physics.OverlapSphereNonAlloc.
При нахождении сокета — спавнит «призрак» (Ghost Prefab) модуля с прозрачным материалом.
Призрак фиксируется к сокету с гистерезисом: прилипание на 2.0м, отрыв на 2.5м.
При подтверждении постройки: снимает ресурсы из инвентаря, деспавнит призрак, спавнит реальный модуль.
BuilderTool (Визуал):

Реализует «NASA-punk инерцию»: модель инструмента с задержкой следует за камерой (Lerp с большим лагом).
Встроенный экран на инструменте через MaterialPropertyBlock отображает название и стоимость текущего выбранного модуля.
RepairTool.cs
Что это: Ремонтный инструмент для восстановления модулей базы.

Механика: При удержании ЛКМ на поврежденном BaseModule восстанавливает его HP со скоростью repairRate. Расходует энергию скафандра и расходный материал (гель, металл). Если модуль затоплен — инструмент работает медленнее.

FlashlightTool.cs / PlayerFlashlight.cs
Что это: Фонарик. Разделен на логику (FlashlightTool) и реализацию света (PlayerFlashlight).

Режимы:

Flood — широкий рассеянный луч. Ближняя видимость.
Focus — узкий дальнобойный луч. Привлекает больше внимания ИИ.
Перегрев и мерцание: Если батарея падает ниже 15% или фонарь перегрет — PlayerFlashlight запускает процедуру мерцания через Mathf.PerlinNoise(Time.time * flickerFrequency). Интенсивность умножается на шум, создавая органическое мерцание.

Интеграция с ИИ: LightDetectionSystem читает текущий режим фонаря (Flood/Focus) и уровень нагрева (HeatLevel) для расчета заметности игрока.

Volumetric Light Beam: Интеграция с плагином VLB. Интенсивность и наличие «взвеси» в луче меняются в зависимости от глубины и биома.

MantaScooter.cs
Что это: Подводный движитель (аналог Seaglide из Subnautica). Наследуется от PlayerTool, реализует IBatteryTool.

Механика:

При удержании ЛКМ прикладывает силу в направлении взгляда камеры.
Скорость ограничена maxSpeed. Дополнительно ограничена глубиной (давление воды).
Расходует заряд батареи пропорционально прикладываемой силе, не постоянно.
Встроенный дисплей на модели обновляет заряд через MaterialPropertyBlock.
ToolDurabilitySystem.cs
Что это: Синглтон. Отслеживает прочность всех инструментов в игре.

Механика: Хранит Dictionary<RuntimeInstanceId, float> прочностей. Инструменты обращаются к нему при каждом использовании. При достижении нуля — инструмент переходит в состояние Broken, UsePrimary блокируется до ремонта.

Сохранение: Реализует ISaveable. Состояние прочностей сохраняется в SaveData.

ToolLoadoutPreset.cs
Что это: ScriptableObject с пресетом из 4 инструментов для быстрого снаряжения.

Применение: Интерфейс PDA предлагает пресеты на основе контекста (на что смотрит игрок через FieldTargetSemantics). Один клик — полная смена экипировки.

РАЗДЕЛ 5: BASE BUILDING & POWER GRID (Строительство и энергетика)
BaseModule.cs
Что это: Логический и физический компонент построенного модуля базы (комната, коридор, шлюз).

Параметры:

HP — текущее здоровье. При нуле — затопление.
isFlooded — статус затопления. При true — включает ParticleSystem пробоины и звук воды.

Интеграция с системой урона: Реализует ICuttable. LaserCutter при деконструкции снимает HP через этот интерфейс.

Интеграция с сетью питания: При спавне регистрируется в PowerGridManager как PowerNode.

ModuleSocket.cs / HectonSocketHelper.cs
Что это: Точки стыковки на модулях базы.

ModuleSocket: Хранит позицию, поворот и тип допустимых соединений. При занятости блокирует подключение новых модулей.

HectonSocketHelper: Вспомогательные методы для PlayerBuilder. Находит ближайший свободный сокет в радиусе, проверяет совместимость типов, вычисляет целевую позицию и поворот для привязки призрака.

ConstructionManager.cs / ModuleCatalog.cs
Что это: Менеджер сохранения и загрузки построенной базы.

ModuleCatalog: ScriptableObject. Содержит список всех доступных для постройки модулей с их ID, стоимостью, описанием и ссылкой на префаб.

ConstructionManager:

При постройке сохраняет ModuleSaveRecord (ID модуля, позиция, поворот, HP, статус затопления).
При загрузке сцены итерируется по списку записей и спавнит модули в правильном порядке (сначала несущие конструкции, потом внутренние элементы).
Реализует ISaveable.
Fabricator.cs / RecipeData.cs
Что это: Фабрикатор — станок для крафта предметов внутри базы.

RecipeData: ScriptableObject. Содержит список требуемых ресурсов, выходной предмет, время крафта и требуемый уровень разблокировки.

Fabricator:

Потребляет энергию из PowerGrid во время крафта.
Если питание пропадает — крафт ставится на паузу (прогресс сохраняется), не сбрасывается.
При восстановлении питания — крафт возобновляется с той же точки.
Реализует ITickable для отсчета прогресса.
PowerGrid.cs / PowerNode.cs / PowerGridManager.cs
Что это: Симуляция сети электропитания базы.

PowerNode: Компонент на каждом модуле. Хранит генерируемую или потребляемую мощность (в ваттах) и приоритет потребителя.

PowerGrid: Логическая сеть из связанных узлов. Хранит список всех PowerNode.

Алгоритм балансировки:

Суммирует всю генерацию и всё потребление в сети.
Если дефицит — сортирует потребителей по приоритету (от высокого к низкому).
Отключает наименее важных потребителей (Декор = 100, Свет = 50, Жизнеобеспечение = 0) пока не достигнут баланс.
Алгоритм разделения сети (BFS): При уничтожении модуля PowerGridManager запускает BFS (поиск в ширину) от всех оставшихся узлов. Если обход не охватывает все узлы — сеть разделилась. Создается новый PowerGrid для изолированной части.

Алгоритм слияния: При постройке нового модуля, соединяющего две сети, меньшая поглощается большей.

SolarPanel.cs
Что это: Генератор энергии на солнечных батареях.

Механика: Пускает луч вертикально вверх (Physics.Raycast). Если луч не встречает препятствий — панель получает солнечный свет. Выработка энергии умножается на SunElevation из HectonAtmosphereManager (угол солнца) и обратно пропорциональна глубине (свет поглощается водой).

BioReactor.cs
Что это: Генератор энергии на органическом топливе.

Механика: Имеет N слотов для загрузки биологических предметов (PlanktonFilter, Fish, Coral). Каждый предмет имеет BioValue — количество ватт-часов. Реактор постепенно потребляет топливо и передает энергию в PowerGrid.

BatteryCharger.cs
Что это: Настенный зарядник для аккумуляторов инструментов.

Механика: Принимает батарею (реализующую IBatteryTool) из инвентаря. Тратит энергию из PowerGrid со скоростью chargeRate. Заряд передается в батарею. При полном заряде или пропадании питания — останавливается.

BaseAirlock.cs
Что это: Шлюз между внешним океаном и внутренним пространством базы.

Механика:

При взаимодействии запускает последовательность: закрывает внешнюю дверь, проигрывает анимацию откачки/заполнения воды, открывает внутреннюю, телепортирует игрока.

РАЗДЕЛ 6: WORLD GENERATION & GEOLOGY (Генерация мира)
HectonVoxelEngine.cs
Что это: Асинхронный генератор воксельных мешей для пещер и разломов.

Пайплайн генерации (последовательность Job-ов):

VoxelDensityJob (Burst, Parallel): Вычисляет 3D поле плотности (SDF). Поддерживает примитивы: сферы, эллипсоиды, капсулы, Box. Применяет Domain Warping (искривление пространства шумом). Делает плоское дно через math.max(density, -y + floorLevel).

VoxelMCExtractJob (Burst): По таблицам Marching Cubes генерирует треугольники из поля плотности.

VoxelWeldJob (Burst): Склеивает дублирующиеся вершины через NativeParallelHashMap<float3, int>. Уменьшает размер меша.

VoxelNormalJob (Burst, Parallel): Вычисляет нормали вершин через градиент плотности (аналитически, не усредняя треугольники). Дает более гладкий результат.

VoxelColorJob (Burst, Parallel): Красит вершины в зависимости от глубины, уклона поверхности и биома.

VoxelSpawnPointJob (Burst): Находит плоские участки пола через пространственный хэш (SpatialHash) для детерминированного размещения ресурсов.

Асинхронность: Весь пайплайн выполняется через JobHandle.CombineDependencies. Финальная сборка меша — через Mesh.ApplyAndDisposeWritableMeshData (Unity 2021+).

CaveGraphGenerator.cs
Что это: Математический генератор топологии пещер (скелет перед воксельным заполнением).

Алгоритм:

Запускает Random Walk (случайное блуждание) от центральной точки объема.
С вероятностью branchChance создает ответвление туннеля.
Ищет точки выхода на поверхность террейна (CaveEntrance).
От каждого входа «прорубает» прямой туннель к ближайшему узлу графа.
Зоны вокруг входов помечаются как EntranceExempt — они исключаются из алгоритма «запечатывания краев» (Edge Sealing) вокселей.
WorldGenerativeGeologyMeshBuilder.cs
Что это: Процедурный генератор мешей скал, арок и шпилей (не воксельных).

Механика:

Берет базовый примитив (box, ellipsoid, capsule).
Деформирует вершины многослойным фрактальным шумом (fBm Noise): крупный слой задает общую форму, мелкий — детали поверхности.
Сразу генерирует три уровня LOD (треугольников: 100%, 40%, 10% от оригинала).
Генерирует упрощенный меш для MeshCollider.
HectonWorldGenerator.cs / MapMagicBridge.cs
Что это: Интеграция с плагином MapMagic для управления террейном.

HectonWorldGenerator: Управляет загрузкой и выгрузкой чанков вокруг игрока. Настраивает приоритет генерации — чанки по ходу движения игрока генерируются быстрее.

MapMagicBridge: Предоставляет API для запроса данных о мире в конкретной точке: высота террейна, индекс биома, наклон поверхности. Используется системами спавна ресурсов, ИИ и атмосферы.

ScavengePopulator.cs / HectonScatterOutput.cs
Что это: Система спавна ресурсов на сгенерированном террейне.

HectonScatterOutput: Кастомная нода для графа MapMagic. Вместо записи данных в TerrainData передает координаты точек напрямую в ScavengePopulator.

ScavengePopulator: Ставит координаты в очередь _spawnQueue. В каждом кадре (ITickable) извлекает не более maxSpawnsPerTick записей и спавнит ресурсы. Time-slicing исключает лаги при загрузке нового чанка.

ProximityColliderSystem.cs
Что это: Система динамического управления коллайдерами для декоративных объектов.

Проблема: Тысячи камней рендерятся через GPU Instancing (один Draw Call) без коллайдеров. Без коллайдеров игрок проваливается сквозь них.

Решение:

Burst Job (DistanceCalcJob) вычисляет квадрат расстояния от игрока до каждого инстанса.
Инстансы в радиусе 40м получают реальный BoxCollider из пула.
Инстансы за 45м (гистерезис) возвращают коллайдер в пул.

HectonCelestialEngine.cs
Что это: Рендер Газового Гиганта и небесного свода.

Механика:

HectonOceanPalette.cs / HectonBiomeProfile.cs
Что это: ScriptableObject-наборы параметров воды для разных биомов.

HectonBiomeProfile: Содержит наборы значений для всех параметров воды (HectonUnderwaterVisuals): цвета тумана, плотность взвеси, интенсивность биолюминесценции, музыкальный профиль.

HectonBiolumManager.cs
Что это: Менеджер биолюминесцентного освещения.

AmbientWaterMotion.cs / AmbientWaterMotionManager.cs
Что это: Система имитации колыхания водорослей и мелких объектов без физики.

CurrentVolume: Локальный источник течения. При входе игрока или физического объекта в триггер — добавляет свой вектор к суммарному течению. Примеры: поток из трубы вентиляции базы, выброс гейзера, течение у входа в пещеру.

РАЗДЕЛ 8: AI, FAUNA & DIRECTORS (ИИ, фауна, режиссура)
HectonBoidController.cs
Что это: GPU-симуляция рыбьих стай.

Архитектура Ping-Pong буферов:

Данные рыб (BoidData — 32 байта: позиция, скорость, ID стаи) хранятся в двух ComputeBuffer (A и B).
На четных кадрах Compute Shader читает из A, пишет в B. На нечетных — наоборот.
CPU никогда не ждет GPU — чтение и запись происходят в разные буферы.
Поведение стаи (Compute Shader): Каждая рыба читает данные ближайших соседей (через пространственный хэш в GPU-памяти) и применяет три силы: Separation (избегание столкновений), Alignment (выравнивание скоростей), Cohesion (стягивание к центру стаи).

Рендер: Graphics.RenderMeshIndirect — один Draw Call для 5000+ рыб.

Ограничение зоны: Ось Y зоны стаи ограничена сверху waterSurfaceY — рыбы не вылетают в воздух.

FaunaDirector.cs
Что это: Управление спавном и деспавном существ вокруг игрока.

Кольцо спавна: Существа спавнятся в кольце от spawnRadiusMin (50м) до spawnRadiusMax (150м). Слишком близко — ИИ мог бы появиться прямо перед игроком. Слишком далеко — игрок никогда не встретит.

Лимиты: globalFaunaLimit (общий лимит) и biomeFaunaLimit[] (лимит на биом). Хранятся как простые счетчики int[]. Без LINQ Count() — только инкремент/декремент.

Деспавн: Существа за cullRadius (200м) возвращаются в пул. При деспавне проигрывается переходная анимация исчезновения (fade out), если существо в поле зрения.

HectonDirectorAI.cs
Что это: Режиссер напряжения. Управляет темпом страха и опасности.

TensionScore (0-100):

О2 < 30% → +25 очков.
HP < 40% → +20 очков.
Хищник в радиусе 30м → +15 очков за каждого (лимит +40).
Глубина > 500м без базы → +10 очков.
Фазы:

BuildUp (0-60): Редкие пугающие звуки. Случайные глитчи HUD. Далекий силуэт левиафана.
Peak (60-100): Спавн орды хищников (ForceSpawnHorde). Поломка фонаря (принудительно снижает заряд батареи). Дестабилизация компаса.
Relax (после Peak): Хищники получают команду отступить (FaunaState.Retreat). Спавн редкого лута рядом с игроком. Автосохранение.
Расчет: Выполняется в SlowTick (2 раза в секунду). Использует Physics.OverlapSphereNonAlloc с кэшированным Collider[].

FaunaBrain.cs
Что это: Мастер-контроллер существа. Координирует все подсистемы ИИ.

Brain LOD: Если существо вне поля зрения камеры (GeometryUtility.TestPlanesAABB), мозг переключается в экономный режим — обновление раз в 30 кадров. Полная симуляция только для видимых.

Координация подсистем:

FaunaSensorSuite — поставляет данные о восприятии.
FaunaStateMachine — принимает решения.
FaunaSteeringEngine — выполняет движение.
FaunaSensorSuite.cs
Что это: Сенсоры существа — зрение и слух.

Зрение:

Physics.SphereCastNonAlloc в направлении взгляда.
Проверка угла между направлением к игроку и направлением взгляда существа (Vector3.Angle).
Применяется коэффициент из LightDetectionSystem — яркий фонарь увеличивает дистанцию обнаружения.
Слух:

NoiseSystem возвращает уровень шума от игрока.
При шуме выше порога — существо поворачивается в сторону источника даже без визуального контакта.
FaunaSteeringEngine.cs
Что это: Физика плавания существа.

Центростремительное снижение скорости: При резких поворотах скорость автоматически снижается. Рыбы не разворачиваются мгновенно как вертолеты.

Banking (Крен): При повороте тело существа наклоняется в сторону поворота через Quaternion.Lerp. Угол крена пропорционален угловой скорости.

Избегание препятствий: SphereCastNonAlloc в направлении движения. При обнаружении препятствия — рулевая сила отталкивается от нормали поверхности.

Что это: Конечный автомат состояний существа.

Состояния:

Curious — осторожное приближение к необычному объекту.
Flee — паническое бегство (от хищника или выстрела).
Hunt — активное преследование добычи.
Attack — атака цели в зоне досягаемости.
Sated — сытость после поедания. Агрессия снижена на satedDuration секунд.
Retreat — отступление по команде HectonDirectorAI.

РАЗДЕЛ 9: HAZARDS & SURVIVAL (Опасности среды)
HectonHazardManager.cs
Что это: Централизованный менеджер опасностей окружающей среды.

Архитектура:

Хранит массив структур HazardSourceData[128] (позиция, тип, интенсивность, радиус).

РАЗДЕЛ 11: SAVE SYSTEM (Система сохранений)
SaveManager.cs / ISaveable.cs / SaveData.cs
Что это: Асинхронная система сохранений с проверкой целостности.

ISaveable: Интерфейс с методами PopulateSaveData(SaveData data), RestoreFromSaveData(SaveData data) и приоритетами SavePriority/LoadPriority.

Порядок загрузки:

HectonPlayerHealth (Priority 100) — игрок существует.
PlayerInventory (Priority 80) — инвентарь загружен.
SuitUpgradeManager (Priority 60) — апгрейды применены.
QuestManager (Priority 40) — квесты восстановлены.
ConstructionManager (Priority 20) — база построена.
Целостность:

Данные сериализуются в байты.
Вычисляется CRC32 хэш и сохраняется в отдельный .meta файл.
При загрузке хэш пересчитывается и сравнивается. Несоответствие — файл поврежден.
Система автоматически откатывается на последний валидный бэкап (до 8 поколений .bak файлов).
Асинхронность: await Awaitable.BackgroundThreadAsync() — тяжелая сериализация уходит на фоновый поток. Main Thread не блокируется.

SaveDataMigration.cs
Что это: Система обратной совместимости сохранений.

Механика: При загрузке проверяется версия SaveData.Version. Если версия старше текущей — SaveDataMigration последовательно применяет патчи (Migration Steps). Например: версия 1 → 2: добавляются поля Thirst и Hunger со значениями по умолчанию. Игра не крашится при загрузке старого сейва.

WorldStateManager.cs
Что это: Менеджер состояния ресурсных узлов в процедурном мире.

Оптимизация Delta-Save:

Не сохраняет все ресурсы в мире (их могут быть тысячи).
Хранит только HashSet<string> ID добытых или уничтоженных ресурсов (_depletedNodeIds).
При загрузке чанка — проверяет каждый ресурс на наличие в HashSet. Найден — SetActive(false).
Детерминированные ID ресурсов гарантированы SpatialHash из VoxelSpawnPointJob.

РАЗДЕЛ 15: RENDERING & OPTIMIZATION SYSTEMS (Рендер и оптимизация)
CullingManager.cs
Что это: Менеджер отсечения невидимых объектов.

Механика:

Объекты регистрируются с указанием Bounds.
Каждый Tick проверяет дистанцию (через квадрат расстояния, без sqrt) и попадание в пирамиду видимости (GeometryUtility.TestPlanesAABB).
При выходе за порог: renderer.forceRenderingOff = true.
Гистерезис: Отключение на 100м, включение на 90м. Устраняет мерцание на границе.
LODSystemManager.cs
Что это: Менеджер уровней детализации.

Механика:

Координаты всех LOD-объектов копируются в NativeArray<float3>.
DistanceCalculationJob (Burst, Parallel) вычисляет квадрат расстояния до каждого.
Результаты NativeArray<float> читаются на Main Thread.
На основе дистанции выбирается уровень LOD (0, 1 или 2).
Переключение через LODGroup.ForceLOD(level).
Производительность: Расчет дистанций для сотен объектов занимает <1 мс благодаря параллельному Burst Job.

DynamicResolutionScaler.cs
Что это: Адаптивное масштабирование разрешения рендера.

Механика:

Отслеживает FrameTime через скользящее среднее (последние 30 кадров).
Если среднее время > targetFrameTime (16.67 мс для 60 FPS) — плавно снижает renderScale URP.
Если время значительно меньше целевого — плавно повышает обратно.
Изменение плавное (Mathf.Lerp) — без резких скачков качества.
Уведомляет другие системы через событие OnRenderScaleChanged.
ImpostorSystem.cs
Что это: Система замены дальних 3D объектов на 2D билборды.

Механика:

При превышении impostorDistanceThreshold — реальный меш заменяется на Quad с материалом-импостором.
Импостор всегда повернут к камере (Billboard).
Материал импостора создается в рантайме из текстур реального материала: new Material(sourceMaterial).
Риск утечки памяти: Созданные через new Material() объекты не управляются GC Unity — управляются C++ ядром. Требуют явного Destroy() при деактивации. Вызывается в ReleaseCachedMaterials() через OnDestroy. При долгих сессиях без правильной очистки — постепенный рост потребления памяти.

HectonBiolumManager.cs (детали рендера)
Shader.SetGlobalColor: Доминирующий биолюминесцентный цвет биома передается в шейдер воды как глобальная переменная. Все водные шейдеры в сцене получают цвет без отдельных вызовов на каждый объект.

FloraInteractionManager.cs
Что это: Система физического взаимодействия флоры с движением игрока (Prop Wash).

Механика:

Вычисляет силу воздействия: force = velocity.magnitude * propWashStrength.
Передает позицию и силу в GPU через Shader.SetGlobalVector(_PropWashPosId, ...) и Shader.SetGlobalFloat(_PropWashForceId, ...).
Все шейдеры водорослей в видеопамяти читают эти глобальные значения и смещают вершины в вершинном шейдере.
CPU: ноль затрат на физику флоры. GPU: линейная нагрузка от количества вершин водорослей в кадре.

РАЗДЕЛ 16: SCATTER & PROCEDURAL FLORA (Процедурная флора)
WorldProceduralScatterDirector.cs
Что это: Центральный директор процедурной расстановки флоры, камней и декора.

Архитектура (Partial классы):

.Contexts — управление контекстами биомов и параметрами.
.Integration — интеграция с MapMagicBridge и FaunaDirector.
.Pipelines — управление последовательностью Job-ов.
.Memory — ScatterWorkingMemory (сотни предвыделенных массивов).
ScatterWorkingMemory: Все рабочие массивы и буферы аллоцируются один раз при инициализации. Job-ы работают с этой памятью без новых аллокаций.

ScatterEvaluator.cs
Что это: Burst Job для вычисления позиций объектов флоры.

ScatterCellEvaluationJob (Burst, IJobParallelFor):

Для каждой ячейки сетки вычисляет детерминированный Random.State на основе HashInt2(cellX, cellZ, seed).
Генерирует N кандидатов (ScatterSimulationCandidate) — позиция, поворот, масштаб, ID префаба.
Применяет ScatterHeuristicsUtility — кривые плотности по глубине и уклону.
Проблема Interlocked: Interlocked.Increment(ref CandidateCount) для подсчета кандидатов из параллельных потоков вызывает Cache Line Contention. При большом числе потоков это замедляет Job. Альтернатива — NativeQueue.ParallelWriter.

ScatterHeuristicsUtility.cs
Что это: Математические кривые плотности флоры.

Механика: Для каждого вида флоры определены AnimationCurve — зависимость вероятности появления от глубины и уклона. Например: Ламинария — высокая плотность на 10-50м, нулевая ниже 150м. Кораллы — высокая плотность на склонах 20-45°.

ScatterHybridRuntimeEntryPoint.cs / ScatterRuntimeBackendFacade.cs
Что это: Точка входа и фасад гибридного бэкенда.

Два бэкенда:

ScatterClassicSimulationBackend — через IJobParallelFor (Burst). Стабильный, хорошо протестированный.
ScatterEntitiesSimulationBackend — через Unity ECS/DOTS. Экспериментальный.
ScatterHybridRuntimeEntryPoint: Выбирает бэкенд на основе настроек и доступности DOTS пакета. При недоступности DOTS — автоматически откатывается на Classic.

Архитектурная проблема DOTS-бэкенда: Создает World, конвертирует данные, выполняет Job, копирует результаты, уничтожает World. Это использует ECS как разовый калькулятор, полностью игнорируя его архитектурные преимущества (постоянное хранение данных в Chunks). Накладные расходы на маршаллинг нивелируют выигрыш производительности.

WorldProceduralCoralMeshBuilder.cs / WorldProceduralSeaweedMeshBuilder.cs
Что это: Редакторные генераторы 3D-мешей флоры математическими методами.

WorldProceduralCoralMeshBuilder: Генерирует ветвистые структуры через рекурсивный L-систем алгоритм с отклонениями на основе шума. Ветви — цилиндры с уменьшающимся радиусом. Кончики — половинки сфер.

WorldProceduralSeaweedMeshBuilder: Генерирует листья водорослей через кривые Безье. Каждый лист — набор квадов (Quads) вдоль кривой с UV-развёрткой для текстурирования.

Оба скрипта работают только в редакторе и запекают результат в .mesh ассет. В рантайм не попадают.

WorldProceduralFloraTextureAuthoring.cs
Что это: Редакторный инструмент для управления текстурами флоры.

Функции:

Проверяет наличие требуемых текстурных карт (Albedo, Normal, Mask) для каждого вида флоры.
При отсутствии — генерирует файл PROCEDURAL_FLORA_TEXTURE_REQUEST_PACKET.md с Midjourney промптами для создания недостающих текстур.
При наличии — автоматически назначает текстуры на материалы и настраивает параметры импорта (Compression, MipMaps, sRGB).
Содержимое промпта: Seamless tiling PBR {mapType} texture, {speciesDescription}, photorealistic, 4K resolution, edge-perfect seamless tile pattern, --tile --v 6 --ar 1:1.

РАЗДЕЛ 17: INTERACTION SYSTEM (Система взаимодействия)

PlayerInteraction.cs
Что это: Компонент игрока. Управляет обнаружением и выполнением взаимодействий.

Оптимизация частоты: Raycast выполняется не каждый кадр, а по таймеру (raycastInterval = 0.05f — 20 раз в секунду). На 60 FPS это снижает нагрузку в 3 раза.

Блокировка ввода: Читает состояние UI-менеджеров (PDA открыт, Фабрикатор открыт). Если UI активен — блокирует выполнение Interact(), но не блокирует Raycast. Подсказки обновляются даже при открытом меню.

NonAlloc: Physics.RaycastNonAlloc с предвыделенным RaycastHit[].

InteractionEvents.cs
Что это: Статическая шина событий взаимодействия.

События:

OnItemCollected(ItemData item) — подбор предмета.
OnInteractionStarted(IInteractable target) — начало взаимодействия.
OnHoverChanged(IInteractable previous, IInteractable current) — смена цели наведения.
Архитектура: Статические C# event Action<T>. Никаких аллокаций. Подписчики (инвентарь, квесты, аудио, UI) получают данные без прямой связи с PlayerInteraction.

Пресеты графики: Кнопки Low/Medium/High/Ultra применяют наборы настроек из GraphicsPresetProfile (ScriptableObject).

## РАЗДЕЛ 20: AUDIO SYSTEMS (Аудиосистемы)

### SpatialAudioManager.cs
Что это: Глобальный Zero-GC пул AudioSource.

Два пула:
- **3D пул** — для звуков мира (существа, механизмы, взрывы). AudioSource с пространственным смешиванием (spatialBlend = 1.0).
- **2D пул** — для звуков внутри шлема игрока (дыхание, предупреждения костюма, UI). AudioSource без позиционирования (spatialBlend = 0.0).

Алгоритм вытеснения: Если все источники заняты — находит источник с наименьшим оставшимся временем воспроизведения (_startTimes + _clipLength) и перезаписывает его новым звуком.

Никакого AudioSource.PlayClipAtPoint — этот встроенный метод Unity создает и уничтожает GameObject каждый раз, генерируя мусор.

### AcousticZoneController.cs
Что это: Управление акустическим профилем при переходе между средами.

Механика: Читает флаг IsInAir из HectonSurvivalSystem. При переходе океан→база переключает AudioMixerSnapshot через TransitionTo(snapshot, transitionTime). Снимает Low-Pass фильтр (глухой звук воды), включает реверберацию маленькой металлической комнаты (IR-реверб).

При выходе в океан — обратный переход. Длительность перехода соответствует времени анимации шлюза.

### PlayerFootstepAudio.cs
Что это: Система звуков шагов.

Механика определения поверхности:
- Raycast вниз. Попадание в Terrain — запрашивает индекс биома у MapMagicBridge (песок, камень, ил, грязь) → соответствующий звуковой профиль.
- Попадание в GameObject — читает Tag (Metal, Grate, Composite, Glass) → соответствующий профиль.

Адаптация громкости: volume *= Mathf.Clamp01(rigidbody.linearVelocity.magnitude / referenceSpeed). На медленном шагу тихо, на беге громко.

При ShallowWadeWalk: звук плеска воды накладывается поверх звука поверхности, громкость масштабируется по глубине погружения ног.

### PlayerThrusterAudio.cs
Что это: Звук двигателей скафандра при плавании.

Механика: Бесшовный луп двигателей. Pitch и volume в каждом Tick интерполируются (math.lerp с deltaTime) в зависимости от magnitude вектора скорости игрока. При ускорении — нарастание. При остановке — плавное затихание. Создает физическое ощущение усилия и инерции.

### HectonMusicDirector.cs (детали)

Расчет Tension: SlowTick вычисляет TensionScore аналогично HectonDirectorAI но независимо — для музыки нужна собственная оценка без прямой зависимости от ИИ-директора.

Кроссфейд: Два AudioSource (_voiceA, _voiceB). Активный голос плавно снижает volume до 0, неактивный — повышает до targetVolume. После завершения — роли меняются. Следующий трек всегда начинается с нулевой громкости.

Stingers: При получении события (OnBiomeDiscovered, OnThreatDetected, OnLootFound) воспроизводится короткий Stinger через отдельный 2D AudioSource. Основной трек приглушается через AudioMixer.SetFloat("MusicVolume", duckLevel) на время Stinger + fadeOut.

## РАЗДЕЛ 21: PLAYER ANIMATION & PRESENTATION (Анимация игрока)

### PlayerSwimPresentationController.cs
Что это: Процедурная система анимации плавания от первого лица.

StrokePhase (Фаза гребка): Вычисляется на основе скорости и направления движения. При движении вперёд — симметричный гребок обеими руками. При движении вверх — гребки смещены в стороны. При вращении вокруг вертикальной оси — асимметричный гребок (одна рука сильнее).

Turn Lag Sway: При повороте камеры добавляется боковой наклон корпуса. Коэффициент зависит от текущего SwimPresentationProfile (лёгкий костюм — меньше лага, тяжёлый — больше).

Sprint Hand Tuck: При максимальной скорости (использование MantaScooter или активное плавание) руки процедурно прижимаются к телу на handTuckDistance.

Архитектура: Класс не имеет прямых зависимостей от Unity компонентов. Принимает чистые данные (скорость, угловая скорость, профиль костюма) и возвращает SwimPresentationResult (смещения и повороты костей). Применяется в PlayerSwimBlockoutRig.

### PlayerSwimBlockoutRig.cs
Что это: Применяет данные от PresentationController к костям рук на экране.

Wall Awareness (осознание стен): Два SphereCastNonAlloc — от левой и правой руки в направлении движения. При обнаружении препятствия в радиусе wallCheckDistance — рука процедурно поджимается к телу. Чем ближе стена — тем сильнее поджатие. Эффект делает движение в узких пещерах убедительным.

### PlayerActionController.cs
Что это: Управление длительными действиями (еда, лечение).

Механика прерывания: При запуске действия (например, применение аптечки, 3 секунды) контроллер отслеживает:
- Скорость игрока > interruptSpeedThreshold → CancelAction().
- Смена инструмента через PlayerToolManager → CancelAction().
- Получение урона → CancelAction().

При отмене — предмет не тратится, прогресс сбрасывается, ActionProgressHUD скрывается.

Интеграция с камерой: При старте длительного действия — передаёт событие в CameraJuiceProcessor для лёгкого смещения камеры (имитация движения рук к лицу).

### PlayerToolSwimContract.cs / PlayerToolSwimHandedness.cs
Что это: Контракт взаимодействия инструмента с анимацией плавания.

PlayerToolSwimContract: ScriptableObject. Определяет для конкретного инструмента: какая рука занята (Left/Right/Both), насколько ограничивает гребок свободной руки (strokeReductionFactor), добавляет ли инерцию удержания (holdInertia).

PlayerToolSwimHandedness: Компонент на инструменте. Передаёт данные контракта в PlayerSwimPresentationController при экипировке инструмента. При снятии — возвращает параметры к стандартным.

## РАЗДЕЛ 22: WORLD STREAMING & FIDELITY (Стриминг мира)

### WorldStreamingDirector.cs
Что это: Динамическое управление качеством генерации и дальностью прорисовки.

Motion Mode адаптация:
- **Survey** (медленное плавание/стоит): Максимальные лоды, максимальная плотность флоры, минимальный terrainPixelError.
- **Traverse** (быстрое плавание/скутер): Снижение LOD флоры, увеличение terrainPixelError MapMagic, снижение mapMagicObjectsPerFrame — новые чанки генерируются медленнее, но без фризов.
- **Sprint** (максимальная скорость): Дополнительное снижение дальности теней, отключение дорогих Post-Process эффектов.

Прогнозирование: Определяет вектор движения игрока и увеличивает приоритет генерации чанков в направлении движения.

### WorldChunkStreamingProfile.cs
Что это: ScriptableObject с параметрами слоёв стриминга.

Слои:
- **FullSimulationRadius** (например, 180м): Полная физика, анимации, ИИ.
- **MidSimulationRadius** (420м): Упрощённый ИИ (Brain LOD), нет физики воды, LOD2 меши.
- **VisualResidencyRadius** (900м): Только силуэты (LOD2 или Impostors), никаких вычислений.

### WorldFidelityRoot.cs
Что это: Компонент на префабах окружения. Принимает команды от системы стриминга.

При смене уровня симуляции:
- FullSim → MidSim: renderer.shadowCastingMode = Off, rigidbody.isKinematic = true.
- MidSim → Visual: renderer.forceRenderingOff при выходе из зоны, возможна замена на Impostor.
- Visual → Culled: GameObject полностью деактивируется.

### WorldSliceAnchor.cs / WorldZoneAnchor.cs / WorldZoneDirector.cs
Что это: Система логических зон мира.

WorldZoneAnchor: Определяет зону через центр и радиус. Рассчитывает принадлежность через расстояние с плавным затуханием на краях. Дополнительно добавляет Perlin Noise смещение границы — зоны не ровные круги, а органические.

WorldZoneDirector: Управляет активными зонами вокруг игрока. Загружает/выгружает зоны при пересечении границ. Уведомляет DepthZoneDirector и HectonMusicDirector.

WorldSliceAnchor: Вертикальный срез мира (глубинная зона). Работает по оси Y, а не XZ. Используется для разделения зон по глубине (мелководье, средняя зона, абисс).

## РАЗДЕЛ 23: DIAGNOSTICS & EDITOR AUTOMATION (Диагностика и автоматизация)

### PerformanceBudgetController.cs (детали)
Измерение: System.Diagnostics.Stopwatch.GetTimestamp() до и после вызова подсистемы. Вычисляется реальное время в миллисекундах.

Throttle механизм: При превышении бюджета — устанавливается throttleLevel (0.0–1.0) для подсистемы. Подсистема читает своё значение и снижает качество: меньше объектов за кадр, реже обновление, ниже разрешение эффектов.

Гистерезис бюджета: Throttle включается при превышении на 20%, снимается при снижении ниже 80% — исключает постоянное мерцание качества.

### RuntimeDiagnosticsTrace.cs (детали)
Формат лога: Каждая аномалия записывается с временной меткой (sessionTime), типом (GCSpike, FrameDrop, VRAMPressure), значением и виновной подсистемой (если определена).

Фоновый поток: Запись через StreamWriter в фоне через производитель-потребитель очередь (ConcurrentQueue<string>). Main Thread только кладёт строку в очередь — без блокировки.

### ConstructionBootstrapAuthoring.cs / ResourceCraftingBootstrapAuthoring.cs

ResourceCraftingBootstrapAuthoring: Аналогично генерирует все RecipeData ScriptableObjects. Задаёт ингредиенты, время крафта, требуемый уровень сканирования.

Назначение: Позволяет изменить баланс стоимости всего контента одним скриптом, не трогая сотни ScriptableObject файлов вручную.

### BiomeMatrixBootstrapAuthoring.cs
Что это: Генератор профилей для всех 108 биомов.

Механика: Использует большой switch/case на имена биомов. Для каждого задаёт набор параметров: atmosphereMood, oreDensity, floraVariant, faunaProfile, hazardType.

Архитектурный риск: Данные биомов хардкодированы в C# коде. Изменение параметра биома требует перекомпиляции. Правильнее — CSV или JSON с биомными данными, которые скрипт только читает и применяет.

### CreatureProxyPrefabAuthoring.cs / CreatureArchetypeAuthoring.cs
Что это: Генераторы заготовок для существ.

CreatureProxyPrefabAuthoring: Создаёт базовый GameObject существа: Rigidbody, CapsuleCollider, FaunaBrain, FaunaSensorSuite, FaunaSteeringEngine, FaunaStateMachine — все компоненты с дефолтными значениями. Художник и дизайнер получают готовую заготовку.

CreatureArchetypeAuthoring: Заполняет CreatureArchetypeData ScriptableObject базовыми балансными значениями для нового вида. Даёт стартовую точку для дизайнера.

WorldRuntimeBootstrapAuthoring: Аналогично — создаёт полную иерархию всех рантайм-директоров (WorldStreamingDirector, FaunaDirector, HectonDirectorAI, DepthZoneDirector). Исключает ситуацию когда левел-дизайнер забывает добавить нужный менеджер в сцену.

### ShellVerificationRuntimeSmokeTester.cs

## РАЗДЕЛ 24: PLAYER SUBSYSTEMS (Подсистемы игрока)

### LightDetectionSystem.cs
Что это: Расчёт визуальной заметности игрока для ИИ.

Формула: visibilityScore = baseScore * distanceFalloff * angleFactor * lightModifier * heatModifier.

- distanceFalloff: 1.0 / (distance * distance) — обратные квадраты.
- angleFactor: Dot Product между направлением взгляда существа и вектором к игроку.
- lightModifier: Flood режим = 1.2, Focus = 1.5, выключен = 0.3.
- heatModifier: heat > 0.7 → lightModifier *= 1.15 (перегретый фонарь светит ярче в ИК-диапазоне).

Результат 0.0–1.0 передаётся в FaunaSensorSuite как множитель дальности обнаружения.

### NoiseSystem.cs
Что это: Расчёт акустической заметности игрока.

Формула: noiseLevel = velocityMagnitude * noiseCurve.Evaluate(depth) * toolNoiseFactor.

- velocityMagnitude: Скорость Rigidbody игрока.
- noiseCurve: AnimationCurve — на большой глубине звук распространяется дальше.
- toolNoiseFactor: Лазерный резак = 2.0, сканер = 0.5, пустые руки = 1.0.

### FieldTargetDescriptor.cs / FieldTargetSemantics.cs
Что это: Семантическая разметка объектов мира.

FieldTargetDescriptor: Компонент на объекте. Хранит FieldTargetRole (enum) и дополнительные метаданные (масса, статус затопления, тип биома).

FieldTargetSemantics: Rule-based система. Принимает FieldTargetDescriptor + текущий инструмент игрока → генерирует SemanticAssessment (заголовок, краткое описание, рекомендация).

Пример правила: Если role == CargoHeavy И activeTool == PropulsionTool И rigidbodyMass > 60 → рекомендация "Используйте короткие импульсы. Масса превышает оптимальный порог".

Используется в: EnvironmentalAnalyzerTool (детальное сканирование), InteractionUI (контекстные подсказки), FieldLoadoutAdvisor (рекомендации пресетов снаряжения).

### RuntimeSurvivalStats.cs
Что это: Рантайм обёртка над базовыми SurvivalStats.

Механика: Хранит базовые значения из SurvivalStats ScriptableObject. Апгрейды (SuitUpgradeData) вызывают ApplyUpgrade() и RemoveUpgrade() — изменяют текущие значения мультипликаторами. Базовый ScriptableObject не изменяется. При загрузке игры — применяются все установленные апгрейды поверх базы.

### InventoryGrid.cs / PlayerInventory.cs
Что это: Инвентарная система с сеткой (Tetris-механика).

InventoryGrid: Чистый C# класс. Двумерный массив ItemData[,] _grid. TryAddItem — линейный поиск первого свободного прямоугольника соответствующего размера. При размещении — заполняет все занятые ячейки ссылкой на предмет. RemoveItem — обнуляет ячейки в прямоугольнике предмета. Никаких Unity зависимостей.

PlayerInventory: MonoBehaviour обёртка. Отслеживает суммарный вес (влияет на скорость передвижения через HectonPlayerMovement). Реализует ISaveable — сериализует сетку как список записей (ItemId, PositionX, PositionY).
