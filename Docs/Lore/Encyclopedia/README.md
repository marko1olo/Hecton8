## Tone Rules

- Write concrete physical facts first.
- Use corporate language only when the source is corporate.
- Use Marauder language only when the source is field-facing.
- Avoid mystical explanation when engineering explanation is stronger.
- Keep horror in implication, procedure, missing data, and pressure consequences.
- No clean omniscient exposition in player-facing text unless it is explicitly an archive article.
