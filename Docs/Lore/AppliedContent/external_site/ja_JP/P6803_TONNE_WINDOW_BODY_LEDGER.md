# Tonne-Window Body Ledger

tonne-window body ledger は、Aegir が route ではなく秤として聞こえ始める場所だ。そこでは、人が救助に値するかは問われない。持ち上げる mass は何か、誰が受け取るのか、何を汚染しうるのか、どの proof が同行するのか、次の carrier pass が慈悲を破片に変えずに減速できるのかが問われる。

Black Keel は Marauder を聞くことができる。signal は安いからだ。custody software が速いため、仮の行も予約できる。だが同情で body を持ち上げることはできない。生きた contractor は、水、骨、suit mass、pressure risk、quarantine exposure、liability history、oxygen addendum、sample contamination、そして誤った receiver に届けば Deep Reach を傷つける名前である。ledger が残酷なのは、正確だからだ。

## 法的状態としての Mass

紙面の行は `4.8 tonne-window equivalent` から始まるが、その数字は値札だけではない。ひとつの狭い recovery opportunity への請求だ。route は lift、thermal margin、shield tolerance、braking authority、receiver berth、quarantine volume を消費しなければならない。すべての kilogram は、receiver が開ける権利を持つものとして到着する必要がある。

だから body は生きていても body recovery として受理されないことがある。生存状態は緊急性を証明する。clean custody は証明しない。suit が blue-debt residue を帯び、recorder core が同じ ascent sleeve に縛られ、corpse tag が witness priority を持ち、Recovery Compliance が quarantine berth をまだ指定していなければ、ledger は body を pending にし、小さな真実を先に動かせる。

## 競合する行

醜い点は、ledger が人と無のどちらかを選ぶのではないことだ。すべて重要になりうる payload lines の間で選ぶ。sealed evidence core は Deep Reach liability を暴ける。pressure-glass sample は Xenon-Omega contamination を認証できる。tool crate は将来の ascent path を復旧できる。corpse tag は worker loss conversion を証明できる。生きた Marauder はその全部を持ちながら、なお certification が最も難しい。

Black Keel の古い firmware はそれらを recoverable mass classes として読む。Body。Proof。Sample。Salvage。Witness。各 class には別々の heat tolerance、quarantine rule、receiver risk、publicity cost がある。proof hash は汚れた packet pass を通れる。sample は sealed canister で待てる。body には、誰かが開くと決めた door が必要だ。

## Proof が先に出る理由

これは system の道徳的弁護ではない。罠が信じられる形になる理由だ。proof は呼吸しないので、copy、seal、hash、delay、verify ができる。body はできない。生きた body が ledger に入ると、欠けた clause のすべてが lawsuit、quarantine order、insurance failure になりうる。

Deep Reach はその差に隠れる術を覚えた。「diver を残せ」と書く必要はない。biological recovery language の前に、payload class、route-notary witness、contamination statement、receiver assignment を求めればいい。すべて手続きに見える。水中では、その手続きひとつひとつが空気を使う。

## World が見せるもの

それらの object は講義なしで rule を教える。route は空ではない。help は不在ではない。machine はそこにいる。数えている。

## Ledger の読み方

すべての recovery promise を四つの質問として読むこと。どの mass を持ち上げるのか。どの receiver が開けるのか。どの contamination が付いてくるのか。どの proof が priority を変えるのか。

答えが食い違うなら、Black Keel が返事をしただけで ascent hardware を使ってはいけない。receipts を保存し、proof sealed を保ち、可能なら samples を body line から分け、低い closure tone を聞け。Aegir 空間では、誰かが聞いた時点で rescue が現実になるのではない。ledger が body をただの cargo と偽れなくなった時に、初めて現実になる。
