# Fact ID Naming Convention - Proposed 1776

Evidence class: STATIC_DOC. Proposed until accepted by lore/data owners.

## Proposed Shape

`FACT_<DOMAIN>_<ARTICLE_OR_OBJECT>_<ASSERTION>`

Examples:

- `FACT_SURFACE_BRIGHTNESS_LOCK`
- `FACT_RESOURCE_BLUE_DEBT_CONTAINMENT_STAGE`
- `FACT_AEGIR_HECTON8_ORBITAL_HAZARD_TABLE_PRIMARY`
- `FACT_COLONY_EVACUATION_HOLD_PRIMARY`

## Rules

- ASCII uppercase only.
- Use `_` as separator.
- Domain comes first: `SURFACE`, `RESOURCE`, `AEGIR`, `COLONY`, `ATLAS`, `DEEP_REACH`, `PLAYER`, `ENDING`, `TRANSIT`, `ECOLOGY`, `HARDWARE`.
- Preserve existing Article ID/Packet ID. The fact ID is an audit key, not a replacement.
- One fact ID owns one assertion. Do not use one fact ID for both a canon truth and a source lie.
- If a source claims a wrong fact, create a separate claimed/contradicted fact row instead of weakening the canon fact.
- Player-note rows may reference fact IDs but must keep their own note template and unlock boundary.

## Migration Note

`fact_owner_matrix.csv` generated by this pass uses `FACT_<ARTICLE_ID>_PRIMARY` for packet-level primary facts. Treat those rows as provisional article-primary fact anchors, not final granular runtime facts.
