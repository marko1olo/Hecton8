## 2026-05-26 - PDA Cartography Native Alias Exorcism

What was wrong:
- `CartographyVaultBuffers` and `CartographyVaultReadBuffers` contained 42 NativeArray/ReadOnly field-like aliases. They were resolved from DataVault handles, but as ordinary structs they could still be accidentally persisted by future code.
- `CartographyTelemetryEntry` was 80 bytes, not the mandated 64-byte blackbox entry.
- `TryResolveViews` and `TryReadOnlyViews` trusted resolved buffer existence without validating expected capacity before jobs/GPU upload received views.
- `TrySetTuning` used a broad mutable view and unsafe pointer write for a single tuning DTO.
- The blackbox dump still used `Dump_SHINOBU_350.bin` and synchronous write semantics.

What was done:
- Converted `CartographyVaultBuffers` and `CartographyVaultReadBuffers` to `ref struct`. Compiler now prevents those 42 NativeArray aliases from becoming persistent fields, async captures, boxed values, or heap-held members.
- Kept persistent authority in `CartographyVaultHandles` as 16-byte `VaultGenerationHandle<T>` descriptors.
- Reduced `CartographyTelemetryEntry` to 64 bytes: grid AUP, local AUP, continuous quality scalar, frame, revision, state hash, mutation microseconds, reveal counts, map flags.
- Added fail-closed capacity validation for mutable, read-only, and legacy resolved views before consumer use.
- Converted `TrySetTuning` to `TryAcquireWriteLock` and `ReleaseWriteLock` in `finally`.
- Routed blackbox output to `Docs/AgentLogs/Dump_1321_Cartography.bin`.
- Reworked dump routing to snapshot the native 300-frame telemetry ring while the phase-local view is valid, then queue a ThreadPool writer. No NativeArray view escapes to the background thread.
- Added editor validator `Assets/_Project/Scripts/PDA/Editor/CartographyMemorySovereigntyValidator1321.cs` with DTO size, field offset, explicit layout, and handle-size checks.
- Added Unity `.meta` files for the new PDA editor folder and validator.
- Generated `Docs/Reports/VAULT_EXORCISM_REPORT_1321.json` with Roslyn scan data, before/after counts, and per-file SHA-256s.

Cinematic cheats used:
- Preserved existing cartography visual fakes and continuous visual decimation. No realistic simulation was added.
- Kept `GlobalQualityWeight` as continuous scalar for upload cadence, telemetry, and visual keep ratio. No binary low/high quality branch was introduced.
- Retained the fixed 1D bitfield/RLE approach instead of adding heavier spatial object graphs.

Exact microseconds saved / costs:
- Persistent native alias retention: 0 us/frame after `ref struct` enforcement; saved failure mode is relocation crash avoidance, not a measurable steady-state loop.
- Telemetry ring size: 80 -> 64 bytes. 300 frames now 19,200 bytes instead of 24,000 bytes, saving 4,800 bytes per cartography vault and reducing cold dump I/O by 20%.
- Resolver capacity gates: about 18 length checks per resolve, expected sub-1 us/control path on i3/MX350; buys fail-closed safety before job/GPU use.
- `TrySetTuning` writer lock: single-buffer control-path lock only, expected sub-1 us when uncontended; removes unsafe pointer write.
- Blackbox background route: hot path remains 0 file I/O. Fault path allocates one 19.2 KB snapshot plus wrapper object and shifts disk write off the caller thread.
