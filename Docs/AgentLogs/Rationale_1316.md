Replacing the density grid with a linear array keyed by cell index was rejected because world cell coordinates are sparse and negative; open addressing keeps lookup bounded without a managed hash map. Moving density cells into `GlobalDataVault` was rejected in this pass because the map is a presentation acceleration cache derived from active vegetation matrices, not authoritative cross-domain data.

## R89 - Loop80 Compaction Fence Closure In Vegetation BRG And Flora Vault Routes

Solution: Added fail-closed pre/post compaction-fence checks to the three touched files. `HectonIndirectVegetationRenderer` now rejects ensure/read/read-only/write-lock paths during compaction and releases acquired locks immediately if the fence activates after lock acquisition. `SargassumGlobalDragManager` now checks the fence around `EnsureGenerationHandle`, read-only resolve, and write-lock paths. `FloraInteractionManager` now checks the fence immediately before write-lock and after read/resolve acquisition. Removed the telemetry dump string interpolations and cold mesh-name interpolations from `HectonIndirectVegetationRenderer`. Re-ran the World native alias audit and seven-file hotpath audit.

Scalability potential: Low devices keep the same fixed BRG/telemetry capacities and fail optional visual data closed during compaction; Middle keeps current buffers; High and Ultra can raise capacities or restore more async scratch only after a formal commit-window route and profiler proof. ## R90 - Loop81 Flora Ambient Sway Vault Lock Discipline
Problem: `FloraAmbientSwayRuntime` still resolved DataVault buffers through a mutable local `TryResolve` helper and then wrote params, flow state, tuning, telemetry, CSV scratch, and biome profiles without explicit write-lock ownership. Several routes also lacked post-resolve compaction-fence checks. The editor CSV import additionally held profile write-lock while checking file existence and reading from disk.
Solution: Replaced mutable resolve routes with local `TryRead<T>` and `TryAcquireWrite<T>` helpers. `TryRead<T>` checks `IsCompactionFenceActive` before and after `TryReadOnlyHandle`; `TryAcquireWrite<T>` checks before acquisition and releases immediately if the fence activates after acquisition. Runtime parameter calculation now reads flow/tuning as `NativeArray<T>.ReadOnly`, writes params under a short write lock, and releases flow/params locks in `finally`. Telemetry ring and cursor writes now release both locks through `finally` even on invalid capacity. Visual upload copies a DTO value read from a read-only Vault view into the mapped graphics buffer. CSV profile import opens the profile write lock only for clear/parse commit.
Rejected Alternatives: Keeping mutable `TryResolveHandle` was rejected because it bypasses the write-lock contract for owned DataVault lanes. Holding params write-lock while every dependent route runs was rejected where it could be narrowed. Rewriting `ProceduralCoralVault` in the same pass was rejected because `TryScheduleGenerationPipeline` has no runtime call site and `TryResolveViews` call sites found in this pass are editor/debug windows only.
Scalability potential: Low devices now fail closed during compaction or missing Vault lanes instead of writing stale aliases; Middle keeps the existing sway cadence and constant-buffer path; High and Ultra can raise visual density or sway complexity later without changing DTO layout, BufferID identity, or authority route. Quality remains continuous through existing `GlobalQualityWeight`.
Hardware Impact: Runtime microseconds measured: 0. Static targeted proof removed mutable Vault resolve tokens and allocator/string/managed collection/job scheduling tokens from `FloraAmbientSwayRuntime`. On i3/MX350 the value is no stale DataVault alias writes in the ambient flora sway path; no frame-time or 0B GC runtime claim exists without Unity profiler data.
