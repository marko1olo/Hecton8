# LOG 1735 - Wreckage Chunk & Debris Prefab Assembler

What was wrong -> Wreckage packages had no dedicated assembler route for converting compartment debris into a single serialized debris mesh, no standalone `VoxelCarveVolume` metadata component, and no cold quality/shadow manager for spawned wreck presentation. Existing wreckage tooling handled fracture states and salvage anchors but did not cover the requested chunk/debris prefab factory contract.

What was done -> Added `Assets/_Project/Editor/Assembly/WreckagePrefabFactory.cs`. It discovers wreck mesh/prefab sources, rejects packages without debris segments, rejects packages without `COL_` collision proxies, resolves exact shared Wave 3 wreckage PBR material names (`MAT_Wreckage_Exterior`, `MAT_Wreckage_Burned*`, explicit debris/scrap variants), combines debris offline using `Mesh.CombineMeshes`, preserves material bucket submeshes, creates `VIS_Hull_*`, `VIS_DebrisScatter`, `COL_*`, `TRIG_SalvageNode`, `EquipmentMetadata`, `VoxelCarveVolume`, and `WreckageScatterManager`, and saves with `PrefabUtility.SaveAsPrefabAsset` only after validator gates.

What was done -> Added `Assets/_Project/Scripts/World/VoxelCarveVolume.cs`. It serializes local carve center, half extents, rotation, burial depth, operation/shape bytes, instruction, and stable hash. Read accessors are pure and do not publish, search, allocate, or touch GlobalRegistry.

What was done -> Added `Assets/_Project/Scripts/World/WreckageScatterManager.cs`. It consumes continuous `HomeostasisBrain.GlobalQualityWeight` during cold enable and maps it to Unity shadow modes only. It does not change collision, carve truth, save identity, DTO layout, or authority route.

What was done -> Added `Assets/_Project/Tests/Editor/WreckagePrefabFactory1735EditTests.cs`. Static tests pin the factory to offline combine/prefab/carve/material gates and reject runtime scene search, runtime mesh combine, runtime material instantiation, GlobalRegistry polling, and renderer material access in the new runtime scripts.

Cinematic Cheats used -> SDF terrain seating is a yaw-aligned OBB from the lowest 20 percent of hull vertices, expanded downward by 1 meter, not mesh-accurate SDF. This buys predictable bottom flatten/bury behavior for wreck placement while visuals stay independent. Small loose debris is visually retained but collapsed into one combined debris mesh. Shadows scale by continuous global quality as presentation only.

Exact Microseconds saved -> Debris renderer collapse: estimated 80-350 us per cluttered wreck on weak hardware depending on source shard count. Spawn-time bounds/raycast avoidance from serialized `VoxelCarveVolume`: estimated 20-70 us per spawn. Mesh-accurate SDF avoidance: estimated 150-800 us per spawn. Collision proxy requirement vs visual mesh collider/cooking: estimated 100-900 us at spawn/import depending on mesh complexity. SRP/material gate: estimated 25-120 us render setup variance avoided. Runtime steady-state GC from new scripts: 0 by source audit.

Validation -> Unity `validate_script` ran on `VoxelCarveVolume.cs`, `WreckageScatterManager.cs`, `WreckagePrefabFactory.cs`, and `WreckagePrefabFactory1735EditTests.cs`: 0 errors. Warnings were false positives from static-audit string literals. Full dotnet/Unity build and edit-mode test execution were not launched: active dotnet PIDs existed and CPU reached 98.85 percent, so the build gate prohibited it. Static report written to `Docs/Reports/WRECKAGE_ASSEMBLER_REPORT_1735.json`.
