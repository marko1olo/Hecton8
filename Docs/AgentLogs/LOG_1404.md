## 2026-05-28 Android Data Monolith PAL Bridge

What was wrong:
- Android/Quest cannot treat `Application.streamingAssetsPath/Hecton8/DataMonolith/static_data.h8bin` as a normal disk file inside APK/OBB packaging.
- Existing `H8StaticDataArena` preserved a Win32 native path and generic URI staging, but no Android NDK `AAssetManager` bridge existed.
- URI staging is not the requested architecture: it caches/copies instead of hydrating the DataVault arena directly.

What was done:
- Added Android-only branch in `H8StaticDataArena.TryInitializeFromStreamingAssets*` guarded by `UNITY_ANDROID && !UNITY_EDITOR`.
- Preserved existing Windows `CreateFileW`/`ReadFile` path and generic editor/unsupported FileStream fallback.
- Added JNI acquisition using `AndroidJavaClass("com.unity3d.player.UnityPlayer")` plus `AndroidJNI.GetStaticFieldID`, `GetStaticObjectField`, `GetObjectClass`, `GetMethodID`, `CallObjectMethodUnsafe`, and `GetJavaVM`.
- Added P/Invoke declarations for `H8_GetAssetSize` and `H8_LoadAssetToPointer` with explicit `JavaVM*` argument, Cdecl, and `I1` bool marshaling.
- Added native plugin source `Assets/Plugins/Android/Native/HectonAndroidAssetBridge.cpp`.
- Added `CMakeLists.txt` for `libHectonAndroidBridge.so`, C++17, linked against `android` and `log`.
- Added Gradle `androidResources { noCompress += ['h8bin'] }` so `.h8bin` is not packaged as a compressed APK entry and `externalNativeBuild` so the CMake shared library has a Gradle route.
- Added editor static audit script `H8AndroidAssetBridgeStaticAudit.cs`.
- Wrote proof artifact `Docs/Reports/ANDROID_PAL_OPTIMIZATION_REPORT_1404.json`.

Cinematic Cheats used:
- No physical simulation involved.
- Rejected runtime decompression/copy staging. Data path is a deterministic cold boot byte transfer into owner memory.

Pointer and native memory self-audit:
- C# resolves DataVault arena through existing `TryAllocateArena()` and acquires payload write access through `TryAcquireWriteLock`.
- Destination pointer is `NativeArrayUnsafeUtility.GetUnsafePtr(arena)` after capacity check.
- Asset name is stack-written ASCII/UTF-8; no P/Invoke string marshaling.
- C++ never allocates `std::vector`, `std::string`, `malloc`, or `new`.
- C++ rejects null `assetManager`, null filename, null destination, non-positive buffer, bad length, and `assetLength > bufferSize`.
- `AAsset_close` is called after size query, read success, overflow refusal, and short-read failure.
- No byte swapping, padding rewrite, or DTO mutation occurs in C++; bytes are copied as-is.
