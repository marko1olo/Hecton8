Exact microseconds saved:

- Menu route reflection removed in APEX re-audit: 0 us during simulation.

## 2026-05-28 - APEX Re-Audit

What was wrong:
- `QA_WatchdogBot.cs` released DataVault writer locks only on the success branch. A successful acquire followed by invalid buffer/slot or exception could strand a writer lock.
- Menu automation used `Object.FindObjectsByType<MonoBehaviour>` and reflection from the tick route before simulation. That produced an avoidable managed array search in the watchdog itself.
- `globalQualityWeight` was a local serialized field written to metadata only. It did not consume `HomeostasisBrain.GlobalQualityWeight`.

What was done:
- Wrapped metric and black-box `TryAcquireWriteLock` calls in `try/finally`, releasing with `ReleaseWriteLock` at lines 912 and 969 when `lockAcquired` is true.
- Replaced menu reflection/array search with direct `MainMenuController.StartGame(string.Empty)`, cached controller reference, and preallocated root traversal scratch.
- Added `_resolvedQualityWeight01` from `HomeostasisBrain.GlobalQualityWeight`; continuous `math.lerp` scales swim lateral/vertical perturbation amplitudes while thresholds and DTO layout stay invariant.
- Reran text scans on `SimulationHot` lines 618-1037 and `LateMetric` lines 738-1006: zero hits for reference-style `new`, `string.Format`, `.ToString()`, `foreach`, LINQ materializers, and scene-search APIs.

Cinematic cheats used:
- Navigation still uses deterministic triangle-wave input perturbation and KCC velocity feedback. No raycast obstacle solver was added.
- Low to ultra behavior is a continuous amplitude curve, not a binary tier branch.

Exact microseconds saved:
- Removed `Object.FindObjectsByType<MonoBehaviour>` route search: avoids a scene-wide managed array allocation and reflection invoke before simulation.
- DataVault lock fix is correctness-first; cost is one bool and one branch per vault write, estimated under 1 us.
- Four lerps for quality-scaled route motion replace any proposed PhysX avoidance; expected savings versus raycast avoidance remain 20-80 us/frame on i3/MX350.

Verification state:
- Build gate sampled `CPU_LOAD_PERCENT=99` with active `csc` process `43496` and active `dotnet` process `35512`; `dotnet build` was not launched.
- PlayMode endurance and fuzzer execution remain pending. Static proof only.

## 2026-05-28 - APEX Route/Metric Hygiene Follow-Up

What was wrong:
- Route state checks still risked string scene-name reads.
- Profiler frame-time fallback documentation still referenced `Time.unscaledDeltaTime`, and code had previously allowed Unity time as a fallback source.
- `SampleMetricHot` duplicated KCC/player freshness reads that `IntegrateDistanceHot` had already performed.
- Graphics-driver memory fallback could be evaluated even when `Gfx Used Memory` recorder data was valid.

What was done:
- Replaced hot route scene checks with build-index constants mapped to `EditorBuildSettings`: main menu `1`, orbit `2`, world `3`.
- `ReadRecorderMicroseconds` now falls back to `_lastFastDeltaTimeSeconds`, written only from validated dispatcher `FastTick` delta.
- `SampleMetricHot` consumes `_lastKccVelocityFresh` and `_lastPlayerStateFresh` cached from `IntegrateDistanceHot`.
- `Profiler.GetAllocatedMemoryForGraphicsDriver()` now executes only if `_gfxUsedRecorder.Valid` is false.
- Re-ran corrected literal-signature hot-path scan over `FastTickRouteAndSimulation` lines `436-1021`, `SimulationHot` lines `631-1021`, and `LateMetric` lines `755-1021`; all mandated filters returned zero.

Cinematic cheats used:
- No physical obstacle simulation was introduced. The bot still uses deterministic triangle-wave input perturbation plus KCC velocity feedback.
- Continuous `HomeostasisBrain.GlobalQualityWeight` changes only swim perturbation amplitude, not truth ownership, thresholds, DTO layout, or DataVault route.

Exact microseconds saved:
- Removed duplicated sampler freshness reads and an eager graphics fallback call on valid-recorder frames. Expected saving is small, but it reduces observer pressure on low-end CPUs.
- String route-name risk and Unity time fallback were removed from the hot proof surface; this is primarily correctness/evidence hygiene, not a large throughput win.
