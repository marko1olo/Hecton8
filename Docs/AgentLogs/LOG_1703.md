## 2026-06-02 - Zero-GC Tool Battery & Automation Purifier

What was wrong:
- Drone fleet used mock SDF truth (`BuildMockSdfGrid`, `MockSDFGrid`) and mock-named repair/mining service signals.

- Replaced mock drone service signal types with `DroneFleetRepairServiceSignal` and `DroneFleetMiningServiceSignal`.
- Removed runtime drone procedural material allocation; material must come from `RuntimeShaderReferenceCatalog`.
- Added GlobalQualityWeight presentation scaling for drone matrix uploads: low tier 4-frame cadence, high/ultra 1-frame cadence.
- Added extractor `IPostFixedTickable` completion window and 256-capacity ABI validation.
- Tool screen charge/heat text now writes through `stackalloc Span<char>` and `TMP_Text.SetCharArray()`.

Cinematic cheats used:
- Last Charge Clutch: below 1% charge, tool output gets a 2.5x final spike while physical battery truth still depletes to zero.
- Drone visual upload throttle: weak devices reuse previous GPU matrix buffers; gameplay state remains native and authoritative.

Exact microseconds saved:

- Single tool energy authority: estimated 0.4 us avoided by not creating a parallel battery buffer.
- Tool text path: 0 B/frame GC; avoided TMP managed string formatting.
- Drone fail-closed missing SDF path: skips full A*/cognition schedule when SDF authority is absent.
