# Rationale 2010

Task: Batch20 quality scalability matrix and proof checklist.
Evidence class: STATIC VERIFIED only.

## Decisions

1. Low/middle/high/ultra are review labels over continuous `GlobalQualityWeight`, not implementation authorities.
   - Reason: root law forbids binary quality switches and forbids quality changing gameplay truth, DTO layout, save identity, or authority route.

2. The existing `TOASTER/DECK/PRO/GOD_MODE` matrix was treated as useful static data, not final acceptance.
   - Reason: `Visual_Scalability_Matrix.json`, `VisualStressSim.py`, and tool output all declare offline/static evidence only.

3. The deliverable requires compact and high visual proof for every domain.
   - Reason: bibles require compact readability and high-tier sensory value without new truth.

4. The checklist requires graphics, optimization, and gameplay gates together.
   - Reason: root three-pillar acceptance rejects beautiful-empty, fast-flat, and complex-but-bad-performing work.

5. Black-box and profiler requirements were separated into a dedicated report.
   - Reason: critical visual proof needs last-300-frame state, state hashes, quality value, dump triggers, profiler markers, GC proof, and memory/VRAM proof.

6. No Assets changes were made.
   - Reason: user explicitly restricted work to deliverable docs and prohibited Unity/Assets modifications.

- Ocean single-pass code: static quality scaling and telemetry ring evidence.
- Shoreline foam code/doc: static quality scaling, 300 telemetry capacity, dump route.
- Toxic outgassing code: static quality resolution/cadence/sampling scaling, 300 telemetry capacity, NaN dump.

- World procedural validators: static LOD/crossfade/placeholder rejection checks.

## Remaining Risk

Static inspection cannot prove the scene looks good. Runtime proof must show surface, sky, Aegir, ocean, shoreline, shallows, medium depth, terrain, flora, ProductFace objects, and telemetry under compact and high lanes.
