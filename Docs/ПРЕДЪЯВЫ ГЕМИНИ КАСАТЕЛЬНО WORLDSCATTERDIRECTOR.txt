ЧАСТЬ 2: Анализ системы "Narrative AI Guidance / Atlas-6"

Ты описал новую систему: лорные POI кидают OnNarrativePOIRegistered, HectonNarrativeDirector держит список и отдает GetNearestUndiscoveredPOI(), а AI директор его дергает.

Самопроверка (Self-Check): Прав ли нейронка? Нет, тут есть огромные риски для Enterprise-релиза.

Риск 1: O(N) Nearest Search (Убийца Фреймрейта)
Если GetNearestUndiscoveredPOI тупо бежит по списку List<POIs> и считает Vector3.SqrMagnitude(player, poi), а у нас на карте 500 POI, и ИИ дергает это каждый кадр (или даже раз в 0.5с для толпы врагов/компаньонов) — это спайк CPU.
Решение: Нужен Spatial Partitioning. Идеально — Grid-базис (как у вас уже сделано в Scatter: ячейки ComposeScatterGridKey). ИИ должен проверять только соседние чанки.

Риск 2: Навигация сквозь стены (Евклидово расстояние vs NavMesh)
"Ближайший лорный объект" по sqrMagnitude может находиться за стеной пещеры в 10 метрах, тогда как реальный путь до него — 500 метров. ИИ "зависнет", пытаясь вести игрока в стену.
Решение: GetNearest должен сначала отфильтровать 3 ближайших по радиусу, а затем запустить асинхронный NavMesh.CalculatePath (или A* в вашей воксельной сетке), чтобы выбрать тот, к которому есть реальный путь.

Риск 3: Утечки памяти на событиях (Memory Leaks)
Если NarrativeDiscovery.cs делает подписку на глобальный NarrativeEvents, но объект уничтожается (например, при выгрузке чанка), а OnDisable не отработал из-за краша или хитрой логики пула — глобальный event сохранит ссылку на объект. GC его не соберет.
Решение: Использовать паттерн IObserver или явно регистрировать объект в реестре через интерфейс (как у вас сделано с пулами), а не через статичные C# events.

using System;
using System.Runtime.CompilerServices;
using UnityEngine;
using Unity.Collections;

namespace Hecton8.World
{
    /// <summary>
    /// [ENTERPRISE FIX] Замена старого CandidateMap.
    /// Старый CandidateMap использовал линейный поиск O(N) по массиву (for i=0 -> count).
    /// Этот класс использует хеширование с открытой адресацией (Linear Probing),
    /// обеспечивая поиск и вставку за O(1). 100% Zero-GC.
    /// </summary>
    public struct FastCandidateMap : IDisposable
    {
        private ScatterCandidate[] _values;
        private long[] _keys;
        private int[] _buckets; // Хранит индексы элементов. -1 значит пусто.
        
        public int Count { get; private set; }
        public int Capacity { get; private set; }
        private bool _disposed;

        public void Init(int capacity)
        {
            // Берем емкость с запасом (load factor ~0.7) для минимизации коллизий хэшей
            int bucketSize = HashHelpers.GetPrime(capacity * 2);
            
            _values = new ScatterCandidate[capacity];
            _keys = new long[capacity];
            _buckets = new int[bucketSize];
            
            for (int i = 0; i < bucketSize; i++)
                _buckets[i] = -1;

            Capacity = capacity;
            Count = 0;
            _disposed = false;
        }

        public void Dispose()
        {
            if (_disposed) return;
            _values = null;
            _keys = null;
            _buckets = null;
            Count = 0;
            _disposed = true;
        }

        [MethodImpl(MethodImplOptions.AggressiveInlining)]
        private int GetBucketIndex(long key)
        {
            // Перемешиваем биты ключа, чтобы избежать плохих хэшей
            ulong hash = (ulong)key;
            hash ^= hash >> 33;
            hash *= 0xff51afd7ed558ccd;
            hash ^= hash >> 33;
            hash *= 0xc4ceb9fe1a85ec53;
            hash ^= hash >> 33;
            return (int)(hash % (ulong)_buckets.Length);
        }

        public bool TryAdd(long key, ScatterCandidate value)
        {
            int bucketIdx = GetBucketIndex(key);

            // Linear probing для разрешения коллизий
            while (_buckets[bucketIdx] != -1)
            {
                int index = _buckets[bucketIdx];
                if (_keys[index] == key)
                {
                    _values[index] = value; // Replace
                    return true;
                }
                bucketIdx = (bucketIdx + 1) % _buckets.Length;
            }

            if (Count >= Capacity)
            {
#if UNITY_EDITOR || DEVELOPMENT_BUILD
                Debug.LogWarning($"[FastCandidateMap] Capacity exceeded ({Capacity}), key: {key}");
#endif
                return false;
            }

            // Вставка
            _keys[Count] = key;
            _values[Count] = value;
            _buckets[bucketIdx] = Count;
            Count++;
            return true;
        }

        public bool TryGetValue(long key, out ScatterCandidate value)
        {
            int bucketIdx = GetBucketIndex(key);

            while (_buckets[bucketIdx] != -1)
            {
                int index = _buckets[bucketIdx];
                if (_keys[index] == key)
                {
                    value = _values[index];
                    return true;
                }
                bucketIdx = (bucketIdx + 1) % _buckets.Length;
            }

            value = default;
            return false;
        }

        public void Clear()
        {
            if (Count == 0) return;
            
            // Очищаем только затронутые бакеты для ускорения (не чистим весь массив _buckets)
            for (int i = 0; i < _buckets.Length; i++)
            {
                _buckets[i] = -1;
            }
            Count = 0;
        }
        
        // Позволяет итерироваться по значениям без аллокаций
        public ReadOnlySpan<ScatterCandidate> GetValuesSpan()
        {
            return new ReadOnlySpan<ScatterCandidate>(_values, 0, Count);
        }
    }

    /// <summary>
    /// Утилита для вычисления простых чисел для размера хэш-таблицы (взято из .NET Core source)
    /// </summary>
    internal static class HashHelpers
    {
        public static readonly int[] Primes = {
            3, 7, 11, 17, 23, 29, 37, 47, 59, 71, 89, 107, 131, 163, 197, 239, 293, 353, 431, 521, 631, 761, 919,
            1103, 1327, 1597, 1931, 2333, 2801, 3371, 4049, 4861, 5839, 7013, 8419, 10103, 12143, 14591,
            17519, 21023, 25229, 30293, 36353, 43627, 52361, 62851, 75431, 90523, 108631, 130363, 156437
        };

        public static int GetPrime(int min)
        {
            for (int i = 0; i < Primes.Length; i++)
            {
                int prime = Primes[i];
                if (prime >= min) return prime;
            }
            return min | 1; // Fallback
        }
    }
}

Почему мы можем обосраться (Критические Риски Разбиения):

Потеря Zero-GC (Убийство Garbage Collector'ом):

Если ИИ разобьет логику на разные классы и начнет передавать эти коллекции через интерфейсы или IEnumerable, появятся аллокации (closures, boxing).

Рассинхрон Пайплайна (Execution Order):
В файле стоит [DefaultExecutionOrder(-4036)], и он завязан на кастомный ITickable / GameTickManager. Если ИИ предложит разбить систему на ScatterBudgetDirector, ScatterSpawningDirector и ScatterSamplingDirector (сделав их независимыми MonoBehavior'ами), порядок их тиков рассинхронизируется. Скаттер начнет спавнить объекты на основе данных из прошлого кадра.

Параметрический Ад:
Методы внутри (например, InjectRescuePlacementsIfNeeded) жрут по 30+ параметров. Если просто вынести этот метод в другой файл, придется прокидывать все 30 ссылок на массивы. Это нарушит инкапсуляцию и сделает код еще более хрупким.
