## 2026-05-25 CORE_MEMORY_WARDEN_AND_LOCK_SENTRY

What was wrong:
- `TryAcquireWriteLock` could publish `ActiveWriterSystemID` before the private block lock became visible. That gave compaction/growth a stale-pointer window.
- `TryLockBuffer` published pin state in an order that let active-mask checks and block lock checks disagree under contention.
- Arena growth could reach `H8Memory.ReallocateRaw` without proving `_activeLocks == 0` inside the final mutation window.
- Telemetry did not count locked compaction skips and cursor publication was not fully volatile/interlocked.
- No 1310-owned static proof artifact existed for lock/fence/reallocate invariants.

What was done:
- Added `_blockMutationGate` and moved active-lock-bit publication inside the gate before writer id or block pin publication.
- Hardened `TryAcquireWriteLock`, `ReleaseWriteLock`, `TryLockBuffer`, and `TryUnlockBuffer` with `Volatile`, `Thread.MemoryBarrier`, `Interlocked`, gated fresh block reads, and gated active-bit clear.
- Made live compaction own the block mutation gate, recheck active masks, skip locked/private-pinned/external-view blocks, increment `LockedSkipCount`, and request the 1310 dump on sync collision.
- Blocked arena growth under active masks/fence, queued `_deferredArenaGrowthBytes`, and rechecked masks inside the gate before `H8Memory.ReallocateRaw`.
- Rewrote `RecordDefragBlackBox` to use native pointer + `UnsafeUtility.MemCpy`; cursor/count publication uses volatile/interlocked operations.
- Added raw 1310 dump route: `Docs/AgentLogs/Dump_1310_MemorySentry.bin`.
- Added editor-only `OOP_MemorySentryConcurrentRelocationFuzzer` for 100,000-frame allocation/release/write-lock/pin/compaction stress.
- Added `Tools/OOP_MemorySentry_Scanner.py`; generated `Docs/Reports/MEMORY_SENTRY_OPTIMIZATION_REPORT_1310.json` with PASS / failedCount 0.

Cinematic cheats used:
- No simulated allocator physics. Relocation correctness is enforced by cheap masks, one mutation gate, and skip telemetry.
- Locked blocks are skipped instead of waited on. Visual/high-tier systems can buy more compaction cadence later; low-tier hardware stays fail-closed.

Exact microseconds saved / cost:
- Writer/pin admission: estimated +2-8 us uncontested atomic overhead, saving unbounded crash/retry cost from stale aliases.
- Failed arena growth gate: estimated ~3 us, saving full arena relocation and stale-pointer crash under active aliases.
- Locked compaction skip: estimated ~35 us per scan slice on low-end CPU, saving multi-ms stalls from waiting on locks.
- Telemetry write: estimated ~1.5 us native copy per entry, 0 B GC in hot path.

- `TryOpenAliasBuffer` now fails closed when `hadExternalView` is true or `meta.LastAliasRequester != SystemID.Unknown`.

- Report field `failClosedSummary.persistentAliasAdmission` records the policy.

Cinematic cheats used:
- No lifetime simulation, no managed lease object, no ref-count wrapper. The cheap deterministic route is single persistent alias admission, then fail-closed until explicit unmanaged lease support exists.
