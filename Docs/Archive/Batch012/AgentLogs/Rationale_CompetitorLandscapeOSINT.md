# CompetitorLandscapeOSINT Rationale

Date: 2026-05-23
Evidence class: WEB_OSINT + STATIC_DOC
Scope: Competitor and workflow landscape only. No source code, Unity assets, project settings, or runtime systems changed.

Problem: HECTON-8 needs a factual read on whether underwater/deep-sea survival horror/simulation competitors exist and whether the market/community is saturated.
Solution: Split competitors by player promise instead of store tags: underwater survival-craft, submarine/systems co-op, deep-sea horror narrative, ocean survival-adjacent, and AI-agent workflow accelerants. This avoids false equivalence between Subnautica 2, Barotrauma, SOMA, Dave the Diver, and Dredge.
Rejected Alternatives: A single broad "underwater games" list was rejected because it hides threat vectors. Steam tag scraping alone was rejected because tags do not prove market weight, community demand, or production risk.
Scalability potential: Low-tier market angle is stable performance on commodity GPUs with strong fog/noir fakes. Middle-tier angle is readable systemic survival and strong moment-to-moment exploration. High-tier angle is denser bioluminescence, richer post, and longer LOD residency. Ultra-tier angle is visual overkill without changing gameplay truth ownership.
Hardware Impact: Runtime impact is 0 microseconds. This is research. No code path changed. Strategic impact is risk reduction only; not profiler-measurable.

Problem: Subnautica 2 has changed the category baseline in May 2026.
Solution: Treat Subnautica 2 as the critical threat and market proof. It launched Early Access on 2026-05-14, is 4-player co-op, and public reports show multi-million first-week sales. HECTON-8 cannot win by being "Subnautica but darker"; it needs differentiated NASA-punk industrial horror, systemic pressure/vehicle/habitat credibility, and deterministic fake-first performance discipline.
Rejected Alternatives: Competing directly on cozy alien reef wonder was rejected. That lane is occupied and heavily community-owned by Unknown Worlds.
Scalability potential: Low/Middle tiers must sell atmosphere and clarity without expensive full volumetrics. High/Ultra tiers must spend saved budget on dense abyssal light, machinery, fog stratification, and creature presence.
Hardware Impact: Runtime impact is 0 microseconds. Future production implication: keep MX350 viability as a differentiator against heavier modern competitors.

Problem: AI-agent-assisted development changes competitor throughput.
Solution: Treat GitHub Copilot agent, OpenAI Codex, Devin, Replit Agent, Cursor, and Unity AI as workflow competitors because they reduce prototyping, porting, testing, and content-iteration friction for rival teams.
Rejected Alternatives: Treating AI tools as irrelevant because they are not games was rejected. Production velocity is a competitive surface. Treating them as automatic quality was also rejected; public sources still show governance, review, and safety limits.
Scalability potential: Low-tier: AI can help small teams create broad but shallow prototypes. Middle-tier: teams can ship more content updates. High/Ultra: studios with disciplined review loops can combine agents with profiling, asset pipelines, and automation.
Hardware Impact: Runtime impact is 0 microseconds. Production impact is process velocity only.
