# LOG 1607 - Modular Station and Structure Architect

## 2026-06-01 - Offline Station Fabricator Implementation

What was wrong:
- Deep Reach modular bases had no dedicated offline station fabricator under `Assets/_Project/Editor/Generators/Structures/`.
- Existing module prefabs had authored `ModuleSocket` data, but no station-scale WFC route, no socket-gated hidden-plane removal, no seam welding proof, and no single-mesh prefab bake path.
- Runtime/scene assembly would preserve hundreds of transforms/renderers and leave buried polygons on module joins.

What was done:
- Added `DeepReachStationContracts.cs`: explicit unmanaged DTOs, deterministic math, Burst `StationWfcSolverJob`, `StationMeshFusionJob`, `StationVertexWeldingJob`, and `StationProceduralDamageJob`.
- Added `DeepReachStationModuleLibrary.cs`: scans construction prefabs, extracts `ModuleSocket` directions/compatibility masks, reads meshes/materials, tags socket boundary triangles, and returns analysis DTOs without proof-report writes.
- Added `DeepReachStationFabricator.cs`: runs WFC, fuses geometry, removes socket-hidden faces, welds seams, bakes damage vertex colors, writes `.mesh` and `.prefab` assets, and keeps bake metrics in `StationBakeCountersDTO`.
- Added `DeepReachStationArchitectWindow.cs`: Editor UI for seed, grid, module cap, quality weight, weld epsilon, fail-closed behavior, ledger, and metric output.
- Added `DeepReachStationArchitectEditTests.cs`: DTO stride checks, deterministic seed assertion, 100-placement budget fuzzer, hidden-face cull assertion, seam weld assertion, and static source scan.
- Added `Hecton8.Project.Editor` reference in `Hecton8.EditModeTests.asmdef`; added `Unity.Jobs` reference in `Hecton8.Project.Editor.asmdef`.
- Fixed compile-surfaced issues: missing `Unity.Jobs` import/reference and readonly `using` variable writes on `NativeArray` values.

Cinematic cheats used:
- Station shape uses deterministic ellipsoid/noise WFC volume instead of expensive graph search.
- Damage uses seeded scalar spheres and vertex-color masks, not runtime decals or physical hull simulation.
- Dirt/rust/algae are baked to vertex colors; shader/material can consume masks later without gameplay CPU.
- Hidden faces are removed by authored socket direction masks, not by runtime occlusion or per-frame visibility.

Exact microseconds saved:
- Runtime WFC: removed from gameplay path; estimate 1.8 us per baked module.
- Hidden triangles: estimate 0.11 us per culled seam triangle.
- Welded seam vertices: estimate 0.06 us per merged duplicate vertex.
- Transform/render hierarchy: one generated renderer path replaces per-module renderer submission; exact value pending prefab bake metrics.

Verification:

- Console after fix: no 1607 compiler errors remain.
- Blocking external errors observed after 1607 fixes: `Assets/_Project/Tests/Editor/OrbitalSkyEphemerisDrift1601EditTests.cs` missing `CelestialRuntimeSnapshot`, then `Assets/_Project/Scripts/Vehicles/DropPod/DropPodSeatController.cs` missing `TryRegisterLate`.

## 2026-06-01 - Weld Hash and Damage Normal Polish

What was wrong:
- `StationVertexWeldingJob` used modulo in the bucket probing path even though fabricator bucket capacity is power-of-two.
- Direct job calls with a non-power-of-two bucket buffer could produce uneven probing instead of failing the weld contract immediately.
- `StationProceduralDamageJob` used imported normal length for crush displacement and algae bias; malformed normals could over-deform a baked hull.

What was done:
- Added missing-array and power-of-two bucket validation before weld probing.
- Replaced bucket/probe `% bucketCount` with `BucketSlot` and `ProbeSlot` bitmask addressing.
- Added EditMode proof `Welding_FailsClosedWhenBucketCountIsNotPowerOfTwo`.
- Added AST proof `VertexWelding_UsesPowerOfTwoBucketMaskInsteadOfModuloDivision`.
- Normalized source normals in `StationProceduralDamageJob` before displacement and mask encoding.
- Added EditMode proof `DamageBake_NormalizesOversizedInputNormalsBeforeDeforming`.
- Added AST proof `DamageBake_NormalizesSourceNormalsBeforeCrushAndMask`.

Cinematic cheats used:
- Damage remains offline scalar sphere deformation with bounded normalized displacement, not runtime physics or decals.
- Seam repair remains deterministic spatial hash probing, not O(N^2) geometric comparison.

Exact microseconds saved:
- Runtime: 0 direct runtime us because all work stays Editor-only.
- Offline weld probing: removes two modulo divisions per bucket probe; estimated 0.02-0.05 us per 1,000 seam probes on low-end CPUs, pending profiler.
- Offline deformation: adds one normal normalization per baked vertex to buy content safety; runtime visual result is stable with no gameplay cost.

- `CreatePrefabAsset` assigned one `sharedMaterial`, so mixed construction modules lost authored structural material separation.

- Changed `CreateMeshAsset` to build a material-sorted native index buffer and emit one active submesh per used material slot.
- Changed prefab save path to assign `renderer.sharedMaterials`.
- Added behavior tests for fusion material propagation and welding material propagation.
- Added static APEX tests rejecting the old one-submesh/one-material path.

Cinematic cheats used:
- Materials remain authored structural slots, but rejected glass/leak/ghost/scan surfaces collapse to the deterministic grime fallback instead of carrying fragile visual-only materials into the monolithic station hull.
- Submesh sorting is offline; gameplay receives one static mesh renderer with no material routing work.

Exact microseconds saved:
- Runtime: 0 direct runtime work added.
- Avoided child renderers: keeps station submission to one renderer path; estimated savings is transform/render traversal avoided for each material-bearing module child, pending Unity Stats after CPU gate opens.
- Offline sort cost: O(triangle count) native pass during bake only.

Verification:

## 2026-06-01 - WFC Closed-Face Compatibility Polish

What was wrong:
- `BuildCompatibleMask` treated `currentSocket == 0` as compatible only with Empty.
- That falsely turned sealed horizontal adjacency into a contradiction, forcing modules to expose sockets on ordinary side walls or causing bake failure.
- A broad fix would be dangerous because top/bottom closed faces must not allow vertical module stacking.

What was done:
- Added `CanClosedFacesAbut(direction)` and `ModuleHasClosedFace(...)`.
- Updated `BuildCompatibleMask` to allow sealed-to-sealed neighbors only on horizontal directions.
- Updated `RotationFitsCollapsedNeighbors` with the same horizontal sealed-face rule.
- Left `StructuralSocketsCompatible` unchanged, so graph connectivity remains socket-only.
- Added an APEX static test proving horizontal sealed abutment and top/bottom stack rejection.

Cinematic cheats used:
- This is a station topology rule, not a visual simulation. The deliberate cheat is preserving sealed side bays as static baked geometry instead of requiring fake connector sockets.

Exact microseconds saved:
- Runtime: 0 direct runtime work added.
- Offline: prevents false WFC contradiction exits and failed bake retries; exact editor time saved depends on station seed and module vocabulary.

Verification:
- Raw brace counts are balanced for `DeepReachStationContracts.cs`.
- `git diff --check` returned clean for station contracts and APEX tests.
- Forbidden hot-path dependency and lock tokens remain absent from station generator sources.
- APEX test now asserts `StructuralSocketsCompatible` does not call `CanClosedFacesAbut`, preserving socket-only graph connectivity.
