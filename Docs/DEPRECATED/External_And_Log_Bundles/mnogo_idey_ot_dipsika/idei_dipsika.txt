🛠️ RAZDEL 1. TEHNIChESKAYa ChAST: OPTIMIZATsIYa I RENDERING
Tema: GPU Instancing (Grabli i resheniya)

S GPU Instancing mozhno oblazhatsya po-krupnomu, osobenno kogda kazhetsya, chto vse sdelal pravilno. Spisok grabley, kotorye neobhodimo proveryat.

1. Konflikt s SRP Batcher (Glavnaya zhirnaya grablya)

Ispolzuetsya URP — po umolchaniyu vklyuchen SRP Batcher. On imeet bezuslovnyy prioritet nad GPU Instancing. Esli obekt sovmestim s SRP Batcher, Unity budet ispolzovat ego, polnostyu ignoriruya galochku "Enable Instancing".

Kak eto lechit (2 puti):

Prinuditelno "slomat" sovmestimost sheydera s SRP Batcher. Delaetsya cherez #pragma direktivy v sheydere ili cherez Material API v kode.

Ispolzovat MaterialPropertyBlock. Pri ego ispolzovanii SRP Batcher mozhet "slomatsya", i togda GPU Instancing vklyuchitsya avtomaticheski.

Kak proverit: Frame Debugger. Vyberi lyuboy kadr i ubedis, chto tvoi obekty risuyutsya kak "Draw Mesh (instanced)" (paketami), a ne kak "SRP Batch".

2. Sheydery i Materialy

Sheyder ne podderzhivaet instansing: Samaya rasprostranennaya prichina. Esli v inspektore materiala galochka "Enable GPU Instancing" seraya ili ee net — sheyder ne podderzhivaet etu tehnologiyu.

Sheyder ignoriruet instansing: Sheyder napisan s podderzhkoy, no iz-za baga drayvera ili oshibki v sheydere ignoriruet ee. Vyzyvaetsya DrawIndexedInstanced s InstanceCount = 1 (huzhe, chem bez optimizatsii).

Raznye materialy na odinakovyh obektah: Instansing rabotaet tolko esli vse obekty ispolzuyut odin i tot zhe asset materiala. Kopiya cherez Duplicate dlya GPU — uzhe drugoy material.

Raznye svoystva v MaterialPropertyBlock: Popytka izmenit cherez MPB svoystvo, kotoroe ne obyavleno kak UNITY_INSTANCING_PROP v sheydere, polomaet batching.

3. Platformy i Zhelezo

Nepodderzhivaemaya platforma: Ne rabotaet na staryh GPU ili API (naprimer, OpenGL ES 2.0 / WebGL).

Apparatnye ogranicheniya drayvera: Bagi v drayverah konkretnyh ustroystv mogut lomat tehnologiyu.

Limit na kolichestvo instansov: V odnom draw call maksimum 500-1023 instansov. 5000 obektov razobyutsya na ~10 paketov.

4. Meshi i Verteksy

Slishkom malo poligonov: Pravilo «ne ispolzuy instansing dlya meshey s < 256 verteksami». GPU ne mozhet effektivno rasparallelit rabotu, proizvoditelnost upadet.

Slishkom mnogo instansov (oshibka logiki): Dlya 5-10 obektov vyigrysh nulevoy, a nakladnye rashody uhudshat FPS.

5. Protsedurnaya generatsiya i Skripty

Oshibki v Graphics.DrawMeshInstanced: Slozhnyy metod. Nepravilnyy razmer bufera ili bitye matritsy vedut k padeniyu proizvoditelnosti ili krashu.

Nesovmestimost s SkinnedMeshRenderer: Instansing NE RABOTAET s animirovannymi meshami.

✅ Ekstrennaya diagnostika (Poshagovyy chek-list):

Prover "Enable GPU Instancing" na materiale.

Prover Frame Debugger: dolzhno byt Draw Mesh (instanced) s chislom v skobkah.

Prover konsol na oshibki/varningi pri zapuske stseny.

Prover sheyder: nalichie #pragma multi_compile_instancing, makrosov UNITY_INSTANCING_BUFFER_START, UNITY_DEFINE_INSTANCED_PROP, UNITY_SETUP_INSTANCE_ID.
(Esli vse soblyudeno, no ne rabotaet — pisat bagreport v Unity s prilozhennym Frame Debugger).

public class ModLoader : MonoBehaviour
{
    void Awake()
    {
        string modsPath = Path.Combine(Application.dataPath, "../Mods");
        foreach (string dll in Directory.GetFiles(modsPath, "*.dll"))
        {
            var assembly = Assembly.LoadFrom(dll);
            var modTypes = assembly.GetTypes().Where(t => typeof(IMod).IsAssignableFrom(t));
            foreach (var type in modTypes)
            {
                IMod mod = (IMod)Activator.CreateInstance(type);
                mod.Initialize();
                Debug.Log($"Loaded mod: {mod.Name} v{mod.Version}");
            }
        }
    }
}
