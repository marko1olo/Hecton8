🛠️ РАЗДЕЛ 1. ТЕХНИЧЕСКАЯ ЧАСТЬ: ОПТИМИЗАЦИЯ И РЕНДЕРИНГ
Тема: GPU Instancing (Грабли и решения)

С GPU Instancing можно облажаться по-крупному, особенно когда кажется, что всё сделал правильно. Список граблей, которые необходимо проверять.

1. Конфликт с SRP Batcher (Главная жирная грабля)

Используется URP — по умолчанию включен SRP Batcher. Он имеет безусловный приоритет над GPU Instancing. Если объект совместим с SRP Batcher, Unity будет использовать его, полностью игнорируя галочку "Enable Instancing".

Как это лечить (2 пути):

Принудительно "сломать" совместимость шейдера с SRP Batcher. Делается через #pragma директивы в шейдере или через Material API в коде.

Использовать MaterialPropertyBlock. При его использовании SRP Batcher может "сломаться", и тогда GPU Instancing включится автоматически.

Как проверить: Frame Debugger. Выбери любой кадр и убедись, что твои объекты рисуются как "Draw Mesh (instanced)" (пакетами), а не как "SRP Batch".

2. Шейдеры и Материалы

Шейдер не поддерживает инстансинг: Самая распространенная причина. Если в инспекторе материала галочка "Enable GPU Instancing" серая или её нет — шейдер не поддерживает эту технологию.

Шейдер игнорирует инстансинг: Шейдер написан с поддержкой, но из-за бага драйвера или ошибки в шейдере игнорирует её. Вызывается DrawIndexedInstanced с InstanceCount = 1 (хуже, чем без оптимизации).

Разные материалы на одинаковых объектах: Инстансинг работает только если все объекты используют один и тот же ассет материала. Копия через Duplicate для GPU — уже другой материал.

Разные свойства в MaterialPropertyBlock: Попытка изменить через MPB свойство, которое не объявлено как UNITY_INSTANCING_PROP в шейдере, поломает батчинг.

3. Платформы и Железо

Неподдерживаемая платформа: Не работает на старых GPU или API (например, OpenGL ES 2.0 / WebGL).

Аппаратные ограничения драйвера: Баги в драйверах конкретных устройств могут ломать технологию.

Лимит на количество инстансов: В одном draw call максимум 500-1023 инстансов. 5000 объектов разобьются на ~10 пакетов.

4. Меши и Вертексы

Слишком мало полигонов: Правило «не используй инстансинг для мешей с < 256 вертексами». GPU не может эффективно распараллелить работу, производительность упадет.

Слишком много инстансов (ошибка логики): Для 5-10 объектов выигрыш нулевой, а накладные расходы ухудшат FPS.

5. Процедурная генерация и Скрипты

Ошибки в Graphics.DrawMeshInstanced: Сложный метод. Неправильный размер буфера или битые матрицы ведут к падению производительности или крашу.

Несовместимость с SkinnedMeshRenderer: Инстансинг НЕ РАБОТАЕТ с анимированными мешами.

✅ Экстренная диагностика (Пошаговый чек-лист):

Проверь "Enable GPU Instancing" на материале.

Проверь Frame Debugger: должно быть Draw Mesh (instanced) с числом в скобках.

Проверь консоль на ошибки/варнинги при запуске сцены.

Проверь шейдер: наличие #pragma multi_compile_instancing, макросов UNITY_INSTANCING_BUFFER_START, UNITY_DEFINE_INSTANCED_PROP, UNITY_SETUP_INSTANCE_ID.
(Если всё соблюдено, но не работает — писать багрепорт в Unity с приложенным Frame Debugger).

public class ModLoader : MonoBehaviour
{
    void Awake()
    {
        string modsPath = Path.Combine(Application.dataPath, "../Mods");
        foreach (string dll in Directory.GetFiles(modsPath, "*.dll"))
        {
            var assembly = Assembly.LoadFrom(dll);
            var modTypes = assembly.GetTypes().Where(t => typeof(IMod).IsAssignableFrom(t));
            foreach (var type in modTypes)
            {
                IMod mod = (IMod)Activator.CreateInstance(type);
                mod.Initialize();
                Debug.Log($"Loaded mod: {mod.Name} v{mod.Version}");
            }
        }
    }
}
Шаг 4. Безопасность и изоляция

AppDomain Sandboxing: Загрузка с PermissionState.None для блокировки ФС/сети.

Валидация: Серверная валидация критичных действий (фальшивый локальный сервер), проверка дубликатов ID.

UnityGuard: Интеграция статического анализатора для блокировки вызовов вроде File.Delete.
