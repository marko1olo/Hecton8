🌊 3. ФИЗИКА, ИИ И ПЕРЕМЕЩЕНИЕ
Что говорят в чатах:
CharacterController (CC) лучше для игрока в опенворлде (плавность, ступеньки, паркур), чем Rigidbody (RB), который дрожит и застревает на стыках мешей.
Быстрый транспорт на RB прошивает стены (эффект туннелирования). Решение: Collision Detection -> Continuous Speculative.
Для добычи ресурсов: Mesh Swap. Целый камень статичен -> при ударе меняется на префаб кусков с RB -> через 3-5 секунд физика кусков отключается (isKinematic = true), остается только триггер подбора.
Для 3D-ИИ под водой: NavMesh не работает, обычный Physics.OverlapSphere жрет CPU. Нужно Octree (Октодеревья) или Пространственное хеширование (Spatial Hashing).
Реальность HECTON-8:
Мы уже молодцы: У нас Continuous Speculative на игроке. У нас есть HarvestableOutcrop. У нас есть Spatial Hashing для воксельного пола (VoxelSpawnPointJob).
Где мы облажались: Игрок работает на гибридном Rigidbody. Мы потратили уйму времени на борьбу с джиттером. FaunaSensorSuite и HectonDirectorAI всё еще используют OverlapSphereNonAlloc.
✅ ЧТО ВНЕДРЯЕМ (Задачи для Кодера):
Оптимизация добычи руды (Mesh Swap & Sleep): Переработать логику HarvestableOutcrop. При разрушении спавнятся куски с Rigidbody. Внедрить жесткий компонент-таймер: через 4 секунды после спавна лута вызывать Rigidbody.isKinematic = true и Collider.enabled = false (оставив только Trigger для подбора). Океан не должен обсчитывать физику валяющегося мусора.
Снижение частоты SphereCast для ИИ: Пока мы не перешли на Octree (это слишком сложно сейчас), нужно жестко разнести OverlapSphereNonAlloc у монстров по времени (Time Slicing). Монстры не должны сканировать сферу в один и тот же кадр. Использовать GetInstanceID() % frames для размазывания нагрузки по SlowTick.
Оставить Rigidbody-игрока в покое: Да, в чате советуют CharacterController, но мы уже убили недели на полировку HectonPlayerMovement с плавучестью, инерцией воды и Crest Ocean. Переписывать ядро мувмента сейчас — это смерть проекта. Игнорируем совет по CC для игрока, применяем RB-советы для транспорта.

Трюк с [field: SerializeField]:

Совет из чата: Использовать эту конструкцию для автоматических свойств.

Применение в HECTON-8: Позволяет делать поля доступными для чтения извне (public), но редактируемыми только в инспекторе, не создавая лишних private переменных.

IDisposable и «Событийная гигиена»:

Совет из чата: Если класс — не MonoBehaviour (например, наш InventoryGrid или PowerGrid), он обязан реализовывать IDisposable.

Применение в HECTON-8: У нас много систем, которые подписываются на события. Если игрок выходит в меню и возвращается, старые подписки могут остаться в памяти, вызывая утечки и фантомные вызовы.

🚤 2. ФИЗИКА И ДВИЖЕНИЕ (Секрет «Дорогого» ощущения)

В чате обсуждали, как сделать управление «вкусным». Для подводного выживача это 90% иммерсии.

Raycast-подвеска (Hovering System):

Совет из чата: Объект не должен касаться дна коллайдером. Нужно использовать 4 луча снизу, которые создают выталкивающую силу.

Velocity vs Force:

Совет из чата: Не использовать AddForce для постоянного движения.

Применение в HECTON-8: Для плавного плавания лучше напрямую управлять rigidbody.linearVelocity, но пропускать ввод через Vector3.SmoothDamp.

Борьба с туннелированием:

Совет из чата: Continuous Speculative — самый дешевый и надежный режим для быстрых объектов.

ЗАДАЧА: Проверить все снаряды (гарпун, пули) и транспорт. Убедиться, что режим коллизий не Discrete.

🐟 3. ИИ И ЭКОСИСТЕМА (Живой, но дешевый океан)

В середине логов есть гениальные советы по оптимизации толпы. На MX350 мы не можем позволить себе 100 «умных» акул.

Разделение Intent (Намерения) и Trajectory (Траектории):

Совет из чата: Глобальное поведение (мозг) решает «КУДА», а Steering Behaviors решают «КАК».

Применение в HECTON-8: Наш FaunaBrain сейчас слишком тяжелый.

ЗАДАЧА: Разделить мозг фауны. Мозг (FSM) тикает раз в 0.5с (SlowTick) и ставит целевую точку. А мелкий скрипт SteeringEngine каждый кадр плавно поворачивает рыбу к этой точке, обходя препятствия через простые рейкасты.

Spatial Hashing вместо Distance():

Совет из чата: Для 500 рыб не использовать Vector3.Distance.

ЗАДАЧА: Реализовать простую сетку в FaunaDirector. Рыбы должны искать соседей или игрока только в своей ячейке сетки. Это превращает нагрузку из квадратичной в линейную.

IK (FABRIK) для существ:

Совет из чата: Ноги крабов должны идеально стоять на рельефе.

ЗАДАЧА: Для крупных донных существ внедрить Unity Animation Rigging. Использовать лучи вниз для каждой лапы, чтобы конечности адаптировались к камням, а не проходили сквозь них.

Screen Space Cavity (Микро-рельеф):
