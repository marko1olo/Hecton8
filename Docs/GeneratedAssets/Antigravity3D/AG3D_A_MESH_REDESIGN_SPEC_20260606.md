# AG3D-A Mesh Redesign Specification

## 1. Geology: Quadric Error Metric Decimation and Silhouette Preservation
The primary failure in the generative geology pipeline stems from naive vertex collapse during the Level of Detail (LOD) generation phases. The current algorithm simply collapses the shortest edges iteratively, entirely ignoring the visual importance of boundary vertices and high-curvature ridges. To rectify this, the pipeline must implement a Quadric Error Metric (QEM) based decimation strategy. Before any edge collapse is evaluated, a pass must be executed to calculate the discrete Gaussian curvature at every vertex. Vertices exhibiting high curvature, specifically those forming the outer silhouette from orthographic projection axes, must be assigned a mathematical protection weight. The QEM matrix cost function must be multiplied by this protection weight, ensuring that the algorithm penalizes the collapse of silhouette-defining edges exponentially higher than coplanar internal edges. Furthermore, the decimation must enforce normal preservation; if an edge collapse results in an adjacent face normal deviating by more than 15 degrees from its original orientation, the collapse must be rejected. This process must be integrated directly into the `WorldGenerativeGeologyMeshBuilder.cs` static utility class, overriding the default Unity decimation library entirely to guarantee strict 0 B/frame runtime adherence. The generated LOD1 and LOD2 meshes will inherently possess higher vertex counts along sharp ridges while drastically reducing geometry in flatter planar areas, satisfying both the topology budget and the aesthetic requirement for rock formations to retain their distinctive shapes at abyssal distances.

## 2. Geology: Contact Shadows and Hemispherical Raycasting
A critical aesthetic flaw in the procedural rock generation is the visual disconnect between the base of the rock meshes and the seafloor terrain. Because dynamic ambient occlusion is disabled in the Hecton-8 photic zones for performance reasons, rocks appear to float even when perfectly grounded. The solution requires an offline ambient occlusion baking process encoded directly into the vertex colors. For every vertex situated within the lower 20 percent of the mesh bounding box (the local Y-axis minimum), the algorithm must cast a hemisphere of 64 rays directed downward and outward relative to the local face normal. The ray hits must be evaluated against the mesh itself and a localized proxy ground plane. The inverse proportion of unobstructed rays dictates the occlusion factor. This factor, ranging from 0.0 (fully occluded) to 1.0 (fully exposed), must be written exclusively into the blue channel of the vertex color data array. The Hecton-8 environment shader will read this blue channel specifically as a multiplier against the indirect lighting buffer. To ensure smooth transitions, a secondary diffusion pass must average the occlusion values of adjacent vertices across three iterations, smoothing the baked shadow gradient. This eliminates the 'floating' artifact entirely without introducing a single byte of runtime overhead or relying on screen-space post-processing.

## 3. Geology: Boolean Unions on Procedural Clusters
The `PFB_family_rock_cluster_medium__cluster` generation logic relies on instantiating multiple primitive rock SDFs (Signed Distance Fields) and meshing them concurrently. However, the current marching cubes implementation treats the overlapping volumes as distinct shells, resulting in massive amounts of internal geometry and horrific z-fighting where faces intersect precisely. To resolve this, the procedural builder must perform a Constructive Solid Geometry (CSG) boolean union on the volumetric data *before* the marching cubes algorithm extracts the isosurface. When merging the localized SDF grids of two adjacent rock primitives, the pipeline must evaluate the `min(SDF_A, SDF_B)` function at every voxel. This mathematical union guarantees that the resulting combined SDF describes a single, continuous, and manifold external hull. Consequently, the subsequent marching cubes pass will only generate triangles on the exposed outer boundary, completely omitting the internal intersecting faces. This redesign not only eliminates the visual z-fighting artifacts but also drastically reduces the final vertex count of the cluster prefabs, reclaiming valuable polygon budget that can be reallocated to higher-fidelity silhouette features. The static mesh validator must be updated to explicitly check for internal shells by utilizing a volume-filling winding number evaluation, failing the build if internal geometry is detected.

## 4. Cave Systems: Toroidal SDF Subtraction for Overhangs
Cave entrances generated by the current system transition too abruptly from flat rock walls to empty space, resembling cleanly drilled tunnels rather than natural erosion or pressure fractures. The redesign requires modifying the `WorldCaveDirector.cs` script to implement a secondary, localized SDF carving pass focused exclusively on the entrance perimeter. The system must define a procedural torus primitive, scaled and oriented to match the entrance aperture. Instead of a perfect geometric torus, the SDF mathematical definition must be perturbed by a 3D noise function, scaling the major and minor radii dynamically along the polar angle. This deformed torus SDF must then be subtracted from the primary rock wall SDF using the `max(SDF_Wall, -SDF_Torus)` boolean difference operation. By carefully tuning the minor radius of the torus, this subtraction carves away the hard edge of the tunnel hole, creating an irregular, rounded, and overhanging lip that blends organically into the surrounding geology. The noise perturbation ensures that the lip varies in thickness and depth, simulating uneven rock composition collapsing under water pressure. This approach strictly adheres to the offline-only generation mandate while vastly improving the visual fidelity of the critical transition zones between open ocean and claustrophobic cave environments.
## 5. Cave Systems: Winding Order Verification and Inverted Normals
A persistent rendering bug involves procedural shafts within cave networks displaying inverted normals on interior faces, causing backface culling to completely erase sections of the geometry when viewed from inside. This occurs because the marching cubes triangulator occasionally misinterprets the sign gradient of the SDF field near complex intersection points. To rectify this, the pipeline must implement a robust winding order verification pass. After triangulation, the algorithm must identify distinct logical shaft components by performing a breadth-first search across the connected graph of vertices. For each identified shaft segment, a geometric centroid is calculated. Then, a vector is cast from the centroid to the center of every triangle belonging to that segment. The dot product is calculated between this outward-pointing vector and the face normal defined by the triangle's vertex winding order. If the dot product is positive, it indicates the normal is pointing away from the interior space. The algorithm must automatically swap the second and third vertices of the triangle, flipping the winding order and inverting the normal. This guarantees that all interior cave surfaces face inward towards the camera, completely eliminating the visual gaps and shading errors without relying on expensive two-sided rendering materials.

## 6. Flora: Internal Cavity Subtraction for Porous Corals
The massive coral structures (`PFB_family_coral_massive__porous`) currently read as solid, heavy lumps of rock rather than intricate, porous biological organisms. Displacement maps alone are insufficient at grazing angles. The generation specification must mandate true volumetric subtraction. The pipeline must generate a 3D cellular noise field (specifically, Worley noise with inverted distance functions) mapped to the bounding volume of the coral mass. A threshold is established; values exceeding this threshold represent internal cavities. The algorithm performs a CSG boolean subtraction, carving out these spherical and irregular noise cavities from the primary coral SDF. Crucially, the noise field parameters must scale radially, with higher density and larger cavities concentrated near the exterior surface, gradually transitioning to solid structure near the core to maintain structural integrity. To prevent the polygon count from exploding uncontrollably, the marching cubes resolution must be adaptively scaled, utilizing a coarser grid for the internal cavity surfaces while maintaining high resolution on the exterior silhouette. This generates genuine hollow structures that light can pass through, satisfying the rigorous visual demands for reef biomes.

## 7. Flora: Recursive L-System Branching with Radius Tapering
The current branching coral generation uses simple linear extrusion that produces rigid, pipe-like structures with uniform thickness, lacking any biological plausibility. The redesign dictates the implementation of a full recursive L-system. The L-system grammar must encode forward extrusion, pitch rotation, yaw rotation, and branching forks. Most importantly, the execution interpreter must maintain a recursion depth variable. The radius of the generated cylindrical mesh at any given point must be defined as `BaseRadius * (TaperFactor ^ Depth)`. The `TaperFactor` is a constant typically set around 0.85. As the L-system branches recursively outward, each subsequent branch segment exponentially narrows, accurately simulating natural growth constraints. Furthermore, at terminal branch points (where maximum recursion depth is reached), the geometry must cap with a rounded hemisphere scaled to match the final calculated radius, rather than a flat, clipped polygon. This mathematical tapering drastically improves the organic appearance of the coral assets and naturally reduces the polygon density at the chaotic extremities.

## 8. Flora: Flow-Field Aligned Procedural Leaning
Tall kelp and aquatic plant structures exhibit static, rigid poses that contradict the dynamic ocean environment. Generating pre-bent meshes based on random vectors fails because they often point against the established visual current. The redesign mandates heavy integration with the static world generation data. Before generating the geometry for `PFB_family_kelp_tall`, the builder must query the pre-computed fluid flow vector field at the specific world-space coordinate of the stalk's base. The generation algorithm then constructs the central spline of the stalk. Instead of growing straight up along the Y-axis, the spline path must be skewed progressively by a directional bias vector. This bias vector is a normalized derivative of the queried flow field vector, scaled by the stalk's height to simulate increasing hydrodynamic drag on higher foliage. The resulting curved spline serves as the path for the procedural geometry extrusion. This ensures that every single procedurally generated tall plant inherently leans in the correct downstream direction, cementing the environmental cohesion without requiring a single cycle of runtime physics simulation.
## 9. Fauna Spawns: Terrestrial Raycast Grounding
Passive fauna spawn markers often float above the irregular terrain of the ocean floor, confusing level designers and occasionally leading to creatures spawning in mid-air and dropping into the scene. The `WorldProceduralScatterDirector.cs` script must implement a rigid terrain conformity pass for all marker rings. After generating the initial XZ spawn coordinates based on the noise map, the script must isolate every vertex in the marker's mesh. For each vertex, a ray must be cast vertically downward (-Y axis) against the static physics collision layer. The vertex's Y coordinate is then precisely set to the raycast hit point. To prevent z-fighting with the ground, a micro-offset (e.g., 0.01 meters) is added back to the Y axis along the hit normal. This vertex-level projection guarantees that the entire ring deforms perfectly to the undulating shape of the seafloor, providing accurate visual feedback for spawn locations without floating gaps.

## 10. Fauna Spawns: Crevice Depth Occlusion Mapping
Predator spawn nests are placed in dark, abyssal crevices but frequently lack the necessary localized shadowing, appearing flat and uniformly lit. The redesign mandates a specialized vertex color baking pass tailored for concave structures. The generator must iterate through the nest mesh vertices and calculate a 'crevice depth' factor. This is achieved by calculating the average distance from the current vertex to its neighbors within a defined search radius. Vertices that are deeply recessed compared to their neighbors are assigned a low depth factor. This factor is then inverted and mapped to the blue vertex color channel. The result is a procedural ambient occlusion map that accurately darkens the deep, sharp crevices of the nest while leaving the exposed outer ridges bright. This technique is far more performant than full hemispherical raycasting and is specifically optimized for the highly concave geometries typical of predator habitats.

## 11. Wreckage: Collision-Aware Packing Algorithms
The current egg clutch and debris field generation rely on grid-based or uniformly random scattering, which often results in meshes intersecting awkwardly or aligning in unnatural patterns. The scattering director must be rewritten to utilize a relaxed Poisson disk sampling or circle-packing algorithm. During the generation of a `PFB_family_debris_field`, the script must define a sequence of bounding circles (or spheres) corresponding to the rough dimensions of the individual debris components. The packing algorithm attempts to place these circles within the defined field boundary such that they are tightly grouped but never mathematically intersect. Once a valid packed layout is determined, the actual debris meshes are instantiated at the circle centers. This approach guarantees organic, dense clustering while definitively preventing the ugly geometry clipping that occurs with naive random placement, satisfying the rigorous visual standards for scattered objects.

## 12. Wreckage: Catenary Curve Sag for Cables
Procedural power routes and communication relays are currently connected by perfectly straight geometric cylinders, which looks entirely artificial and ignores gravity. The geometry builder for `PFB_family_route_power__relay` must be overhauled to generate cables using catenary curve mathematics. Given two connection points (nodes), the algorithm must calculate the mathematical catenary curve `y = a * cosh(x/a)` that passes through both points, where 'a' is a parameter controlling the sag tension. The procedural mesh extrusion then follows this precise curve rather than a linear interpolation. This ensures that every generated cable exhibits a physically accurate sag under its own weight, regardless of the distance or height difference between the nodes. The tension parameter can be slightly randomized per cable to simulate varying degrees of wear and slackness across the ruined infrastructure.
## 13. Hard-Surface Ruins: Beveling via Edge Chamfering
The ruin modules currently generate with perfect 90-degree mathematical corners, violating the fundamental hard-surface aesthetics of the Hecton-8 universe. Infinite sharpness creates rendering artifacts and destroys the illusion of scale. The generator must incorporate a post-triangulation edge chamfering pass. The algorithm identifies all boundary edges where the angle between adjacent face normals exceeds a defined threshold (e.g., 45 degrees). For each identified hard edge, the vertices are split and pulled back along their respective edges by a specified bevel distance. New polygons are generated to bridge the gap, effectively chamfering the corner. For higher LODs, this chamfer can be subdivided further into a rounded bevel. Crucially, the normals of the newly created bevel faces must be smoothed, while the normals of the original adjacent faces remain flat, ensuring that light catches the edge smoothly without blowing out the shading of the primary flat surfaces. This operation drastically improves the perceived visual quality of all hard-surface scatter modules.

## 14. Hard-Surface Ruins: Triplanar Mapping for Tiling Eradication
Large ruin blocks and megastructures often exhibit severe texture tiling when viewed from a distance, revealing the repeating patterns of the base materials and destroying the illusion of scale. Standard UV projection mapping is insufficient. The redesign must mandate the use of triplanar mapping shaders for all massive ruin assets (`PFB_family_ruin_megastructure`, `PFB_family_ruin_module_single__block`). Triplanar mapping projects the texture along the three world-space axes (X, Y, Z) and blends them based on the face normal, completely eliminating the need for complex UV unwrapping and preventing any stretching on steep angles. To further combat tiling, the shader must incorporate macro-variation noise masks. These low-frequency procedural noise textures are multiplied over the base albedo and roughness maps, breaking up the repeating patterns over large distances while preserving the high-frequency detail up close. The offline generator only needs to ensure that the mesh provides accurate vertex normals; the shader handles the rest dynamically.

## 15. Hard-Surface Ruins: Modular Snapping and Cluster Cohesion
Ruin clusters currently look like haphazard piles of individual pieces rather than coherent destroyed structures. The procedural generation of `PFB_family_ruin_cluster_medium` must be constrained by a strict modular snapping logic. The offline generation script must define a grid (e.g., 2m x 2m x 2m) and a set of predefined attachment sockets on every ruin module primitive. When the algorithm attempts to place a new module, it must raycast outward from existing sockets. Instead of random placement, the new module is snapped to the nearest valid socket, aligning its local rotation perfectly. A secondary noise function can slightly perturb the final rotation to simulate collapse, but the base structure must adhere to the grid. This ensures that corridors align, walls connect, and frames support each other logically, transforming a chaotic pile of debris into a believable, interconnected architectural ruin.

## 16. Optimization: Protected Silhouette Decimation for Impostors
At abyssal distances, complex 3D meshes transition to 2D impostor cards to save performance. However, if the transition happens while the LOD1 or LOD2 mesh is heavily decimated and stripped of its silhouette features, the crossfade to the billboard is painfully obvious. The redesign dictates that the final decimation pass before the billboard LOD must strictly protect silhouette vertices. The algorithm renders the object from 8 cardinal directions and marks any vertex that lies on the outer boundary of the resulting 2D projections. During the Quadric Error Metric (QEM) simplification, these marked vertices are assigned a collapse cost approaching infinity. The result is an LOD2 mesh that consists almost entirely of silhouette geometry with very few internal polygons. When this mesh finally transitions to the 2D billboard impostor, the outlines match perfectly, minimizing the visual 'pop' while aggressively cutting the polygon count for distant objects.
## 17. Collision Proxies: Convex Hull Generation for Complex Shapes
Relying on high-poly visual meshes for physics collision on complex objects like cave entrances or coral heads is computationally disastrous. The redesign demands that the offline pipeline automatically generates optimized collision proxies. For solid, convex-like objects, the pipeline must implement the QuickHull algorithm to calculate a minimal convex hull that encapsulates the visual mesh. For non-convex objects like archways or hollow caves, the algorithm must perform an automated convex decomposition (e.g., using a library like V-HACD integration). This process breaks the complex mesh into a small set of simple, non-overlapping convex hulls. These hulls are then assigned to `MeshCollider` components with the 'Convex' flag enabled. This ensures that the physics engine only ever evaluates collisions against geometrically simple, highly optimized mathematical shapes, maintaining the rigid 0 B/frame runtime budget while providing accurate collision boundaries for the player.

## 18. Validation: Automated Normal Continuity Checks
The offline generation pipeline currently relies heavily on manual visual inspection to verify mesh quality. This leads to smoothing errors and faceted edges slipping into the final build. The redesign requires the implementation of an automated, headless topology validation script. Immediately after generating any mesh, the script iterates through every vertex. For each vertex, it examines the normals of all adjacent triangles. If the angle between any two adjacent face normals is less than a defined 'smoothness threshold' (e.g., 30 degrees), the script checks if the vertex is shared (split). If it is split, it flags a 'smoothing discontinuity error'. Conversely, if the angle is greater than the 'sharpness threshold' (e.g., 60 degrees) and the vertex is *not* split, it flags a 'faceting error'. Any mesh that accumulates more than a defined number of topology errors automatically fails the generation process and is rejected from the prefab output directory. This creates a hard, verifiable gate that guarantees mesh quality without requiring human intervention.
