## 0\. КРИТИЧЕСКОЕ ПРЕДУПРЕЖДЕНИЕ О СРЕДЕ

В проекте **параллельно работают другие агенты**. За время сессии файлы `HectonVoxelEngine.cs`, `HectonVoxelVolume.cs`, `WorldCaveDirector.cs`, `CaveGraphGenerator.cs`, `CrashTelemetryBuffer.cs`, `WorldProceduralScatterDirector.cs` и `water.md` менялись извне.

**Правила работы, выведенные из этого опыта:**

1. **Коммить сразу после каждой правки.** В этой сессии один патч (отбраковка вырожденных треугольников \+ фикс дубля состояний чанка) чуть не потерялся, потому что был применён, но не закоммичен. Обнаружено и исправлено в конце.
2. **Всегда используй mtime\-гард при записи.** Если гард отверг запись — перечитай файл, а не форсируй.
3. **Перед правкой перечитывай файл с диска.** Кэшированные копии устаревают: в этой сессии повторный стейджинг **не перезаписал** уже существующие копии, и проверка «грепом по кэшу» дала ложную тревогу о потере всех правок. Проверяй по размеру/хэшу реального файла, а не по кэшу.
4. `git diff` перед коммитом. Всё под git — откат дёшев.

## 3\. P0 — БЛОКЕР ИГРАБЕЛЬНОСТИ: у воксельных пещер нет коллизии

**Это главное невыполненное. Игрок проплывает сквозь стены, пол и потолок каждой пещеры — весь меш\-пайплайн декоративный.**

Доказательства:

- `HectonVoxelVolume.cs:1748` — `AssignColliderChunkBakeMesh(int index, Mesh mesh)` содержит буквально `return false;`. `GetColliderChunkBakeMesh` → `null` (`:1743`), `IsDeferredColliderChunkUploadReady` → `false` (`:1738`). **Проверено повторно в конце сессии — всё ещё так.**

- `HectonVoxelEngine.cs:14255-14301` (`ApplyChunkedColliderMeshesAsync`) аккуратно считает `chunkTriangleIndices`, `bucketOffsets`, `bucketCounts`, `localRemap` (аллокация `:14205`, очистка в −1 `:14235`) — а коммит\-цикл `:14309-14352` **их не читает вообще**.
- Корневой `MeshCollider` принудительно выключен: `:13795-13796`.
- Фолбэк\-боксы бесполезны: `:7996-8001` — `Physics.IgnoreLayerCollision(Player/Vehicle/PlayerVehicle, VoxelProxy, true)`. Прокси — единственные включаемые коллайдеры (`HectonVoxelVolume.cs:1720`, `:2034`), и они не триггеры (`:14055`).
- Гейт бейка написан **правильно** — `HectonVoxelVolume.cs:3946`\: `collisionAllowed = _bakeState == VoxelBakeState.Complete;`. Он просто вакуумно истинный, потому что меша нет.

**Что делать:**

1. Реализовать `AssignColliderChunkBakeMesh`\: собрать `Mesh` из `chunkTriangleIndices[bucketOffsets[i] .. +bucketCounts[i]]` с компактизацией вершин через готовый `localRemap`. Явные bounds брать из `state.BoundsCenterLocal`, `MeshUpdateFlags.DontRecalculateBounds`.
2. Бейк через `Physics.BakeMesh(meshId, convex: false)` в воркере; `_bakeState = Complete` ставить **только** по возврату. Гейт `collisionAllowed` уже есть, не дублировать.
3. Прокси держать только пока `_bakeState != Complete`. По готовности — реальный меш\-коллайдер на `HectonLayerMasks.VoxelCave` (уже назначается в `HectonVoxelVolume.cs:1603`), прокси выключить.
4. Проверить `:14055` `proxy.isTrigger = false`\: `IgnoreLayerCollision` **не** влияет на `Physics.Raycast`/`SphereCast`, поэтому лучи инструментов/сонара могут бить в невидимую плиту. Найти реальные layer\-маски у `SeafloorDrillTool`, сонара, интеракции. **PLAUSIBLE, не подтверждено** — сначала проверь маски, потом ставь `isTrigger = true` либо переводи на `IgnoreRaycast`.

**Приёмка:** Play Mode — упереться в стену пещеры; дрель/лазер регистрируют попадание; `Physics.Raycast` возвращает `VoxelCave`, не `VoxelProxy`; профайлер — стоимость бейка на стрим\-ин в бюджете кадра.

## 4\. P0 — Burst, вероятно, не компилирует главный marching\-cubes джоб

`HectonVoxelEngine.cs:3033` внутри `[BurstCompile] VoxelMCExtractJob`\:

```csharp
int edgeBits = Hecton8.PureLogic.Systems.MarchingCubesLookupTable.Calculate(
    (byte)cubeIndex, densities.d0, ..., 0f);
```

`MarchingCubesLookupTable.Calculate` (`PureLogic\Systems\MarchingCubesLookupTable.cs:79-94`) индексирует `static readonly int[] EdgeTable` — **управляемый массив** — и делает `throw new ArgumentException(...)`. Burst не поддерживает ни то, ни другое. Сосед `VoxelMCCountJob` сделан правильно: читает `NativeArray<int>.ReadOnly triTable` (`:2867-2871`). У `VoxelMCExtractJob` поле `edgeTable` **уже прокинуто** (`:10830`), но используется только для `.Length` (`:3123`).

**Фикс:** `int edgeBits = edgeTable[cubeIndex];`. **Перед заменой сверь семантику** — убедись, что `edgeTable` это именно 256\-элементная `EdgeTable`, и что `Calculate` не делает ничего сверх индексации (прочти тело целиком).

**Приёмка:** Burst Inspector показывает джоб скомпилированным; в Burst\-логе нет ошибок про managed array/throw; профайлер до/после на стрим\-ине пещеры. Если ускорения нет — значит компилировался и раньше, так и напиши.

## 5\. P0 — Текстуры: мусор в репозитории и 4× перерасход VRAM

**5a. Закоммичен массив из чистого неинициализированного мусора.**
`Art\Materials\Terrain\Terrain_AlbedoArray.asset` — все 1.4 МБ payload это `0xCD` (MSVC debug\-заполнитель), `m_Width: 512, m_Depth: 4`. Причина — `Editor\Terrain\HectonTerrainTextureArrayBuilder.cs:182`\: `Graphics.CopyTexture` (GPU→GPU) не заполняет CPU\-буфер, который сериализует `CreateAsset`, плюс `Apply(false, true)` с `makeNoLongerReadable:true`. Тот же код дал валидный 2048\-массив → баг **недетерминированный**, что хуже стабильного: проходит на машине, где бейкали, ломается у остальных.
**Фикс:** `Graphics.CopyTexture` → `SetPixels(tempTex.GetPixels(m), slice, m)` по мипам (правильный образец в `RebuildTexArrays.cs:71-75`); `Apply(false, false)` **до** `CreateAsset`; никогда `makeNoLongerReadable:true` перед сериализацией. Пост\-бейк ассерт: slice 0 mip 0 не константный.

**5b. 128 МиБ VRAM вместо 32.**
`HectonTerrainTextureArrayBuilder.cs:12` — `_resolution = 2048`, и оба headless\-входа (`AutoBuildTextureArrays.Run`, `RebuildTextureArrays.Run`) его не переопределяют. Проверено по заголовку связанного ассета: `m_Width: 2048, m_Depth: 8, m_MipCount: 12, m_DataSize: 44739456` × 3 массива \= ровно **128\.0 МиБ** резидентно, без стриминга (привязано к material template). Bible требует 1024 → было бы 32.0 МиБ. На MX350 (2 ГБ) это 6.25% всей VRAM только на сплат\-текстуры.
**Фикс:** `_resolution = 1024` \+ hard\-assert. Шейдер тайлит на \~14 м (`HectonTerrainSampling.hlsl:513`) — 2048 выше экранного Найквиста уже за несколько метров, переплата ничего не даёт визуально.

**5c. Пять конкурирующих бейкеров, три каталога, нет источника истины.**
`BakeDeepSeaTerrainArrays.cs` (1024, 4 слоя, RGBA32) — назван в bible, но материал использует **не его**; `Terrain\HectonTerrainTextureArrayBuilder.cs` (2048, 8, BC7/BC5) — **фактически связанный**; плюс `BakeTerrainArrays.cs`, `RebuildTexArrays.cs`, `TextureBakerRun.cs`. На диске 11 ассетов в 2 каталогах, включая мусорный 512 и три дубля `_Fixed` по 44.7 МБ.
**Фикс:** оставить `HectonTerrainTextureArrayBuilder` (единственный с корректной компрессией и цветовым пространством), переименовать в `BakeDeepSeaTerrainArrays` чтобы совпало с bible, остальные четыре удалить, удалить осиротевшие `_Fixed` (≈180 МБ репозитория). Сверить GUID материала до/после.

**5d. Бейк не привязан к сборке.** `Editor\HectonBuildPipeline.cs:93` — `configure()` это только PlayerSettings/Burst; поиск `IPreprocessBuildWithReport|OnPreprocessBuild|BuildPlayerProcessor` не даёт ничего. Bible\-инструмент — только `[MenuItem]` (`:9`).
**Фикс:** `IPreprocessBuildWithReport.OnPreprocessBuild` → бейк → **hard\-fail** (`BuildFailedException`) если массив `null`, `depth != 8` или `width != 1024`.

**5e. В плеере нет фолбэка и нет ошибки.** `World\HectonTerrainMaterialInjector.cs:74` — единственная страховка в `#if UNITY_EDITOR`; ранний выход молчит без `LogError`. Несвязанный `Texture2DArray` на D3D семплится чёрным → **чёрный террейн с чистой консолью**.
**Фикс:** вынести фолбэк из `#if UNITY_EDITOR`, на неудаче `Debug.LogError` с именем террейна и null\-свойства.

**5f. 4\-слойный массив биндится в шейдер, семплящий 8 слоёв.** `HectonTerrainMaterialInjector.cs:76` — фолбэк смешивает DeepSea albedo/normal (depth 4, 1024²) с `Terrain_MaskArray` (depth 8, 2048²). `_NumLayersCount` инжектор ставит (`:121`), но **ни один шейдер его не читает**; цикл жёстко `for (int k = 0; k < 8; k++)` (`HectonTerrainSampling.hlsl:611`). Слои 4\-7 клампятся в слой 3 (базальт), но PBR\-константы применяются свои (`:286` манган 0.58 \+ metallic 0.55, `:288` рассол 0.40).

**Фикс:** бейкать все 8 слоёв \+ mask либо удалить фолбэк; честно читать `_NumLayersCount` в цикле (ещё и перф\-выигрыш) либо ассертить `depth == 8` на бинде.

## 6\. P1 — Растительность и стриминг: перф\-дефекты (аудит проведён, ничего не внедрено)

Подсистема написана дисциплинированно — реальный GPU indirect culling с HZB, кэшированные `Shader.PropertyToID` (65 \+ 55 ID), ноль LINQ, ноль `Camera.main`, ноль строковой работы вне `#if UNITY_EDITOR`, гистерезис в трёх местах. **Zero\-GC закон соблюдён.** Проблемы — не GC, а пропускная способность и устаревшее состояние куллинга.

**6a. CRITICAL. Полная небюджетированная перезаливка всего набора инстансов на каждое завершение сборки чанка.**
`World\HectonIndirectVegetationRenderer.cs:2065` — `CanUseDirtyPageUpload` требует **бит\-в\-бит совпадения** числа инстансов с прошлым кадром (`:2180`), но `RebuildAndBindActiveBuffers` пересчитывает `totalSurfaceCount` от видимого набора чанков, поэтому счётчик меняется почти всегда. Управление уходит в `BindInstanceNativeArrays` (`:2044-2049`) — **четыре** полных `UploadNativeArray` без PCIe\-бюджета и пагинации (в отличие от paged\-пути, который чтит `ResolveNativeUploadBudgetBytes()` на `:2124`). Триггер: `VegetationChunkResidencyDirector.cs:1095` ставит `_activeSetDirty = true` на **каждом** финализе сборки чанка.
Оценка при \~40k инстансов: 4 × 40 000 × 64 Б \= **10\.2 МБ на канал, 20.5 МБ за кадр** на surface\+underwater. На MX350 это \~5\-7 мс DMA. **Симптом: повторяющийся хитч каждый раз, когда достраивается чанк растительности — то есть непрерывно, пока игрок плывёт вперёд.** Наиболее вероятная причина заиканий на маршруте.
**Фикс:** сравнивать с **ёмкостью** буфера, а не с прошлым счётчиком, и метить грязными только `[min(old,new), max(old,new))` плюс реально сдвинувшиеся диапазоны. Минимум — пропустить полный путь через `GraphicsBufferUploadUtility.TryBeginManualUpload(bytes)` (уже используется в `ImpostorSystem.cs:1301`).

**6b. HIGH. Подсистема dirty\-page инертна.** `VegetationChunkResidencyDirector.cs:1853` — `MarkActiveAggregateDirtyPagesOneLock` безусловно метит `[0, elementCount)`, то есть весь буфер. Вся машинерия страниц корректна, но не может сэкономить ни байта.
**Фикс:** отслеживать реально затронутый диапазон записи на чанк (`writeIndex`…`writeIndex+copyCount`, `:301`/`:363`) и метить только его.

**6c. HIGH. CPU\-куллинг чанков устаревший — не переоценивается при повороте камеры.**
`VegetationChunkResidencyDirector.cs:223` — фрустум\-тест решает, какие чанки попадут в агрегатный буфер, но `RebuildAndBindActiveBuffers` запускается только по `selectionChanged || _activeSetDirty || _activeBufferRebuildRequested`. **Ни один из 15 сайтов `_activeSetDirty = true` не зависит от вида.**
**Симптом:** встать и развернуть камеру на 180° — чанки, бывшие сзади на момент последней смены residency, отсутствуют в буфере и **не рендерятся**. GPU\-куллинг может только убрать то, что в буфере, но не добавить отсутствующее. Паддинг `(36,24,36)` не спасает при сетке 100 м.
**Фикс:** проще всего **удалить** CPU\-куллинг чанков — GPU\-куллинг (`HectonIndirectVegetationRenderer.cs:2957`) уже делает точный per\-instance фрустум \+ HZB. Удаление заодно убирает скачки счётчика, ломающие 6a — два из трёх топ\-дефектов схлопываются в одну правку.

**6d. HIGH. Бюджет микро\-скаттера залочен на `Awake`/`OnEnable` — качество не может его снизить.**

## 12\. Что подтверждено зрелым (не ломать)

Честный кредит — это тоже результат аудита:

- **Сейв\-система.** Каждый префикс длины/счётчика проверяется на `<0`, `>max`, переполнение (`count > int.MaxValue/stride`) и остаток байт **до** аллокации. Запись основного сейва атомарна: temp → `Flush(true)`/`FlushCriticalSavePath` (сверка длины до и после fsync) → `File.Replace`/`File.Move` \+ backup. Magic, диапазон версий, `CompatMask`, хэш заголовка и per\-sector контрольные суммы проверяются обязательно и в правильном порядке. Порядок WAL\-перед\-миром корректен.
- **Моддинг\-песочница.** Моды **не исполняют управляемый код** — `Assembly.Load` в моддинге нет вообще. Burst\-валидатор конверта default\-**deny**, каждое значение мода проверяется на конечность/границы до использования, запись в общий blackbox\-буфер **дважды** валидируется против реальной аллокации на commit, изоляция по `ModderSignature` держится. Это архитектурно правильная защита от RCE.
- **Знак SDF консистентен end\-to\-end.** Подозрение на вывернутые пещеры **не подтвердилось**\: мост float→sbyte не негует (`HectonVoxelEngine.cs:2946`), базовая плотность positive\-inside (`VoxelSeamDirector.cs:62`), потребители согласованы, и winding марширующих кубов проверен вручную для `cubeIndex == 1` против раскладки углов — согласуется с гейт\-нормалями.
- **Живой воксельный пайплайн до загрузки меша.** Клэмп интерполяции ребра (`:3149`, `0.001..0.999`), детерминированное владение рёбрами через `PackEdge(min,max)`, все деления защищены, non\-finite ловится в black\-box слоты, аллокации ограничены (`gridDimension` в `[32,128]`, `StreamingPointScratchMax`), карв забюджетирован с валидацией повреждений на загрузке. Гейт коллизии написан правильно.
- **Защита поверхности от пробоя пещерами** реальна и через smoothstep (`HectonVoxelEngine.cs:1021-1027`).
- **Террейн:** нет kaleidoscope\-бага (`math.abs(wrap-period)` отсутствует, поле непрерывное в абсолютных координатах — швов нет по построению); zero\-GC чтение высот соблюдено (`Terrain.SampleHeight`/`GetHeights` в горячем пути **отсутствуют**); детерминизм эрозии обеспечен сортировкой дельт по индексу.

Плюс NaN\-щит, guard на `normalize(0)`, фикс знака тангенса, удалён сломанный GBuffer\-пасс. Декод нормалей BC5 корректен, цветовое пространство связанных массивов верное, мипы полные.
