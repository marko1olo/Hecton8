## Runtime Doctrine

This is a deterministic presentation approximation. Do not spawn dynamic lights per coral, fish, ping, or pulse. Consumers should drive emissive shader parameters, SSGI eligibility, fog tint contribution, or GPU instance data from preloaded binary records.

Hot path requirements:

- No JSON parsing during gameplay.
- No string profile lookup during gameplay.
- No `MaterialPropertyBlock` for standard SRP-batched geometry.
- No per-frame `GlobalRegistry.Get<T>()`.
- No string event names for `AcousticPing`.
- Use typed environment/acoustic signal payloads or cached scalar state.

## Binary Layout

All integers are little-endian `uint32`. All floats are little-endian `float32`.

Header format: `<8sIIIIIIIIII`, 48 bytes.

| Field | Meaning |
|---|---|
| magic | `H8BIOLUM` |
| version | `1` |
| profileCount | `20` |
| paletteCount | `8` |
| maxHarmonics | `8` |
| curveSamples | `256` |
| maxQualityColorCount | `10` |
| minQualityColorCount | `2` |
| profileStride | `1232` bytes |
| paletteStride | `156` bytes |
| payloadCrc32 | CRC32 of payload bytes |

Profile base format: `<IIIII15f`, 80 bytes.

Fields: `profileHash`, `profileIndex`, `biomeHash`, `flags`, `harmonicCount`, then:
`periodSeconds`, `baseline`, `amplitude`, `gamma`, `noiseScale`, `noiseRateHz`, `safetyClampHz`, `rawMaxHz`, `effectiveMaxHz`, `acousticGain`, `acousticDecaySeconds`, `acousticRefractorySeconds`, `acousticPhaseKickRad`, `acousticStrobeHz`, `acousticWidth01`.

Profile tail:

- 8 harmonic records: `<4f>` = `multiplier`, `amplitude`, `phaseRad`, `shapePower`.
- 256 normalized curve samples: `float32[256]`.

Palette record format: `<III36f`, 156 bytes.

Fields: `paletteHash`, `paletteIndex`, `flags`, then 36 floats:
Minimum-quality two RGB HDR colors followed by maximum-quality ten RGB HDR colors.

## Profile Flags

| Bit | Meaning |
|---|---|
| `1 << 0` | Safety clamp active because authored max frequency or strobe exceeded 15 Hz |
| `1 << 1` | AcousticPing reactive |
| `1 << 2` | Predator-visible warning/readability profile |
| `1 << 3` | High-fidelity visual-overkill candidate |

## Shader Evaluation

The global phase name is `_BiolumMasterPhase`.

Minimum-quality path:

1. Read profile `curveSamples[phaseIndex]`.
2. Lerp the two minimum-quality palette colors.
3. Multiply emissive intensity by bounded local mask and fog eligibility.

Maximum-quality path:

1. Reconstruct harmonic sum with 4-8 sine terms.
2. Apply deterministic phase/noise scalar from a precomputed or shader hash path.
3. Sample the 10-color HDR ramp by normalized brightness.
4. Feed emissive output into the existing biolum SSGI path only on eligible tiers.

Do not add bloom on MX350. The pulse profile can be bright HDR; presentation must still go through existing ACES/noir/fog policy.

## AcousticPing Response

`AcousticPing` is a scalar overlay, not a dynamic-light event.

Required consumer behavior:

- Cache the last accepted ping time and strength from a typed signal.
- Respect `acousticRefractorySeconds`.
- Clamp `acousticStrobeHz` to `safetyClampHz`.
- Use a decaying sine lobe, not a square flash.
- Drop or coalesce excessive pings by entity/zone; do not enqueue unbounded visual events.

Reference overlay:

```text
afterPing = max(0, time - pingTime)
strobeHz = min(acousticStrobeHz, safetyClampHz)
lobe = max(0, sin(TAU * strobeHz * afterPing + acousticPhaseKickRad))
overlay = pow(lobe, widthPower) * exp(-afterPing / acousticDecaySeconds) * acousticGain
```
