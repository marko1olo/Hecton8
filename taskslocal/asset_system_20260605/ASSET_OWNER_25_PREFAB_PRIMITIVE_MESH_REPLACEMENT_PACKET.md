## Regression Model

- CPU: risk from added renderer count, LODGroup evaluation, collider count, convex collider complexity, shadow casters, prefab instance count, and validator/editor overhead. Runtime claims need profiler proof; any single feature over `0.1ms` remains suspicious.
- GC: no runtime allocation claim is allowed without GCMonitor/Profiler proof. Reject runtime mesh generation, runtime material clone creation, `Resources.Load`, hot scene search, string churn, and hot-path `GetComponent`.
- Memory/VRAM: replacement meshes, texture sets, material slots, mip residency, shadow maps, and longer LOD residency can raise memory. Compact hard ceiling remains 1800 MB VRAM and 900 MB texture budget; route promotion needs memory proof before broad placement.
- SetPass/batches: risk from material proliferation, shader variants, unique materials, and extra transparent passes. Use shared materials, atlases/trim sheets, SRP Batcher, GPU Resident Drawer/instancing where appropriate, and Frame Debugger proof.
- Cadence: no runtime cadence is accepted by this packet. LOD, visual, Addressables, and shader updates must use continuous `GlobalQualityWeight`, hysteresis, and bounded owner phases.
- Correctness: prefab GUID, script refs, pivots, sockets, interaction anchors, hand poses, collider truth, scene overrides, save identity, and Addressables identity are the high-risk facts.
- Visual floor: weak primitives, proxy materials, flat panels, missing bevels, blurry textures, faceted curves, or hidden-by-darkness visuals are product rejection even if import and performance pass.
